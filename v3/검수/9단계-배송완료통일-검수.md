## 1. 🔴 오발사 방지 — 다섯 항목 전부 통과 ✅

### 1-1. 미리보기 통과 전에는 「진짜 올리기」류 단추가 화면에 없다 ✅

`닫기 | ↻ 실패한 것만 다시 올리기` 뿐이다(`08m:160~163`).

### 1-2. 자동으로 `진짜:true` 가 나가는 경로가 없다 ✅

- `js/` 전체에서 `shipment-push` 를 부르는 자리는 **`08l-카페24발송.js:63` 하나뿐**이다
- `진짜` 를 넘기는 자리도 하나 — `부르기(짝들, 진짜)` → `진짜: 진짜 === true`

## 4. ③ 손처리·되돌리기 — 안전장치 넷 다 통과 ✅

### 4-1. 아무것도 안 고르면 전체로 안 퍼진다 ✅ (가장 중요)

```
또는, 로젠 파일 없이 —  먼저 주문표에서 건을 고르세요
[✋ 배송완료로 넘기기](off)  [↩ 배송완료 되돌리기](off)

- 두 단추 모두 `disabled`. **강제로 `.click()` 을 쏴도** 확인창이 안 뜨고 `zg.v3.출고` 불변
- 코드로 `ZG.수동배송완료.넘기기([], …)` 를 직접 불러도 토스트만 뜨고 **아무 일도 안 일어난다**
- `08g.고른건들()` 은 `ZG.주문.상태.고른` 으로 직접 세고 **`ZG.주문.고른줄들()` 을 안 쓴다** — 폴백 경로가 없다(소스 확인 + 실측)

### 4-2. 확인창에 무엇을 몇 주 깎는지 나온다 ✅

8건을 고르고 눌렀을 때 —

```

김미정 · SAC01-15 외 1품목 5주 차감

### 4-3. 되돌리기가 서비스 출고를 안 건드린다 ✅ (섞인 건으로 직접 재현)

상품줄(`SAC01-15` 2주) + 서비스줄(`GIFT01-10` 1주, `출처:'서비스'` 출고 `sh_svc1` 이미 있음)이 섞인 건.

| 단계 | `zg.v3.출고` |
|---|---|
| 처음 | `[sh_svc1 GIFT01-10 서비스]` |
| 넘기기 | `[sh_svc1 GIFT01-10 서비스]` + `[… SAC01-15 2 주문]` ← **서비스줄은 넘기지 않는다** |
| 되돌리기 | `[sh_svc1 GIFT01-10 서비스]` ← **서비스 출고 그대로 남았다** |

확인창도 `출고 1건을 지우고 재고를 원래대로 돌립니다.` — 서비스 1건을 안 센다.
`카페24상태` 는 손대지 않는다(되돌린 뒤 값 그대로 확인). 카페24에서 이미 나간 건에는
`이 건은 카페24에서 이미 발송처리됐습니다 — 카페24 쪽은 되돌아가지 않습니다` 한 줄이 붙는다.

### 4-4. 이중처리가 안 된다 ✅

같은 건을 두 번 「넘기기」 — 두 번째는 **확인창이 아예 안 뜨고**
`이미 나갔거나 품목코드가 없어 넘길 줄이 없습니다.` 토스트로 끝난다. 출고 배열 불변.

### 4-5. 폰 상세 ✅

## 🟡 배포 컨펌 때 함께 여쭐 것

**🟡-1. 출고에 운송장번호가 안 남는다 — 설계 §3(1) 미구현**

설계 §3(1)이 「로젠 길 → `{운송장번호: 것.운송장번호}`」라고 적었는데,
같은 절이 「기존 두 호출부(`08g:159`·`08g:333`)는 안 고친다」라고도 적어 **설계 자체가 모순**이다.
구현은 뒤쪽을 따랐다 — `08g:194`·`08g:418` 둘 다 세 인자로만 부른다.

```
출고: [["SAC01-15",3,"주문","(운송장번호 없음)"], …]
```

`덧` 인자는 손처리 길(`{수동:true}`)만 쓴다. 설계가 노린 「CS·재출력 때 어느 송장으로 나갔나」는 못 찾는다.
재고·계산에는 영향이 없다. **한 줄 고침**(`08g` 두 곳에 `, {운송장번호: 것.운송장번호}`)이면 된다.

**🟡-2. 카페24 모달 머리 힌트가 꺼진 줄까지 센다**

`5건 · 로젠 송장번호를 카페24에 올립니다` — 실제로 올라갈 것은 **3건**(둘은 처음부터 꺼져 있다).
발 단추는 `☁ 진짜 올리기 3건` 으로 맞게 뜨지만 머리와 어긋난다.

**🟡-3. 실패 건수를 두 곳이 다르게 센다**

미리보기에서 1건이 막히고 진짜 올리기에서 1건이 실패한 경우 —

- 요약: `✅ 카페24 발송처리 1건 · ❌ 실패 1건` (이번 묶음만)
- 닫으려 하면: `실패 2건이 남아 있습니다` (미리보기 막힌 것까지)

둘 다 틀린 말은 아니나 우람님이 「1건이랬는데 왜 2건?」 하실 자리다.

**🟡-4. PC 「또는」 줄은 출고가 없는 건을 골라도 「↩ 배송완료 되돌리기」가 빨갛게 살아 있다**

누르면 확인창 없이 `되돌릴 출고가 없습니다.` 토스트로 끝나 사고는 안 난다.
폰 상세는 상태를 보고 **한 개만** 보여 주는데 PC 는 둘 다 늘 보인다(설계 §5-1 문면 그대로이긴 하다).

**🟡-5. 카페24 창이 뜨는 동안 로젠 처리 결과가 안 보인다**

`08m:27` 이 뒤의 결과창을 `display:none` 으로 감춘다. 「정상 N건 · 확인 필요 N건」을 보면서
카페24에 올릴 줄을 고르실 수 없다. 두 창이 겹쳐 삐져나오는 것을 막으려는 의도는 이해된다.

## 확정 설계 §11 검증 11가지

| # | 무엇 | 결과 |
|---|---|---|
| ① | 고객 수 ≒ **539명** | 🔴 **못 했다.** 실데이터는 로그인 게이트 뒤에 있어 헤드리스로 못 연다. **시험 데이터로 셈은 맞다**(주문 5줄 → 사람 3명 + 손등록 2명). 사람키가 구 `customerHistory` 와 같은 모양(`김철수\|12345`)인 것은 확인 |
| ② | 건수·합계 대조 | ✅ 김철수 주문 2건(같은 날 2줄은 1건) · 줄 3 · 합계 30,000 |
| ③ | 이름을 안 가린다 | ✅ 전체 이름 그대로 (`김철수`) |
| ④ | 050 에 ⚠ 배지 | ✅ 표·카드·상세 세 곳 다 |
| ⑤ | 필터 → 엑셀 줄 수 | ⚠ **필터만 확인.** 최소주문·최소문자·손등록만·판매처·기간·검색 6종 통과. **엑셀 내려받기는 못 눌러 봤다** — 헤드리스가 파일을 저장 못 한다 |
| ⑥ | 메모 | ✅ 오늘 날짜 카드가 **맨 아래**에 생기고, 새로고침해도 남고, 🗑로 그 장만 지워진다 |
| ⑦ | 3명 체크 → `문자 1` | ⚠ **자료 계층만 확인.** 발송 한 줄이 두 사람에게 붙고 문자수가 1로 오른다. **창을 눌러 저장해 보지는 못했다** |
| ⑧ | 보낸 뒤 주문 | ✅ 06-09 발송 · 14일 창 → 06-10 주문한 김철수만 1명 (06-23 밖 박영희는 안 셈) |
| ⑨ | 견적요청 만들기 | 🔴 **못 했다.** `u.물음` 대화상자를 눌러야 한다. 부르는 코드는 `15b` 와 같은 `ZG.견적자료.추가` 다 |
| ⑩ | 손등록이 안 갈린다 | ✅ 우편번호 없는 이민수가 **보조키(이름+전화)로 주문에 붙었다** — 두 줄로 안 갈린다 |
| ⑪ | 주문 조회·견적 요청이 멀쩡한가 | ✅ 탭 3칸 · 주문 탭은 가로채지 않음(08b가 제 화면을 그린다) · 견적/고객 탭 정상 · 수동주문 같은 다른 뷰에는 탭줄 없음 |

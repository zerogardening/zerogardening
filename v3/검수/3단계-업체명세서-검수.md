## 🔴 반려 사유 — 1건

### 🔴-1 명세서 표에서 수량·단가를 고치면 **엉뚱한 숫자가 박힌다** (`11b-명세서작성.js:155~167`)

한 글자를 치는 순간 표 전체가 다시 그려져 **입력칸이 사라지고 포커스가 `body`로 날아간다.**
두 번째 글자부터는 아무 데도 안 들어간다. 그런데 **첫 글자는 이미 값에 섞여 들어가 있다.**

실제로 눌러본 것 (수량 40 인 줄에서 칸을 클릭하고 `1`,`2`,`3` 을 차례로 침) —

```
클릭 직후 활성: 수량
  '1' 친 뒤 → 활성: BODY | 상태 수량: 410
  '2' 친 뒤 → 활성: BODY | 상태 수량: 410
  '3' 친 뒤 → 활성: BODY | 상태 수량: 410
```

전체선택(⌘A) 후 다시 쳐도 마찬가지다.

| 하려던 것 | 실제로 저장된 값 |
|---|---|
| 수량 40 → **12** | **140** |
| 단가 5,600 → **7,500** | **75,600** |

**이 숫자가 그대로 종이에 찍히고 발행 이력에 저장된다.** 실제로 인쇄 미리보기에
`수량 140 · 단가 75600 · 합계 10,584,000` 이 찍히는 것을 봤다(`샷-3단계-업체명세서/35-PC-인쇄미리보기.png`).
거래명세서 금액이 조용히 틀리는 것이라 배포하면 안 된다.

**원인** — `숫자셀()` 의 `input` 리스너가 `표다시()` 를 부른다.
`표다시()` → `표채우기()` → `u.비우기(표칸)` 으로 방금 타이핑 중인 `<input>` 을 통째로 지우고 새로 만든다.

```js
입력.addEventListener('input', function () {
  줄[밭] = Math.max(0, Number(입력.value) || 0);
  표다시();            // ← 표를 통째로 다시 그린다. 지금 치고 있던 칸이 사라진다
});
```

**고치는 법** — 표를 다시 그리지 않는다. 그 줄에서 파생되는 칸만 갈아 끼운다.
`표채우기()` 에서 만든 그 줄의 「공급가액」·「세액」 `<td>` 를 변수로 들고 있다가
`input` 때 그 두 칸의 `textContent` 만 바꾸고 `합계채우기()`(폰이면 `ZG.업체앱.요약다시()`)만 부른다.
표 다시 그리기는 **줄이 늘거나 줄 때(`줄넣기`·`×`·할인율·단위정리)만** 한다.
설계 §4-5 「고치면 그 줄의 공급가액·세액과 아래 합계가 곧바로 바뀐다」가 원래 이 뜻이다.

> 폰 화면은 아예 수량·단가를 고칠 칸이 없다(🟡-5 참고). 이 고침은 PC 표만 해당한다.

### 계산 (업무규칙 §3 · 설계 §4) — **전부 맞다**

브라우저 콘솔에서 실제 값을 넣어 확인 —

| 넣은 값 | 나온 값 | 기대 |
|---|---|---|
| `단가(10000, 0)` | **20,000** | 매입×2 ✅ |
| `단가(10000, 20)` | **16,000** | ×2×0.8 ✅ |
| `단가(10000, -20)`(할증20) | **24,000** | ×2×1.2 ✅ |
| `단가(3333, 13)` | **5,800** | 5,799.4 → 100원 반올림 ✅ |
| `할인율자르기(150 / -500)` | **99 / −200** | 설계 §4-1 상·하한 ✅ |
| `단위맞추기(16234, 1000, 올림/내림)` | **17,000 / 16,000** | ✅ |
| `줄세액(3×1000, 면세 / 과세)` | **0 / 300** | 면세는 언제나 0 ✅ |

화면에서도 — 매입 2,800 품목을 자동완성으로 골라 넣으니 단가가 **5,600** 으로 자동으로 찼고,
할인 20% → **4,500 / 5,100**(2,800·3,200 기준), 할증 20% 로 바꾸니 **6,700 / 7,700** 로 되돌았다.
단위 정리 1,000원 올림 → **7,000 / 8,000** (모두 1,000 배수).
합계 = 공급가액 333,000 + 세액 15,300 = **348,300** (면세 줄은 세액 0).

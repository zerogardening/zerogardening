## 1. 본 버그 — 인쇄 미리보기 빈 종이

실제 화면 흐름으로 재현: 업체관리 › 명세서 탭 → 상호칸에 「한아름농원」 IME 조합 입력 →
자동완성 클릭 → 품목 검색칸에 「휴케라」·「청사초」(·「수크령」) 조합 입력 → 자동완성 클릭 →
`＋ 품목 추가` → `🖨 출력` 클릭 → 인쇄 상태에서 `Page.printToPDF`.

### PDF 바이트 수 (핵심 근거)

| 상태 | PDF 크기 |
|---|---|
| 고치기 전 (보고된 값) | **998 bytes** — 빈 종이 |
| 옛 방식 재현 (`.doc` 이동 없이 `body.명세서인쇄중` 클래스만 부여) | **1,124 bytes** — 빈 종이 (버그 메커니즘 재현됨) |
| **고친 뒤 · 실제 🖨 출력 클릭 (품목 2건)** | **227,799 / 232,293 / 236,639 bytes** (3회 독립 측정) |
| 참고 · 인쇄상태 아닌 일반 인쇄(앱 전체) | 314,495 ~ 322,543 bytes |

- 5KB 기준 대비 **약 45배** — 빈 종이 아님.
- 옛 방식(1,124B)과 새 방식(22만B)이 같은 세션·같은 문서에서 갈리므로, 크기 차이가 이번 수정 때문임이 확인된다.
- 인쇄 미디어(`Emulation.setEmulatedMedia:print`) 렌더 확인 결과 종이에는 **`.doc` 만** 남는다 —
  사이드바·탭줄·툴바·할인줄·단위정리줄·품목추가줄·삭제(×)열·빈 납기일이 모두 빠지고,
  상호/품목표 2줄/수량·단가·공급가액·세액/합계 7,600원/비고가 정상 출력.

## 2. 빈 품목 안내창

품목 0건에서 🖨 출력 → 회색 토스트가 아니라 **모달 확인창** `.askbox`
「품목이 없습니다 / 출력할 품목을 먼저 넣어 주세요. / [취소] [알겠습니다]」가 뜬다. ✅
(인쇄 진입 안 함 — `body` 클래스 미부여 확인)

## 5. 🟢 적어만 두는 것

1. 빈 품목 안내창에 [취소]와 [알겠습니다]가 둘 다 있다. 알림 성격이라 버튼 하나면 충분하다.
2. 복원은 `afterprint` + 1.5초 타이머 이중 안전장치다. 데스크톱 Chrome은 `window.print()`가 동기라 문제 없지만,
   미리보기가 1.5초 안에 안 열리는 환경(느린 PC)에서 인쇄 미리보기 도중 화면이 먼저 복원될 여지는 남아 있다.
   현재 측정에서는 이상 없음.
3. 폰(390px) 명세서에는 🖨 출력이 없다 — 「출력은 PC화면에서」 안내줄이 있으므로 **시안 ③ 결정대로**이며 누락 아님.

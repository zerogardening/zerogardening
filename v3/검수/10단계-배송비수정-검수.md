## 1. 🔴 가장 중요 — J열 = 단가 × 박스수 (합계) ✅

### 1-1. 손질 0건이면 지금 파일과 **완전히 같다** ✅

같은 CSV를 `76f7bed`와 **직전 커밋(`64d0268`)** 두 벌에 각각 올려 시트를 셀 단위로 비교했다.

```
실물 CSV : 줄수 2/2 · 완전동일 True
시험 CSV : 줄수 5/5 · 완전동일 True
```

E열 앞머리·`/`·L열·Z열까지 한 글자도 안 바뀌었다. **회귀 시험 1번 통과.**

### 1-2. 단가 2,750 · 박스 2 → **모든 물리적 줄이 `5500`, 줄 수는 그대로** ✅

합포장 3줄짜리 홍길동 묶음을 「2,750」 세그 + `＋` 한 번(박스 2)으로 저장한 결과 —

```
C:20260807-0000001 | E:'(3) 추명국 핑크터치(15cm) 1개/' | J:'5500'
C:20260807-0000002 | E:'에키네시아(10cm) 1개/'          | J:'5500'
C:20260807-0000003 | E:'에키네시아(10cm) 2개/'          | J:'5500'
```

**파일 줄 수는 5줄 그대로다.** 박스수를 2로 올려도 새 줄이 생기지 않았다(이전 설계 오류가 되살아나지 않았다).
세 줄 모두 같은 합계가 반복해 찍힌다 — 설계 §4-3 그대로.

### 1-3. 단가 3,300 · 박스 1 → `3300` ✅

이영희 묶음을 「3,300」으로 저장 → J열 `3300`. 곱셈 인자가 1이라 단가가 그대로 나간다.

### 1-4. 확인요망을 안 고치면 **`확인요망` 글자 그대로** ✅

김철수 묶음(점수 16)은 손대지 않았다 → J열 `'확인요망'` **문자열 그대로**. 곱하지 않는다.
`08i:130` 의 `(g.단가 === '확인요망') ? '확인요망' : String(Number(g.단가) * g.박스수)` 가 그대로 동작한다.

### 1-5. 화면 숫자와 파일 값이 맞는다 ✅

```
발밑 — 내려받을 파일 — 20260809-01.xlsx · 5줄 · 3묶음 · 박스 4개 · 로젠 운임 예상 8,800원 · 확인요망 1묶음 제외
```

`8,800 = 3,300(이영희) + 5,500(홍길동)` · `박스 4 = 1 + 1 + 2` · 확인요망은 합계에서 빠졌다.
펼침의 「합계」도 `2,750원 × 2박스 = 5,500원` / 「이 5,500원 하나가 로젠 J열에 들어갑니다」로 정확하다.

## 2. 🔴-1 「송장 한 장 더 만들기」가 뒤 묶음의 출력번호를 민다 — **동봉카드와 어긋난다**

### 무엇이 되고 무엇이 안 되나

**되는 것부터 —** 기능 자체는 설계대로다.

| 확인 | 결과 |
|---|---|
| 새 그룹(별도 송장)이 실제로 생기나 | ✅ 로젠 파일 줄이 5 → 6줄 |
| 자기 단가·박스수를 **독립으로** 갖나 | ✅ 원래 묶음 `5500` 유지 · 추가 송장만 따로 계산 |
| 원래 묶음 값과 안 섞이나 | ✅ 손질 행이 `…#2`로 따로 선다 |
| E열에 `/` 가 있나 | ✅ **한 글자도 없다** — `(4) 2번 송장 · 추명국 핑크터치(15cm) 1개 외` |
| 주문번호·수령인·전화·우편 | ✅ 원래 건과 같다 (`20260807-0000001` · 홍길동 · `01011112222` · `12345`) |
| L열 · Z열 | ✅ 둘 다 `0` |
| v3 주문줄이 늘어나나 | ✅ **안 늘어난다** — 5건 그대로. 재고·매출 부풀지 않는다 |
| 없애기 | ✅ 「이 송장 없애기」로 줄과 손질 행이 같이 사라진다 |

### 🔴 어긋나는 것

`08i:197~199` 의 `표만들기()`가 **추가 송장 그룹에도 `g.출력번호 = gi + 1`을 그대로 매긴다.**
그래서 추가 송장이 목록 가운데에 끼면 **그 뒤의 모든 묶음 번호가 한 칸씩 밀린다.**

실측 —

```
① 첫 내려받기       파일 E열 (1)이영희 (2)김철수 (3)홍길동
                    저장된 출력번호  이영희=1 · 김철수=2 · 홍길동=3   ← 동봉카드가 인쇄하는 번호

② 이영희에게 「송장 한 장 더」 → 다시 내려받기
                    파일 E열 (1)이영희 (2)이영희 2번 송장 (3)김철수 (4)홍길동
                    저장된 출력번호  이영희=1 · 김철수=2 · 홍길동=3   ← 그대로다
```

**김철수 상자에 붙일 카드는 `2`인데 송장에는 `(3)`이 찍힌다. 홍길동은 카드 `3` · 송장 `(4)`.**
포장하는 사람이 번호로 카드와 상자를 맞추는데, 그 짝이 통째로 한 칸씩 어긋난다.

이 자리는 `08i:277` 이 스스로 **「동봉카드와 번호를 맞추는 유일한 자리. 카드를 인쇄한 뒤 파일을 다시 내려받아도
번호가 바뀌면 안 된다」** 고 적어 둔 곳이고, 설계 §6도 **「번호되쓰기()·동봉카드는 한 글자도 안 바뀐다」** 고 약속했다.
저장소 값은 안 바뀌지만 **파일에 찍히는 번호가 바뀌어** 약속이 깨진다.
게다가 완료창은 그 상태에서도 여전히 이렇게 적는다 —

```
출력번호   1 ~ 3 · 동봉카드 번호와 같습니다
📦 로젠에 나갈 4묶음 · 박스 5개   포장하는 순서 그대로입니다 — 동봉카드 번호와 같습니다
```

**언제 터지나** — 「내려받기 → 카드 인쇄 → 송장 한 장 더 → 다시 내려받기」 순서일 때.
(손질을 다 끝내고 **처음 내려받는** 경우에는 같은 판에서 번호가 매겨져 어긋나지 않는다.)

**고칠 방향(참고)** — 추가 송장 줄이 **자기 출력번호를 새로 먹지 않고 원래 묶음 번호를 그대로 쓰면** 끝난다.
`표만들기()`에서 `추가` 그룹은 `gi`를 소비하지 않고 `g.원.출력번호`를 쓰게 하는 정도의 변경이다.
그러면 같은 손님의 두 상자가 같은 번호를 달아 카드 한 장과도 자연스럽게 맞는다.
어느 쪽이 맞는지는 **우람님 확인이 필요할 수 있다** — 판단은 팀장께 넘긴다.

`표만들기()`의 `(g.원 && g.원.출력번호) || 순번 || 1` 도 같은 이유로 항상 원본 번호를 잡는다.

**캐시 버스팅은 이번엔 문제가 아니다** — `?v=37`이 그대로지만 `76f7bed`·`f8a8029` 둘 다 아직 push 전이라

### 🟡-5 완료창 표의 「줄 수 N줄 · 합포장 M묶음」이 다시 안 그려진다 — **이번 수정과 무관(f8a8029에도 똑같다)**


**데이터 사고는 아니다** — 내려받는 파일은 8줄로 맞고, 창을 다시 열면 표도 `8줄 · 6묶음`으로 맞는다.

## 🟡 새로 (배포 컨펌 때 함께 여쭙는다)

### 🟡-6 안심번호가 서로 다른 합포장은 **카드 번호가 겹치고 장수가 배로 는다** — 이번 변경이 기존 어긋남을 증폭시킨다

**재현(실측).** 같은 사람·같은 우편번호·같은 주소인데 **안심번호가 다른 두 주문**(카페24에서 주문 2건이면 실제로 그렇게 온다)을 올리고 「송장 한 장 더」를 붙였다.

| 어디 | 옛(`ba29ba7`) | 새(작업트리) |
|---|---|---|
| 08i 묶음 | 1묶음 (`이름|우편|__안심__`) | 1묶음 (같음) |
| 08a 건 | **2건** (`이름|전화|주소` — 전화가 다르다) | **2건** (같음) |
| 로젠 E열 | `(1-1)` `(1-2)` — 송장 2장 | `(1-1)` `(1-2)` — 송장 2장 (같음) |
| 동봉카드 | `['1','1']` — 2장 | `['1-1','1-2','1-1','1-2']` — **4장** |

- **뿌리는 이번 변경이 아니다.** `08a.묶음키`(이름+전화+주소)와 `08i.그룹키`(이름+우편+안심통일)가 서로 다른 데서 이미 갈라져 있었고, 옛 판도 **카드가 2장·번호가 둘 다 `1`**이었다.
- **포장 결과는 틀리지 않는다.** 1번 상자에 `1-1` 두 장(에키네시아·휴케라), 2번 상자에 `1-2` 두 장 — 각 상자가 **전 식물 안내를 다 갖는다**. 설계 §9-2 의도대로다.
- 다만 **같은 번호 카드가 두 장씩 나와** 작업자가 「내가 뭘 잘못 눌렀나」 할 수 있다. 종이도 2배다.
- 근본 해결은 「08a 건 묶기도 08i처럼 안심번호를 통일한다」인데 **주문 목록 전체가 흔들리는 변경**이라 이번 판에 얹을 것이 아니다. 샷 `재검수3-안심번호-카드4장.png`

## 🔴 1. 사진을 저장하면 본문에 **서명 URL이 같이 박힌다** — 다시 열면 사진이 깨진다

설계 §5는 **「본문에는 경로만 박는다 · 그릴 때 서명 URL(1시간)을 꽂는다」**로 못박혀 있다.
실제로는 저장할 때 `편집기.읽기()`가 `innerHTML`을 통째로 넘겨 **그때 꽂아 둔 `src`까지 같이 저장**된다.

실측(가짜 Storage) — 저장된 줄

```
본문: 사진 시험<img data-경로="2026/08/m-…/fa87cmmz.jpg" alt="" src="https://…/fa87cmmz.jpg?token=abc">
사진들: ['2026/08/m-…/fa87cmmz.jpg']
```

새로고침 뒤 그 메모를 다시 열면

```
편집기 img: [{ src:'https://…?token=abc'(옛것 그대로), 경로:'2026/08/…' }]
createSignedUrls 호출: 1회 — 목록 썸네일 몫뿐
```

`서명걸기()`가 `img[data-경로]` 중 **`!g.src` 인 것만** 모으기 때문에(`17b:197`), 이미 `src`가 박혀 저장된 사진은 **새 서명을 영영 못 받는다.**
서명 URL은 1시간짜리라 **어제 붙인 사진은 오늘 열면 빈 칸**이다. 목록 썸네일(`사진들` 경로로 새로 만든다)만 정상이라 「목록엔 보이는데 열면 안 보인다」로 나타난다.
설계가 든 두 번째 이유(버킷·프로젝트가 바뀌면 지난 사진이 전부 깨진다)도 그대로 걸린다. 만료된 토큰이 Supabase 행에 그대로 실려 나가기도 한다.

**고칠 자리 둘 (17b-메모화면.js)**

1. `값모으기()`가 부르는 `편집기.읽기()` — 넘기기 전에 복제본에서 `img[data-경로]`의 `src`를 벗긴다
2. `서명걸기()`(17a:197) — `!g.src` 걸러내기를 없애고 열 때마다 다시 꽂는다(또는 그릴 때 `src`를 먼저 지운다)

## 1. 저장된 본문에 서명 URL이 안 남는다 ✅

사진 한 장 붙이고 저장 → `localStorage['zg.v3.메모']` 원문

```
"본문": "사진 재검수<img data-경로=\"2026/08/m-mszcptbp-cs9g/yr2wqcgh.jpg\" alt=\"\">",
"사진들": ["2026/08/m-mszcptbp-cs9g/yr2wqcgh.jpg"]
```

`src=` 0개 · `http`·`token` 0개 · `data-경로`만 남았다. 화면의 img 에는 `src`가 그대로 꽂혀 있다(복제본에서만 벗긴다 — 저장한다고 사진이 사라지지 않는다).

## 3. 이미 서명된 img도 다시 서명받는다(캐시 안 한다) ✅

`.filter(g => !g.src)` 가 빠진 것을 실호출로 확인 — src 가 이미 박힌 편집기에 `ZG.메모자료.서명걸기()` 를 다시 걸었더니
호출이 2 → 3 으로 늘고 `src` 가 `sign=1-0` → `sign=3-0` 으로 갈렸다. **1시간 지난 토큰을 안고 있지 않는다.**

**옛 형식(서명 URL이 박힌 채 저장된 본문)도 살아난다** — 만료 토큰이 실린 줄을 심어 두고 열었더니
`src` 가 새 서명으로 갈렸고(`보임: true`), 한 글자 고쳐 저장하니 본문에서 `token=EXPIRED` 와 `src=` 가 통째로 씻겨 나갔다.
그러니 시험하며 만들어진 옛 줄이 남아 있어도 저절로 정리된다.

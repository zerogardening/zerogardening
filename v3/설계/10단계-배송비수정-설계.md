## 1. 🔴 J열 = **단가 × 박스수 (합계)** — 8/9 우람님 정정

> **🔴 왜 바뀌었나(이전 판과 헷갈리지 않게)** — 이 설계서 첫 판은 「J열 = 박스 1개 단가, 절대 곱하지 않는다.
> 박스 N개 = 파일에 N줄」이었다. **틀렸다.** 우람님이 직접 정정하셨다 —
> 「**합계를 넣어야 해. 예를 들어 2개에 2750원이면 5500원 넣어야 해.**」
> 그래서 ①J열 계산식 ②「한 건 더 만들기」의 뜻, **이 둘만** 아래에서 바뀌었다. 나머지 절은 첫 판 그대로다.

| 단가 | 박스수 | **J열(`C.결제업체`, index 9)에 넣을 값** |
|---|---|---|
| 2,750 | 2 | **`5500`** |
| 3,300 | 1 | **`3300`** |
| 4,400 | 3 | **`13200`** |

### 1-1. 🔴 과거에 로젠에 낸 돈이 틀렸던 적은 없다 — 다시 조사하지 마라

`08i-로젠파일.js` **179행**은 지금 `o[C.결제업체] = g.운임;` 한 줄이고, **한 묶음의 모든 물리적 줄에 같은 값을 그대로 반복해 찍는다.**
지금 코드에는 **「박스 수」라는 개념 자체가 없다** — `갈래(g)`는 포장 방식(전용박스/골판지)만 가르고, 개수를 세거나 곱하는 자리는 어디에도 없다.
즉 지금까지는 **암묵적으로 「박스 1개」를 전제**해 왔고, `단가 × 1 = 단가`라서 결과가 맞아떨어져 왔다.
**이번 「박스 수량 손질」이 박스수 개념을 처음 들이는 것**이지, 틀린 자동계산을 바로잡는 일이 아니다.
그래서 **`08i`의 자동계산(점수표·갈래) 자체는 한 글자도 안 고친다.**

### 1-2. 🔴 파일 두 개를 헷갈리지 마라 — 우리가 올리는 것 vs 로젠이 돌려주는 것

| | **우리가 만들어 올리는 파일** | **로젠이 돌려주는 결과 파일** |
|---|---|---|
| 예 | `백업/로젠대량등록_20260806-01.xlsx` | `백업/주문등록_출력(복수건)_출력완료(5)건 (2026-08-04 23시17분41초).xlsx` |
| 형식 | **카페24 27칸을 재활용**(J = 「결제업체」 자리를 박스운임으로 씀) | 로젠 자체 서식 |
| 박스수량 칸 | 🔴 **없다** | **있다(L열)** — 실물은 전부 `1` |
| 운임 칸 | J열 하나 | 택배운임(M열) — 실물 `2,750` |
| 한 줄의 뜻 | 주문 줄 하나(합포장이면 여러 줄이 한 송장) | **행 하나 = 박스 하나** |
| 합계 | 없음 | 맨 아래 합계 줄 — `박스수량 5 · 택배운임 13,750`. **여러 행을 합산한 값**이지 한 행 안에서 곱한 값이 아니다 |

**우리 업로드 포맷에는 박스수량 칸이 애초에 없다.** 그래서 「박스 2개짜리 주문」을 한 줄로 표현할 방법은
**J열에 합계를 적는 것뿐**이고, 우람님이 그렇게 정하신 것이다.

🔴 **박스수는 우리 파일의 줄 수·송장 장수를 바꾸지 않는다.** 곱셈 인자일 뿐이다.
「진짜로 송장을 한 장 더 낸다」는 **별개 기능**이고 §6에 있다.

🔴 **손님에게 받는 배송비는 이 프로그램이 계산하지도 보여주지도 않는다.** AA열(배송비정보)은 원본 그대로 나간다.

## 3. 저장 — 「그 회차에만」의 근거

### 3-1. 새 표 하나. 손질 하나 = 행 하나

`ZG.저장소.키.운임손질 = 'zg.v3.운임손질'` **한 줄만** 더한다. **스키마버전은 안 올린다.**

```jsonc
{ "id": "260808-01#최영주|12432|01012345678",  // 🔴 회차id # 묶음열쇠 (+ 추가 송장이면 #2 #3 …)
  "묶음id": "260808-01",        // 회차. 이 값이 「그 회차에만」을 만든다
  "묶음열쇠": "최영주|12432|01012345678",
  "차수": 1,                    // 🔴 1 = 원래 묶음 · 2↑ = §6으로 더 만든 별도 송장
  "수령인": "최영주",            // 사람이 나중에 알아보기 위한 표시용
  "단가": 4400,                 // 🔴 박스 1개 값. J열에 그대로 들어가지 않는다
  "박스수": 2,                  // 🔴 곱셈 인자일 뿐. 줄 수·송장 장수를 바꾸지 않는다
  "자동값": "확인요망",          // 손대기 전 08i 가 계산한 값
  "만든때": 1754640000000, "고친때": 1754640000000 }
```

🔴 **합계(단가 × 박스수)는 저장하지 않는다.** 파생값이라 두 벌이 되면 반드시 어긋난다 — J열은 읽을 때 곱한다.
🔴 **`차수`가 2 이상인 행은 §6의 「송장 한 장 더」다.** 그 행도 자기 `단가`·`박스수`를 따로 갖고 **자기 합계를 독립으로** 계산한다.

- **다른 회차·다음 업로드에 새어나가지 않는다** — `id` 앞머리가 회차라 `묶음id`가 다르면 아예 다른 행이다.
- 같은 회차를 **다시 내려받으면 고친 값이 그대로 다시 실린다**(시안 ⓐ 그대로).
- 칸 이름을 `품목코드`로 짓지 않았다 — `01-저장소.아이디()`의 `r.id || r.품목코드` 폴백에 안 걸린다(8단계 §5-2와 같은 이유). `표키` 표도 안 건드린다.
- 쓰기는 `저장소.덧붙이기` / `바꾸기` / `지우기` **한 행씩**. 한 덩어리 JSON을 만들지 않는다.

### 3-2. 묶음열쇠 — 08i의 그룹키를 그대로 쓴다

`08i.그룹키()`가 만드는 `이름|우편번호|전화` 다. 같은 파일을 다시 올려도 같은 값이 나온다.
**딱 한 줄만 고친다** — 이름·우편번호가 없어 혼자 처리되는 갈래의 `'홀로#' + i`(줄 번호라 흔들린다)를
**`'홀로#' + 주문번호 + '#' + 원본코드`**로 바꾼다. 묶기 결과는 지금과 똑같다(여전히 줄마다 혼자다).
실데이터 1,287건에 **이름·우편번호 빈 줄은 0건**이라(백업 JSON 전수) 지금 걸릴 일은 없고, 열쇠 안정성만 얻는다.

## 4. `08i-로젠파일.js` — 손질값을 얹어 **합계**를 J열에 찍는다

> **🔴 8/9 정정** — 옛 판의 「박스수 − 1개만큼 `2번박스` 줄을 더 붙인다」는 **폐기**. 줄은 안 늘어난다. 값만 바뀐다.

### 4-1. 손질표를 받는 자리

`준비(항목들)` · `내보내기(항목들, 파일명)` 에 **셋째/둘째 인자로 `{묶음id}`** 를 받는다(없으면 손질 없음 = 지금과 완전히 같은 동작).
`만들기()` 안에서 `ZG.운임손질.표(묶음id)` 를 한 번 읽어 `{묶음열쇠: 손질}` 맵을 만든다.

### 4-2. `재기()` 끝에 여섯 줄 — **여기가 이번 정정의 전부다**

```js
g.자동값 = 점 >= 12 ? '확인요망' : (점 >= 9 ? '3300' : '2750');   // 지금 g.운임 계산식 그대로
var 손 = 손질표[g.키];
g.단가   = 손 ? String(손.단가) : g.자동값;      // 박스 1개 값
g.박스수 = 손 ? Math.max(1, 손.박스수 | 0) : 1;  // 🔴 곱셈 인자. 줄 수와 무관
g.손댐   = !!손;
g.운임   = (g.단가 === '확인요망')               // 🔴 J열에 실제로 나갈 값 = 합계
           ? '확인요망'
           : String(Number(g.단가) * g.박스수);
```

- **손질이 없으면 `박스수 = 1`이라 `g.운임 === g.단가`** — 파일이 지금과 바이트 단위로 같다(회귀 시험 1번).
- `확인요망`은 곱하지 않고 글자 그대로 내보낸다(지금과 같음).

### 4-3. `표만들기()` — **179행 패턴을 그대로 둔다. 값만 합계다**

```js
o[C.결제업체] = g.운임;   // 그룹 전 줄 같은 값 — 지금 179행 그대로. 이제 이 값이 「단가 × 박스수」다
```

- 줄 수는 **하나도 안 늘어난다.** 합포장 묶음의 모든 물리적 줄에 같은 합계를 반복해 찍는다(지금과 동일한 동작).
- E열 앞머리·`/`·`번호되쓰기()`·동봉카드·재구매 표시는 **한 글자도 안 바뀐다.**
- 별도 송장을 진짜로 하나 더 내는 경우만 줄이 늘어난다 — **§6.**

### 4-4. `준비()`가 더 돌려주는 숫자

`묶음수`(= 그룹 수. §6 추가 송장이 있으면 그만큼 늘어난다) · `박스합`(= Σ 박스수 — 화면 표시용) ·
`손댄묶음`(= 손댐 개수) · `확인요망`(= `g.단가`가 `'확인요망'`인 묶음 수 — 지금 있던 셈의 기준만 `g.운임`→`g.단가`로 바꾼다) ·
`운임합계`(= 단가가 숫자인 묶음만 **Σ 단가 × 박스수** = Σ `g.운임`) · `그룹들`.

🔴 **「송장수」라는 이름을 쓰지 않는다.** 옛 판에서 「송장수 = Σ박스수」였는데 이제 뜻이 달라져 혼동을 부른다.

## 5. 화면 — 시안에서 **뺀 것 4가지**를 반영한 최종 구조

### 5-1. 뺀 것 (우람님 마이너 수정)

| 시안에 있던 것 | 이번 |
|---|---|
| 「손댄 묶음 N」 요약 칸(`.sum.ok`) · 「✎ 손댄 묶음」 상자 | **없앤다.** 완료창 위 `sums` 3칸은 **지금 구현 그대로** 둔다 |
| 「어떻게 정해졌나」 칸 · 「자동 (점수 6)」 · 「확인요망(점수 12↑)」 설명 | **없앤다.** 계산 근거를 글로 쓰지 않는다 |
| 「이 묶음 정해두기」 / 「이 묶음 정하기」 | **「저장」** |
| 상단 경고바(「확인요망 N묶음」 + 설명글) · 「확인요망만 보기」 · 「확인요망 N묶음」 통계칸 | **없앤다.** 상태는 **줄 색으로만** 말한다 |
| 「파일에 실제로 들어갈 값」 표(시안 ④ 마지막) | **없앤다.** 줄 목록 자체가 곧 파일에 들어갈 값이다 |
| 「✎ 손댐」 배지 · 취소선 `was` | **없앤다.** 고친 줄은 **초록**으로만 나타낸다 |

### 5-2. 줄 색 — 상태를 나타내는 유일한 수단

| 색 | 언제 | CSS |
|---|---|---|
| **빨강** (왼쪽 띠 + 옅은 빨강 바탕) | `단가 === '확인요망'` — 아직 정해지지 않음 | `.grp.ng` |
| **초록** (왼쪽 띠 + 옅은 초록 바탕) | 손질 행이 있음 — 우람님이 정한 값 | `.grp.edited` |
| 흰색 | 자동값 2750·3300 그대로 | `.grp` |

**저장하는 순간 그 줄이 빨강 → 초록으로 바뀐다.** 그것이 전부다. 안내 문구를 붙이지 않는다.

### 5-3. 완료창(`08h.완료창()`) 최종 차림

1. `sums` 3칸 — **지금 그대로**(저장된 줄 · 건너뛴 줄 · 품목코드 없이 저장)
2. `.done` 한 줄 — **지금 그대로**
3. 상자 「⬇ 로젠 대량등록 파일」 — 지금 그대로. **「박스운임 (J열)」 행의 글월만** 바꾼다 →
   `단가 × 박스수 = 합계가 들어갑니다`
4. 🆕 상자 「📦 로젠에 나갈 {묶음수}묶음 · 박스 {박스합}개」 (회색 톤) — `ZG.운임손질창.상자(준비, {묶음id, 바뀌면})`

## 9. 🔴 8/10 추가 — 동봉카드에도 `1-1`·`1-2`를 찍는다

> **왜 다시 왔나** — `ba29ba7`은 로젠 파일 E열·화면에만 분번을 넣었다. 우람님 재지시: **「동봉카드에도 갈라 적어라.
> 송장 번호와 카드 번호가 반드시 같아야 한다」** — 안 그러면 포장할 때 엉뚱한 카드가 들어간다.

### 9-1. 저장되는 정수 `r.출력번호`는 안 건드린다 — 새 칸 `r.상자수` 하나를 더 얹는다

`09-동봉카드.js`가 `Number(r.출력번호)`로 읽으므로 `"1-1"`을 넣으면 NaN이 난다(`ba29ba7` 주석 그대로).
그래서 **"몇 상자인가"를 별도 정수 칸에 담는다.**

- `08i-로젠파일.js` `추가붙이기()` — 원 그룹에 `g.분번=1`을 줄 때 **`g.총분모 = 손들.length + 1`**도 같이 준다(추가 그룹에도 준다. 카드가 쓰지는 않지만 대칭을 위해)
- `번호되쓰기()` — 다운로드마다 `r.상자수 = g.총분모 || 1`을 **값이 다를 때만** 되쓴다.
  🔴 **`출력번호`와 반대로 매번 갱신한다** — 송장을 나중에 더 붙이거나 지우면 상자 수가 바뀌는데, 그게 카드에 그대로 반영돼야 한다.
  값이 같으면 저장소를 다시 쓰지 않는다(무의미한 sync 트래픽 방지)

### 9-2. `09-동봉카드.js` — 상자 수만큼 카드를 통째로 복제한다

`판들만들기()`에서 `g.줄들[0].상자수`(없거나 1이면 지금과 완전히 같다)를 읽어 그 수만큼 같은 식물 내용을 반복해서 찍고,
번호만 `번호-1`·`번호-2`…로 바꾼다. **품목을 상자별로 나누는 기능은 아직 없어(§5-4 스텁) 내용은 완전히 같다** —
어느 상자를 열어도 전체 관리 안내가 들어 있게 하는 게 안전하다(부분정보보다 낫다).

### 9-3. 어긋나는 경우 — 카드를 로젠 파일보다 먼저/다르게 뽑을 때

`r.상자수`는 `r.출력번호`와 같은 시점(로젠 파일 **다운로드**)에만 갱신된다. 그래서:

- **손질(박스 분리)을 저장만 하고 아직 로젠 파일을 한 번도 안 받았으면** 카드는 옛 값(상자수 없음 또는 이전 값)으로 나온다 — 갈라지지 않은 카드 한 장. 이건 `출력번호` 자체가 이미 갖고 있던 것과 **같은 종류의 위험**이고(§4-3 「아직 안 뽑았으면 지금까지처럼」), 로젠 파일을 받는 순간 다음 카드부터 맞는다.
- **송장을 나중에 하나 더 붙이고 로젠 파일을 다시 받으면** `상자수`가 갱신되므로 그 뒤에 뽑는 카드는 맞다. **먼저 뽑아 둔 카드(인쇄물)는 당연히 갱신되지 않는다** — 종이라서 어쩔 수 없다. 우람님 작업 순서(로젠 파일을 받고 나서 카드를 뽑는다)를 지키면 문제가 없다.
- 결론 — **로젠 파일을 받은 뒤에 카드를 뽑으면 항상 같다.** 순서를 바꾸면(카드 먼저) 옛 카드가 남을 수 있으니 **카드는 로젠 파일을 받은 뒤에 뽑는다**를 지침으로 남긴다.

### 9-4. 회귀

`상자수` 칸이 없는 옛 주문줄은 `Number(undefined) || 1` → `1` → 상자수 반복문이 1번만 돌아 **지금과 완전히 같은 카드 한 장**이 나온다. 로젠 파일 코드(표만들기·손질얹기·정렬)는 한 글자도 안 바꿨다.

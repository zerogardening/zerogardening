**1단계 설계(`1단계-설계.md`)가 원본이다.** CSS 변수·애니메이션(§10)·접근성(§11)·PWA(§15)·저장소 규약(§3-7)·품목코드 규칙(§6)은 **거기 그대로**다. 목록/등록/수정의 화면 뼈대(PC 표 + 시트, 폰 목록 + 상세)는 **입고·주문과 같다** — 패턴 원본은 `js/05a-입고화면.js` · `js/08b-주문목록.js`. 여기엔 **업체·명세서에만 있는 것**만 적는다.

`{ id, 명세서id, 순번:number, 품목코드:"", 유통명, 학명, 규격, 수량:number, 단가:number, 매입단가:number, 과세구분:"면세"|"과세" }`

- `품목코드`가 빈 문자열이면 **직접 입력한 미등록 품목**이다(실데이터 명세서 1건이 전부 이 경우다 — 코드·매입단가가 다 비어 있다).
- `매입단가`는 **할인율을 바꿀 때 다시 계산하려고** 들고 있는다. 0이면 비율 환산으로 간다(§4-2).
- `금액`은 저장하지 않는다. `수량 × 단가`로 그때그때 계산한다.

### 2-4. 🔴 `99-이사.js`를 먼저 고친다 — 지금 값이 통째로 빠진다

이사 도구는 **아직 우람님 브라우저에서 돌지 않았다**(현재상태.md). 그러니 지금 고치면 된다. 백업 JSON을 실제로 열어 확인한 것:

구 데이터의 업체 13곳은 **필드 이름이 두 세대로 갈려 있다.** 옛 6곳은 `ceo`·`category`·`manager`·`items:배열`, 새 7곳은 `representative`·`type`·`contactPerson`·`terms`·`bankAccount`·`items:문자열`. 그런데 `99-이사.js` 269~287줄은 **옛 이름만 읽는다.**

| 빠지는 값 | 몇 건 | 무엇이 사라지나 |
|---|---|---|
| `representative` → `대표` | 7곳 | 박찬규·서수현·박기민·김도현·김두용·채인·배재식이 전부 빈칸 |
| `bankAccount` → `입금계좌` | 1곳 | 제로가드닝 농협 계좌 — **명세서 비고의 입금계좌가 통째로 사라진다** |
| `contactPerson` → `담당자` | 1곳 | 제로가드닝 「백우람 / 010-2296-4669」 |
| `terms` → `거래조건` | 7곳 | |
| `type` → `구분` | 7곳 | 전부 `공급업체`로 뭉개진다. 시골살이궁리소(`other`)가 틀린다 |
| `items` 자료형 | 13곳 | 배열과 문자열이 섞여 들어간다 |

고치는 방법 — **두 이름을 다 읽는다.** `c.representative || c.ceo || ''` / `c.contactPerson || [c.manager, c.managerPhone].filter(Boolean).join(' / ')` / `c.bankAccount || ''` / `c.terms || ''`.
`구분`은 `supplier→공급업체` · `customer→판매처` · `logistics→운송·택배` · `other→기타 협력사` · `'기타'→기타 협력사`, 없으면 `공급업체`.
`취급품목`은 배열이면 `.join(', ')` 해서 **언제나 문자열**로 만든다.
명세서는 지금 `(구.statements||[]).map(s=>s)` 로 **영문 칸 이름 그대로** 들어간다 — §2-2·§2-3의 한글 칸으로 바꾸고 `items`를 `명세서줄` 3줄로 쪼갠다. 실데이터 1건이라 비용이 거의 없다.

## 4. 명세서 계산 규칙 — 기존 식을 한 글자도 바꾸지 않는다

업무규칙 §3 「명세서 단가」와 `app.html` `calcDiscountedPrice`가 같은 식이다.

### 4-1. 단가

```
단가 = Math.round( (매입단가 × 2) × (1 − 할인율/100) / 100 ) × 100
```

- 할인율은 **`-200` ~ `99`로 자른다**(`Math.max(-200, Math.min(99, 값))`).
- 화면의 `할인/할증` 드롭다운에서 **할증을 고르면 입력값의 부호를 뒤집어** 위 식에 넣는다. 즉 할증 20% = `할인율 -20`. 실데이터 명세서 1건이 정확히 `-20`이다.
- `매입단가`가 0이면 단가를 계산하지 않는다(0을 돌려주고 사용자가 직접 넣는다).

### 4-2. 할인율을 바꿨을 때 이미 들어간 줄

```
매입단가 > 0  →  4-1 식으로 다시 계산
매입단가 = 0  →  단가 × (1−새할인/100) ÷ (1−옛할인/100) → 100원 반올림, 0 밑으로 안 내려간다
```

### 4-3. 단위 정리 (일괄)

단위 `10 / 100 / 1,000 / 10,000`(기본 100) × 방식 `반올림 / 올림 / 내림`(기본 반올림)을 골라 「적용」을 누르면 **모든 줄의 `단가`를** `Math.round|ceil|floor(단가/단위) × 단위`로 바꾼다. 줄이 없으면 토스트로 알리고 아무것도 안 한다.

### 4-4. 합계 · 번호

```
줄 공급가액 = 수량 × 단가
줄 세액     = 과세구분==='과세' ? Math.round(줄 공급가액 × 0.1) : 0      ← 면세는 언제나 0
합계        = Σ공급가액 + Σ세액
NO          = YYYYMMDD-HHmm            (발행 시각. 예 20260805-1432)
인쇄 파일명  = YYYY-MM-DD_업체명_NN     (같은 날 같은 업체로 이미 저장된 건수 + 1, 2자리)
             업체명의 \ / : * ? " < > | 는 _ 로 바꾼다
```

### 4-5. 품목 추가

- **타이핑이 아니라 목록선택이다.** `ZG.ui.자동완성` + `ZG.ui.후보찾기`를 그대로 쓴다(접두 묶음 → `최근규격`·`최근단가`). 고르면 `매입단가 = 최근단가`, `단가 = 4-1식`으로 자동으로 채운다.
- **같은 품목을 두 번 못 넣는다** — 품목코드가 둘 다 있으면 코드로, 없으면 `유통명 + 규격`으로 본다. 걸리면 `ZG.ui.확인`이 아니라 토스트로 알리고 **수량은 표에서 직접 고치라고** 안내한다(기존 문구 그대로).
- 「✏️ 직접 입력」 — 등록 안 된 품목을 이름·규격·학명·수량·단가·과세로 넣는다. 품목명 없음 / 수량 0 이하 / 단가 0 이하는 막는다. `품목코드=''`, `매입단가=0`.
- 검색어에 맞는 게 없으면 **적은 글자를 그대로 미등록 품목명으로** 넣는다(단가는 반드시 입력).
- 표 안 `수량`·`단가`는 인라인으로 고친다. 고치면 그 줄의 공급가액·세액과 아래 합계가 곧바로 바뀐다.

### 4-6. 공급자(자사)·비고

- 공급자란은 `내업체:true`인 업체에서 **읽기 전용으로** 채운다. 지정된 곳이 없으면 상호 자리에 「⚠ 업체 등록에서 "공급자로 지정"을 체크해주세요」를 띄운다.
- 「⚙ 내 업체정보」는 **업체 검색 탭으로 옮겨 그 업체 수정 시트를 연다**(지정이 없으면 등록 탭을 열고 토스트로 안내). 명세서 안에서 자사 정보를 고치지 않는다.
- 비고 기본값 = `배송비 별도` + 자사 `입금계좌`가 있으면 `입금계좌: …` 한 줄. **사용자가 손댄 흔적이 없을 때만** 자동으로 갱신한다 — 빈칸이거나 / 정확히 `배송비 별도`거나 / `배송비 별도` + `입금계좌: …` 두 줄 그대로일 때.

## 5. 발행 이력 저장 방식

| 무엇 | 규칙 |
|---|---|
| **💾 저장** | 이력에 한 장 **덧붙인다**(머리 1줄 + 줄 N줄). 품목이 0이면 막는다 |
| **🖨 출력** | **인쇄만 한다. 저장하지 않는다** — 기존 구현 그대로. 품목이 0이면 막는다 |
| 중복 저장 막기 | 직전에 저장한 내용의 스냅샷 문자열을 들고 있다가 **똑같으면 「이미 저장되었습니다」**로 넘긴다. 불러오기 직후에도 이 스냅샷을 채워 둔다 |
| 불러오기 | 머리 + 그 `명세서id`의 줄을 `순번`대로 읽어 작성 화면을 채우고 작성 탭으로 넘어간다. **새 장이 아니라 그 장을 다시 여는 것**이라 `번호`도 그대로 쓴다 |
| 삭제 | `ZG.업체자료.명세서지우기(id)` — 머리와 줄을 같이 지운다. `ZG.ui.확인` 필수 |
| 이력 검색 | 고객사명·NO 부분일치 + 유형 필터(전체/거래명세서/견적서). 정렬은 최신순 |

**인쇄** — 화면의 `.doc`가 곧 종이다. 할인율·단위정리·품목추가줄·삭제(×)는 `@media print`에서 감춘다(시안 「화면에서만 쓰는 것」). PDF 파일명이 되도록 `window.print()` 직전에 `document.title`을 §4-4 파일명으로 바꾸고 1.5초 뒤 되돌린다. 인쇄 제목이 끼어드는 사고는 `09-동봉카드`에서 `.pcsheet:has(…) .hd` 로 이미 겪었다 — **업체.css에서 `.doc` 바깥 전부를 `display:none`으로 확실히 끈다.**

## 6. IME 안전입력 (`04-공통UI.js`의 `조합안전입력`)

한글을 치는 동안 `input` 이벤트마다 다시 그리면 **글자가 깨지거나 조합이 끊긴다.** 아래 칸은 전부 `ZG.ui.조합안전입력(입력, 처리, 200)`으로 감싼다.

| 화면 | 칸 |
|---|---|
| 업체 검색 | 검색어 (목록을 다시 그린다) |
| 업체 등록·수정 | 업체명 · 대표자 · 담당자 · 주요 취급 품목 · 주소 · 거래조건 · 메모 |
| 명세서 작성 | 공급받는자 상호(자동완성) · 대표자 · 주소 · 담당자 · 비고 |
| 명세서 품목 | 품목 검색칸(자동완성) · 직접입력의 품목명·규격·학명 |
| 발행 이력 | 고객사명·NO 검색 |

숫자칸(사업자번호·전화·수량·단가·할인율)은 감싸지 않는다 — 조합이 없다.
`ZG.ui.자동완성`은 안에서 이미 `조합안전입력`을 쓴다. **두 번 감싸지 마라.**
Esc는 `ZG.ui.탈출걸기/탈출풀기`만 쓴다. 모듈이 각자 `document`에 리스너를 걸면 시트가 통째로 닫힌다(8/5 `09b` 사고).

## 7. 실데이터에서 확인한 것 — 이 설계가 막는 오류

1. **업체 필드가 두 세대로 갈려 있다** (§2-4). 이사 도구를 안 고치면 대표자 7곳·입금계좌 1곳이 조용히 빈칸이 된다. **입금계좌가 빠지면 명세서 비고가 빈다.**
2. **`취급품목`이 배열(6곳)과 쉼표문자열(7곳)로 섞여 있다.** 문자열로 통일해 넣는다. 화면은 문자열만 다룬다.
3. **`담당자전화`는 구 데이터 1곳(영주포장 `010-4118-9392`)에만 있다.** 시안이 담당자를 한 칸으로 그렸으므로 `이름 / 전화`로 합쳐 넣고 폼에는 칸을 두지 않는다. **값을 버리지는 않는다.**
4. **명세서 실데이터 1건은 품목코드·매입단가가 전부 비어 있다**(직접 입력한 견적서). 코드가 없는 줄에서 터지지 않게 §4-2의 비율 환산 갈래를 반드시 넣는다.
5. **그 1건의 `discount`가 `-20`이다** — 할증 20%. 불러오기 했을 때 드롭다운이 「할증 / 20」으로 서야 한다. 「할인 / -20」으로 뜨면 틀린 것이다.
6. 업체 19곳 중 6곳은 **입고에만 이름이 있어 이사 때 새로 만든 곳**이라 이름·구분 말고는 전부 비어 있다. 목록에서 빈칸이 `-`로 얌전히 보여야 한다.

## 9. 3단계에서 **만들지 않는 것**

- 페이지 넘김(pager) — 업체 19곳·명세서 1건이다. 다 그린다. 시안의 `.pager`는 넣지 않는다.

- 업체별 거래내역·미수금 집계 화면.

- 스키마버전 올리기 — 올리면 실데이터가 목데이터로 덮인다(`01-저장소.js` 106줄).

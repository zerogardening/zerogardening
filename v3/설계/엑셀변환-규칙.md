## 파일 4개가 도는 순서

```
① 카페24 주문 내려받기  →  ② 로젠 대량등록      (generateShippingXlsx)
③ 로젠 출력완료         →  ④ 카페24 송장 업로드  (convertRosenToShipped)
```

파일 이름은 **`20{YYMMDD}-{NN}.xlsx`** (예 `20260804-01.xlsx`). 같은 이름이 있으면 `-01` `-02` 를 뒤에 붙인다.
③번 파일의 「파일명」칸에 ②에서 올린 이름이 그대로 돌아온다.

# ① → ② 카페24 주문 → 로젠 대량등록

**열 순서는 카페24 원본 27칸 그대로 두고, 아래 두 칸만 덮어쓴다.**

```
A쇼핑몰 B쇼핑몰번호 C주문번호 D발주일 E주문상품명 F상품번호 G옵션 H자체품목코드
I결제수단 J결제업체 K결제정보 L판매가 M수량 N수령인 O우편번호 P주소
Q수령지전화 R전화번호 S핸드폰 T비고 U주문자 V주문자우편번호 W주문자주소
X주문자전화번호 Y주문자핸드폰 Z옵션추가가격 AA배송비정보
```

🔴 **머리글 줄을 넣지 않는다.** 택배 프로그램이 1행도 데이터로 읽는다.

## E열 앞 — 출력번호 `(N)`

🔴 **동봉카드와 송장을 짝지으려고 붙인다.** 동봉카드에서 받는 분 이름을 뺐기 때문이다
(이름을 찍으면 오히려 불편한 경우가 많았다고 우람님이 빼라고 하셨다).

- **번호 = 합포장 그룹 순번.** 아래 「줄 순서 = 작업자가 포장하는 순서」로 정렬한 뒤, **그룹마다 1번씩** 매긴다
- 같은 그룹의 줄은 **전부 같은 번호**를 쓴다. 줄마다 늘어나지 않는다
- 🔴 **출력번호와 재구매 회차를 괄호 하나에 합쳐 쓴다.** 따로 두 개 붙이지 않는다

| 손님 | 붙는 것 |
|---|---|
| 처음 사시는 분 | `(12) ` |
| 3번째 사시는 분 | `(12/★3) ` |

- 🔴 **묶음의 맨 앞 줄에만 붙인다.** 한 송장에 품목이 여러 개여도 **두 번째 줄부터는 아무것도 안 붙는다**
  (전에는 줄마다 별이 다 붙어 지저분했다 — 우람님이 맨 앞 하나만 하라고 하셨다)

```
(12/★3) 추명국 핑크터치(15cm) 2개/     ← 맨 앞 줄에만
        청사초(10cm) 6개/               ← 그냥 상품명만
        수크령 '레드헤드'(15cm) 4개/
```

**동봉카드는 같은 번호를 오른쪽 아래에 연한 회색으로 찍는다**(`12`). 종이와 송장을 번호로 맞춘다.

## E열 — 상품명을 다시 쓴다

카페24 상품명(`제로가드닝 추명국 (아네모네) 15cm화분…`)을 그대로 보내지 않는다.

```
{유통명}({N}cm) {총수량}개        예: 추명국 핑크터치(15cm) 2개
```

- **유통명**: 품목코드 앞 5자(`ANP01`)로 찾는다. 1차 SKU 마스터, 없으면 입고기록에서 보충
- **cm**: 품목코드 뒤 숫자(`ANP01-15` → 15). 없으면 `(cm)` 부분을 뺀다
- **못 찾으면 원본 상품명을 그대로 둔다** (지어내지 않는다) + 콘솔에 경고

## 총수량 = 옵션수량 × 주문수량

🔴 **옵션이 `수량=N개` 일 때만 곱한다.**
`색상=3.휴케라 라임리키` 같은 옵션은 **무시하고 M열 수량만 쓴다.**

## 합포장 묶기

**묶음키 = 이름 + 우편번호 + 연락처**

- 이름·우편번호는 NFC 정규화 + 모든 공백 제거 후 비교. 우편번호는 숫자만 남긴다
- 연락처는 휴대폰 → 전화2 → 전화 순으로 첫 번째 있는 것, 숫자만
- 🔴 **`050`으로 시작하면 안심번호다**(쿠팡). 서로 달라도 같은 사람으로 묶고, **나중에 들어온 주문의 번호로 그룹 전체를 통일**한다
- 이름이나 우편번호가 없으면 **혼자 처리**한다. 다른 무명 주문과 섞지 않는다

🔴 **v3 확정문에는 「이름＋주소＋전화번호」로 돼 있으나 우편번호로 간다.**
주소 글자를 그대로 비교하면 `( 목동, 신시가지5단지 )` 와 `( 목동 신시가지5단지 )` 가 다른 사람이 된다. 실데이터에 이미 있다.

## 복수건 표시

한 묶음에 줄이 2개 이상이면 **상품명 뒤에 `/` 를 붙인다.** 로젠이 이걸로 합포장을 인식한다.
품목을 하나로 합치지 않는다 — **줄마다 1행 그대로** 내보낸다.

## J열 — 박스운임 자동계산

포트 크기 점수 × 수량을 묶음 전체로 더한다.

| 포트 | 점수 |
|---|---|
| 10cm 이하 | 1 |
| 15cm 이하 | 2 |
| 22cm 이하 | 3 |
| 23cm 이상 | 4 |
| 모름 | 2 |

| 합계 | J열에 넣는 값 |
|---|---|
| 9 미만 | `2750` |
| 9 이상 | `3300` |
| 12 이상 | `확인요망` (1박스 넘을 수 있다) |

같은 묶음이면 **모든 줄에 같은 값**을 넣는다.

**박스를 여럿 보낼 때는 `단가 × 박스수` 합계를 넣는다** (2750×2 = `5500`). 박스수는 아래 K열에 같이 적는다.

## K열 — 택배수량(박스수)

🔴 **J열만 올려도 K열이 비어 있으면 로젠은 「5500원 1개」로 찍는다** (우람님 8/12 신고 — 실제로 이렇게 나갔다).
J열과 K열은 **반드시 짝으로** 나간다.

| 우람님이 넣은 값 | J열 | K열 |
|---|---|---|
| 2750원 × 2박스 | `5500` | `2` |
| 2750원 × 4박스 | `11000` | `4` |
| 손 안 댐 (1박스) | `2750` | **빈칸** |

- **박스수 1은 빈칸으로 둔다** — 여태 나간 파일과 한 글자도 달라지지 않는다
- 🔴 **묶음(합포장)에서는 딱 한 줄에만 적는다. 나머지 줄은 빈칸이다** — 로젠은 줄마다 더한다.
  2품목 묶음의 두 줄에 다 `3` 을 적었더니 송장이 **3+3=6장** 나갔다(우람님 8/31 신고, 조혜숙 건).
  J열은 반대로 **모든 줄에 같은 값**이다 — 그건 로젠이 안 더한다
- 원래 K열은 카페24 `결제정보` 자리인데 **실주문에서 늘 비어 있다** (`백업/카페24주문원본_20260806.csv` 로 확인)

## 줄 순서 = 작업자가 포장하는 순서

🔴 **이게 이 파일의 진짜 값이다.** 아무렇게나 정렬하면 안 된다.

1. **포장 갈래** — ①단품·15cm이상·수량1(전용박스 1개) → ②단품·15cm이상·수량2+(전용박스 여러개) → ③단품·15cm미만 또는 크기모름(롤골판지) → ④복수건(롤골판지)
2. 그 안에서 **포트 크기** 작은 것부터 (크기 모름은 맨 뒤)
3. 그 안에서 **품종**(코드 앞 5자)
4. 그 안에서 **수량**
5. 그 안에서 **주문번호**

**묶음 안의 줄 순서는 주문 들어온 순서 그대로 둔다.**

이 순서를 저장해 둬야 **동봉카드를 같은 순서로 뽑는다.**

## 재구매 회차

2회차부터 표시한다. 🔴 **따로 붙이지 않는다 — 위 「출력번호」의 `(12/★3)` 안에 같이 들어간다.**
🔴 **묶음의 맨 앞 줄에만.** (옛 코드는 줄마다 `(★3)` 을 다 붙였다. 그러지 마라)

- **이름 + 우편번호** 기준 (안심번호 때문에 전화로는 사람을 못 가린다)
- **같은 날 여러 주문은 1회**로 센다
- 한 송장 안에 같은 사람이 여럿이면 **가장 큰 회차로 통일**
- 이름이나 우편번호가 없으면 **안 센다**(표시 없음)

# ③ → ④ 로젠 출력완료 → 카페24 송장 업로드

## 읽기

🔴 **4행부터가 데이터다.** 1행 제목, 2·3행 머리글 두 줄.

| 뽑을 것 | 어디 |
|---|---|
| 주문번호 | **S열** (19번째) |
| 운송장번호 | **D열** (4번째) |
| 박스수량 | **L열** (12번째) |

**주문번호와 운송장번호가 둘 다 비면 건너뛴다.** (전화주문 줄이 섞여 있다)

## 쓰기

머리글 **포함** 4칸으로 내보낸다.

```
주문번호, 품목별 주문번호, 운송장번호, 수량
```

- **품목별 주문번호** = `{주문번호}-{NN}`. NN은 같은 주문번호가 나온 순서, 두 자리(`-01` `-02`)
- **수량이 1이면 공란**으로 둔다
- 주문번호가 없으면 품목별 주문번호도 빈칸

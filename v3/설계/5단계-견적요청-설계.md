# v3 5단계 설계 — 주문 관리 › 견적 요청 (서브탭)

**1단계 설계(`1단계-설계.md`)가 원본이다.** CSS 변수·애니메이션(§10)·접근성(§11)·PWA(§15)·저장소 규약(§3-7)은 **거기 그대로**다.
서브탭을 다는 방식은 **3단계 설계 §1(업체 › 명세서 탭)과 같다.** 목록+등록+수정의 뼈대는 **입고·업체와 같다** — 패턴 원본 `js/05a-입고화면.js` · `js/10b-업체목록.js` · `js/10c-업체폼.js`. 여기엔 **견적 요청에만 있는 것**만 적는다.

시안 = `시안/05-견적요청-macA.html`(+png). 화면은 바꾸지 않는다.
기존 구현 = `app.html` 2945~2990(HTML)·4747~4785(Store)·9350~(JS). **로직을 그대로 옮긴다. 새 규칙을 만들지 않는다.**

🔴 **왼쪽 메뉴는 안 건드린다.** 4개(상품·주문 관리·업체 관리·상품소싱) 그대로다. 폰 아래 탭바도 4개 그대로다. 견적 요청은 **주문 관리 안 두 번째 탭**이지 메뉴가 아니다.
🔴 **주문 조회는 한 줄도 안 고친다.** `08a`·`08c`·`08d`·`09`·`09b`는 손대지 않고, `08b`는 **아래 §3의 두 줄만** 바뀐다.

## 3. 🔴 서브탭 붙이는 법 — `08b`에서 고치는 것은 **두 줄뿐**

`주문.html`의 셸은 `js/08b-주문목록.js`가 그린다(`폰뼈대`·`PC뼈대`·`다시그리기`). 여기에 **갈고리 한 개**만 낸다.

```js
/* 08b-주문목록.js 다시그리기() — 바뀌는 곳은 이 두 줄이다 */
    if (u.폰인가()) {
      var 뷰 = 뷰객체();
      폰뼈대(뷰);
      if (!(ZG.견적탭 && ZG.견적탭.가로채기(본문, 상태.뷰))) 뷰.그리기(본문);   // ← ①
    } else {
      if (상태.뷰 !== '목록') 상태.뷰 = '목록';
      PC뼈대();
      if (!(ZG.견적탭 && ZG.견적탭.가로채기(본문, 상태.뷰))) PC그리기(본문);    // ← ②
    }
```

`ZG.견적탭.가로채기(본문, 뷰이름)` 이 하는 일 — **나머지는 전부 DOM 손질이라 `08b`를 더 안 건드린다.**

1. `뷰이름 !== '목록'` 이면(수동주문·출고리스트·주문상세) **아무것도 안 하고 `false`.** 그 화면들엔 탭줄이 없다.
2. 탭줄을 만들어 넣는다.
   **PC** — `.pc-tabs` 두 칸(`주문 조회` · `견적 요청`)을 `본문.parentNode.insertBefore(탭줄, 본문)`. 시안대로 `pc-head` 바로 아래다.
   **폰** — `.subtabs` 두 칸을 `본문`의 **첫 자식으로 prepend**.
3. 견적 탭이 꺼져 있으면 여기서 `false` → 주문 조회가 평소대로 그려진다.
4. 켜져 있으면 머리글을 고쳐 쓰고 견적 화면을 그린 뒤 `true`.
   - PC — `.pc-head .path` 글을 `주문 관리 › 견적 요청`(수정 중이면 `… › 수정`)으로. `.headbtns`(카페24 변환·출고리스트·동봉카드)는 `hidden` — 견적 화면에서 쓸 수 없는 버튼이다.
   - 폰 — `.ph-top h1` 을 `견적 요청`/`새 견적 요청`/`고객명`으로. 요약줄(`.ph-sub`)이 없으면 만들어 `본문` 앞에 끼운다.
   - `ZG.견적PC.그리기(본문)` 또는 `ZG.견적폰.그리기(본문)`.

**탭 상태는 `15d`가 메모리로만 갖는다**(`켜짐` · 폰 안쪽 뷰 `목록|등록|상세`). 저장하지 않는다 — 새로고침하면 주문 조회로 돌아온다. 조회 일자를 저장하지 않는 것(2단계 §2-4)과 같은 이유다.
탭을 바꿀 때는 `ZG.주문.다시그리기()`를 부른다. 그리는 길은 하나뿐이다.
**폰 뒤로가기** — 견적 안쪽 화면(등록·상세)에서는 `.ph-sub` 왼쪽의 `‹ 견적 요청` 버튼으로 목록에 돌아온다. `history.pushState`는 쓰지 않는다(주문 상세의 popstate 처리와 엉킨다).

## 4. PC 화면 (`15b-견적PC.js`)

위에서 아래로 **① 등록/수정 카드 → ② 통계 4칸 → ③ 표 카드**. 시안 그대로다.

**① 카드** — `.fgrid`(요청일자 170 / 고객명 250 / 연락처 250 / 남는 폭) + 내용 `textarea rows=3`이 아래 한 줄 전체.
- 평소: 제목 `새 견적 요청 등록`, 버튼 `초기화` · `＋ 등록`.
- 「수정」을 누르면 **같은 카드가 그 건으로 바뀐다.** 제목 `견적 요청 수정 <hint>YYYY-MM-DD 접수 · 마지막 수정 …</hint>`, 오른쪽에 지금 상태 칩, 버튼 `취소` · `💾 수정 저장`. **`prompt()`를 쓰지 않는다**(기존 구현의 4연타 방식을 여기서 버린다 — 시안 확정).
- 수정 중인 줄은 표에서 `tr.editing`(초록 배경) + 상태칸이 드롭다운 대신 `수정 중` 칩.
- 저장·취소하면 카드는 등록 모드로 돌아가고 표를 다시 그린다. 저장한 줄은 `ZG.ui.번쩍`.

**② 통계** — `전체 요청` / `요청 중` / `완료` / `취소`. **필터를 걸어도 전체 기준**이다(시안: 필터 「요청」인데 전체 6).

**③ 표** — 요청일자 104 / 고객명 132 / 연락처 132 / 요청 내용(남는 폭) / 상태 118 / 버튼 132.
- 요청 내용은 `td.memo { white-space:pre-wrap }` — **줄바꿈을 그대로 보여준다.** 자르지 않는다.
- 상태칸은 드롭다운. **바꾸는 즉시 저장한다. 저장 버튼이 없다**(기존 동작). 저장 후 `수정일시` 갱신 + 토스트 `상태를 「완료」로 바꿨습니다`.
- `수정`(카드로 올림) · `삭제`(`ZG.ui.확인` — 되돌릴 수 없다고 적는다).
- 0건이면 `.empty` 한 줄(`아직 접수한 견적 요청이 없습니다` / 검색 중이면 `찾는 견적 요청이 없습니다`).

## 5. 폰 화면 (`15c-견적폰.js`)

**밭에서 전화를 받으며 적는 화면이다.** 내용 글씨가 제일 크다.

**목록** — 요약줄 `전체 N건` / `요청 중 N건`. 검색칸 + 상태 드롭다운(`.sbar`), 카드 목록, 맨 아래 `＋ 새 견적 요청`(`.addbtn`).
카드(`.ph-card.qcard`) = ①줄 `고객명` + 상태칩 + `MM-DD` ②`내용`(`pre-wrap`, 자르지 않는다) ③바닥 `연락처` + `📞 전화`.
- `📞 전화`는 `연락처`에서 숫자만 뽑아 **8자리 이상일 때만** 보인다. `<a href="tel:...">`. 카드 본체 탭과 겹치지 않게 `stopPropagation`.
- 카드를 누르면 상세.

**새 견적 요청** — 요청일자(오늘) · 고객명 · 연락처 · 요청 내용(`rows=5`) · `등록` · 안내줄(`등록하면 상태는 「요청」으로 시작합니다`).

**상세** — 제목이 고객명, 요약줄 `요청일 YYYY-MM-DD` / `수정 MM-DD`.
- **상태 3칸 토글**(`.stpick` 요청/완료/취소) — 장갑 낀 손을 위해 드롭다운을 안 쓴다. **누르는 즉시 저장**한다(PC 드롭다운과 같은 규칙).
- 연락처 · 요청 내용(`rows=6`) · `저장` · `🗑 이 견적 요청 삭제`.
- **고객명·요청일자는 폰에서 안 고친다.** 시안 안내줄 그대로 PC로 넘긴다.
- 한글 칸(고객명·내용)은 전부 `ZG.ui.조합안전입력`을 거친다 — 8/4 「휴케라 → ㅎㅠㅋㅔㄹㅏ」 사고 방지.

## 6. 검색 · 필터 · 정렬 (`15a-견적자료.js`)

- **검색** — `고객명` · `내용` · `연락처` **부분일치**. 공백 지우고 소문자로 맞춰 비교(`이름키` 방식). 연락처는 **숫자만 남겨서도 한 번 더** 비교한다(`01098` 로도 찾히게).
- **상태 필터** — `전체 상태` / 요청 / 완료 / 취소.
- **`↺ 초기화`** — 검색어·상태를 함께 비운다.
- **정렬은 고정이다. 사용자가 못 바꾼다** — `요청일` 내림차순, 같으면 `등록일시` 내림차순. (시안 표 순서가 이것이다)
- **쪽나눔** — PC 20건/쪽, `.pager` 재사용(`08b`와 같은 수). 폰은 쪽나눔 없이 전부 내려 보여준다.
- 검색·필터가 바뀌면 쪽은 1로 돌아간다.

## 7. 값 규칙

- **필수** — 요청일·고객명·내용. 비면 저장하지 않고 그 칸을 `ZG.ui.흔들기` + 토스트(`고객명을 적어 주세요`).
- **연락처는 형식을 강제하지 않는다.** 실데이터에 이메일도 들어올 수 있다(PC 안내문 `010-0000-0000 / email`). 자동 하이픈 넣기도 하지 않는다.
- **내용은 `trim()`만.** 가운데 줄바꿈·빈 줄은 그대로 둔다.
- **상태는 셋뿐.** 저장된 값이 셋 밖이면 화면에서는 `요청`으로 그리되 **값을 몰래 고쳐 쓰지 않는다.**
- 상태 자동 전이는 **없다.** 다른 화면(주문·명세서·업체)과의 연결도 **없다.** 독립 메모다.
- 삭제는 진짜로 지운다(`저장소.지우기`). 상쇄 레코드를 만들지 않는다.

## 8. `css/주문.css`에 덧붙일 것

`select.inp`(화살표 배경) · `.inp.ta` · `.subtabs` · `.empty` · `.st`(wait/done/cancel) · `.fgrid` · `.formfoot` · `.sbar` · `td.memo` · `td.tel` · `td.day` · `tr.editing` · `.qcard` · `.stpick` · `.addbtn` · `.noteline`. 값은 **시안 `<style>` 블록 그대로**.

🔴 **`css/공통.css`·`css/업체.css`는 안 건드린다.** `.subtabs`·`.empty`·`select.inp`는 지금 업체·소싱이 각자 제 파일에 갖고 있다(3·4단계가 그렇게 했다). 배포 직전에 공통.css를 손대면 네 화면이 한꺼번에 걸린다 — **공통화는 별건으로 미룬다**(배포 컨펌 때 🟡로 여쭌다).

## 9. 실데이터에서 확인한 것 (백업 6건)

1. **고객명이 6건 중 4건이 그냥 「고객님」이다.** 이름으로는 못 가른다 → **연락처가 사실상 식별자다.** 그래서 검색에 연락처를 넣고, 목록 카드·표에 연락처를 항상 보여준다.
2. **내용에 빈 줄과 후행 공백이 들어 있다**(`잣나무 1m 200개 견적문의 \nA급 16,000원\n\n5천원 단가…`). `pre-wrap`이 아니면 이 건이 한 줄로 뭉개진다.
3. 상태가 이미 **한글**로 들어 있다(`요청` 5 · `취소` 1 · `완료` 0). 영문 코드 변환이 필요 없다.
4. `요청일`은 6건 모두 `YYYY-MM-DD`로 정상이다(주문에서 났던 미국식 날짜 문제 없음).
5. 6건 전부 2026-05-07~11 것이다. **석 달째 새 접수가 없다** — 기간 필터를 안 만드는 근거다(§11).

## 10. 시안과 어긋난 곳 — 이렇게 정리했다

| 시안 | 실제 | 왜 |
|---|---|---|
| 폰 뒤로가기 `‹ 주문`이 제목 **위**(`.ph-back`) | 요약줄 **왼쪽**(`.ph-sub .back`) | 주문 화면의 다른 뷰(상세·출고)가 전부 이 자리다. 한 화면 안에서 두 벌이 되면 안 된다 |
| 폰 상단 `🖥 PC화면으로` | **없다** | v3 어디에도 아직 없다. 4단계에서 이미 배포 컨펌 대기로 올린 항목이다 |
| 폰 목록에 `‹ 주문` 뒤로 | 견적 **목록**에는 안 넣는다 | 주문 조회로 가는 길은 바로 위 탭줄이다. 두 개면 헷갈린다 |
| PC 표 상태칸이 「취소」건만 칩 | **모든 줄이 드롭다운**, 수정 중인 줄만 칩 | 취소도 되돌릴 수 있어야 한다(기존 동작) |

## 11. 5단계에서 **만들지 않는 것**

품목·수량 칸 · 견적서 발행(명세서 탭이 한다) · 주문/업체와의 연결 · 상태 자동 전이 · 기간 필터 · 엑셀 내보내기 · 알림 · 정렬 바꾸기 · 견적 요청 인쇄.

## 12. 🔴 `?v=` 올리기 체크리스트

`js`·`css`를 하나라도 고쳤으면 **다섯 파일 전부** `?v=6` → `?v=7`.
`index.html` · `주문.html`(+새 `15a~15d` 네 줄) · `업체.html` · `소싱.html` · `이사.html`

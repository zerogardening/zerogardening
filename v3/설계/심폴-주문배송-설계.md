## 2. 수집 — Edge `simpol-collect`

### 2-1. 부름 규격

```
POST /functions/v1/simpol-collect   { 일수: 30, 시험: false }
→ { ok, 새것, 이미, 날짜오류, 짝없음:[{상품코드,상품명,줄수}], 묶음id, 받은주문, 미리보기:[…] }
```
`시험:true`면 **한 글자도 저장하지 않고** 무엇이 들어갈지만 돌려준다(order-collect와 같은 관례).

### 2-2. 심폴에서 읽어오는 순서

1. `POST www.simpol.co.kr/vender/loginproc.php` — `SIMPOL_ID`·`SIMPOL_PW`. 쿠키 보관
2. `POST vender/order_list.php  sdate&edate&deli_gbn=X&listnum=500` → HTML
   `name="chkordercode" value="…"`를 전부 뽑는다. **`deli_gbn=X`(배송요청) 말고는 안 본다**
3. 🔴 뽑힌 코드 수가 `listnum`과 같으면 **잘린 것이다** — `경고`에 적어 돌려주고 기간을 줄이라고 알린다
4. `POST vender/order_excel.php  ordercodes=…,` **100개씩 끊어서.** 🔴 끝에도 콤마
5. EUC-KR 디코딩 → CSV 파싱 → 31칸 머리글 → 27칸 변환

### 2-3. 🔴 변환 규칙은 옮겨 적는 것이지 새로 정하는 것이 아니다

`edge-심폴수집/index.ts` 머리에 **이 주석을 그대로 넣는다** (edge-주문수집 머리 주석과 같은 함정) —

```
🔴 아래 지도(27칸)·날짜글·상품코드글은 v3/js/08j-심폴.js 를 그대로 옮긴 것이다.
   여기서 새로 정하지 않는다. 바꿀 일이 생기면 08j 와 여기를 같이 고친다 —
   한쪽만 고치면 손업로드와 자동수집이 어긋난다.
🔴 줄만들기·중복키·묶음키·우편정규화·옵션입수는 도구/edge-주문수집/index.ts 를 그대로 옮긴 것이다.
   같은 규칙이다. 한쪽만 고치면 카페24 주문과 심폴 주문이 서로 다른 잣대로 저장된다.
```

- 지도(27칸 ← 심폴 칸)·`날짜글`·`상품코드글`(앞 0 18자리) — **08j에서 그대로.**
  🔴 `상품코드`가 `="005017…"` 꼴로 오면 **엑셀 수식 껍데기 `="`·`"`를 벗긴다**(실측 §2)
- `판매처: '심폴'` · `출처: '심폴수집'` · `카페24상태: ''`(08b가 심폴은 출고 기록으로 판정한다 — 건드리지 않는다)
- `원본`(27칸)을 줄에 같이 저장한다 — **08i-로젠파일.js가 이게 없으면 파일을 못 만든다**
- 중복키 = `주문번호|원본코드|수령인` — 손으로 올리신 심폴 건(08h)과 **같은 키가 나와 두 번 안 들어간다**

### 2-4. CSV 파싱

🔴 **`split(',')` 금지.** 주소·전달사항에 콤마·따옴표·줄바꿈이 들어온다. 따옴표를 아는
파서 한 개(~25줄)를 함수 안에 둔다. 머리글 찾기는 08j의 `심폴키`와 같게 — **공백을 지우고
`(` 뒤를 떼고** 비교한다(`전화번호(XX-XXXX-XXXX)` → `전화번호`).

### 2-5. 묶음(회차)

- 하루에 심폴 묶음 하나. **id = `{YYMMDD}-S1`** — 카페24의 `-01`·`-02`와 **id가 절대 안 겹친다**
- `회차` = 그날 묶음 수 + 1 (만들 때 한 번). `출처:'심폴수집'`, `파일명:''`
- 08·12·15시에 같은 묶음에 이어붙인다(order-collect와 같은 규칙)

## 3. 🔴 짝을 못 지은 심폴 상품 — 「보류」

심폴 상품코드는 v3 품목코드가 아니다. 짝표(`v3_심폴짝`)에 없으면 **어느 품목인지 모른다.**

| | |
|---|---|
| 붙이는 법 | `v3_심폴짝`을 Edge가 직접 읽어 `상품코드 → 붙인품목코드 → v3_품목` **열쇠로만** |
| 못 붙었을 때 | `품목코드: ''` · `유통명: 심폴 상품명` · `원본코드: 심폴 상품코드`로 **그대로 저장한다** |
| 🔴 이름 매칭 | **안 한다.** 유통명이 같은 품목 9개·포함 쌍 7쌍이다(8단계 §0). 엉뚱한 상품이 손님에게 나간다 |

**「보류」는 새 칸이 아니라 「품목코드가 빈 상태」 그 자체다.** 이미 있는 대기열이 곧 보류함이다 —
`08b.짝못붙은수()`가 `!품목코드 && 원본코드`인 줄을 세고, `08b.짝짓기창()`이 `08k-심폴짝창`을 띄운다.
**자동수집 심폴 줄이 그 대기열에 자동으로 들어간다. 새 화면을 만들 필요가 없다.**

그래서 builder가 할 일은 셋뿐이다 —
1. `simpol-collect` 응답에 **`짝없음: [{상품코드, 상품명, 줄수}]`**를 담아 돌려준다
2. `08b.주문수집하기()`가 그 수를 토스트에 적는다 — 「🔗 짝 없는 심폴 상품 N종 — 짝짓기에서 지정해 주세요」
3. 짝 없는 줄도 **로젠 파일·포장까지는 그대로 간다**(E열에 심폴 상품명이 찍혀 무엇을 보낼지는 안다).
   막히는 것은 **재고 차감뿐이고 그건 이미 막혀 있다** — `08f`가 품목코드 없는 줄을 「확인 필요」로 뺀다.
   **여기에 새 분기를 넣지 않는다.**

## 4. 🔴🔴 발송처리 — 중복발송 막기가 이 기능의 전부다

심폴은 발송처리하는 순간 **손님에게 문자·이메일이 자동으로 나가고 되돌릴 수 없다**(실측 §3).
우람님 확정으로 미리보기·1건 시험이 없다. 그래서 **막는 층을 셋 둔다.**

### 4-1. 세 겹

| 층 | 어디서 | 무엇을 보나 | 걸리면 |
|---|---|---|---|
| **L1 우리 기록** | 브라우저 `08l.대상뽑기` | 주문줄 `심폴상태 === '배송완료'` | 체크 꺼짐 · 「이미 심폴에 발송처리됨」 |
| **L2 심폴 목록** | Edge, 보내기 직전 | `order_list.php deli_gbn=X`에 그 거래번호가 **있나** | 없으면 안 보냄 · 「배송요청이 아님」 |
| **L3 심폴 송장칸** | Edge, 보내기 직전 | CSV **`상품별 송장번호`가 비었나** · `상품별 처리여부 === '배송요청'` | 차 있으면 안 보냄 · 「이미 송장 있음」 |

🔴 **진실은 심폴이다. L2·L3가 최종 판정이고 L1은 화면을 위한 것이다.**
우리 저장이 실패하거나 함수가 중간에 죽어도, 다시 돌리면 L3가 「이미 송장 있음」으로 걸러낸다.

🔴 **L2·L3는 「보내기 직전」에 한다** — 화면에 미리 받아 둔 판정을 믿고 쏘지 않는다.
50건씩 끊어 보내며 **묶음마다** ①order_excel 조회 → ②거르기 → ③`deliinfoup2` 순으로 돈다.
(`order_list`는 한 번만. 송장칸이 걸린 묶음은 그 묶음만 빠지고 나머지는 계속 간다.)

🔴 **한 거래번호에 상품이 여럿이면 「하나라도 송장이 차 있으면 통째로 안 보낸다.」**
`deliinfoup2`는 거래번호 단위로 먹기 때문에 부분발송을 표현할 방법이 없다. 안 보내고
「사람이 확인」으로 돌려주는 쪽이 두 번 보내는 것보다 낫다.

### 4-2. Edge `simpol-ship` 부름 규격

```
POST /functions/v1/simpol-ship
  { 짝들:[{주문번호, 운송장번호}], 모드: "조회" }      ← 기본값. 아무것도 안 나간다
  { 짝들:[…],                     모드: "발송" }      ← 이것만 실제로 쏜다
→ { ok, 모드, 보낸수, 막힌수, 결과:[{주문번호, 됨, 판정, 사유, 심폴송장}] }
```
- 🔴 열쇠 이름이 **`모드`**다. 카페24 쪽의 `진짜:true`와 **일부러 다르게 지었다** —
  카페24 시험 몸통을 복사해 붙여도 심폴은 **조회만 하고 끝난다.**
- 택배사 `delicoms`는 **로젠 = `9`** 고정(실측 §3). `delinums`는 숫자만 남긴다.
- `ordercodes`·`delicoms`·`delinums` 셋 다 **끝에 콤마를 붙인다.**

### 4-3. 🔴 드라이런과 실발송을 코드로 가른다 (builder가 섞을 수 없게)

1. **파일이 다르다.** `edge-심폴수집`에는 `deliinfoup2`라는 글자가 **없다.** 수집이 실수로 쏠 길이 없다
2. `edge-심폴발송` 안에서 `deliinfoup2` 문자열은 **상수 선언 한 줄 + 쓰는 곳 한 줄, 딱 두 번만** 나온다
   ```ts
   const 발송모드 = "deliinfoup2";   // 🔴 이 상수를 쓰는 함수는 발송쏘기() 하나다
   ```
   검수는 `grep -c deliinfoup2 도구/edge-심폴발송/index.ts` 가 **2인지** 센다. 3이면 반려다
3. `발송쏘기(묶음, 모드)`는 **첫 줄이 `if (모드 !== "발송") throw new Error("발송 모드가 아니다")`**
4. 🔴 **시험 스크립트·curl·주석 예시에 `모드:"발송"`을 쓰지 않는다.** 실사용 날 우람님 화면에서
   처음으로 나간다. builder가 `모드:"조회"`로만 확인한다

### 4-4. 화면 흐름 (9단계 §4 A→B→C 그대로)

- `08l.대상뽑기` — 지금의 `심폴수++; return;`(08l:32)을 갈라 **`심폴짝들`**을 만든다.
  같은 거래번호 둘째 줄은 꺼 둔다(카페24 규칙과 같다). 주문번호·운송장 없으면 제외.
  🔴 **한 로젠 줄에 심폴 줄과 카페24 줄이 섞여 있으면 어느 쪽에도 안 넣고 `섞임수`로 세어 보여준다**
  (지금도 그 건은 통째로 빠져 있다 — 회귀 아니다. 이름만 붙인다)
- `08m` — 「☁ 카페24 발송처리」 상자 아래에 **「🌿 심폴 발송처리」 표**를 같은 모양으로 하나 더.
  단계 A(미리보기)는 **카페24만** 태운다. 심폴은 미리보기가 없다 —
  대신 표에 **L1으로 걸러진 줄**을 회색으로 보여 주고 체크는 꺼 둔다
- **확인창 문구** — 「카페24 N건 · **심폴 M건**을 발송처리 할까요 /
  🔴 **심폴은 손님에게 문자·이메일이 자동으로 나갑니다. 되돌릴 수 없습니다**」. `위험:true`
- `진짜올리기` — **카페24 먼저, 끝나면 심폴.** 한쪽이 실패해도 다른 쪽 결과는 그대로 남긴다
- 되쓰기 — `08l.심폴되쓰기(심폴짝들, 됨번호)`가 성공한 거래번호의 주문줄에
  `{심폴상태:'배송완료', 심폴송장:번호, 심폴발송시각:ISO}`를 **줄 하나 = 행 하나**로 쓴다
  (`08l.상태되쓰기`와 같은 모양. 묶음 통째 쓰기 금지 — 1단계 §10 저장소 규약)

## 6. 배포 순서 (이 순서를 지킨다)

1. 우람님이 `SIMPOL_ID`·`SIMPOL_PW`를 Supabase 시크릿에 넣으신다
2. `simpol-collect` 배포 → `{일수:30, 시험:true}`로 부른다. **저장 0건 · 받은 주문 수만 확인**
3. `{시험:false}` 한 번 — v3 주문목록에 심폴 주문이 뜨는지, 짝 없는 상품 수가 맞는지 눈으로
4. 크론 3개 추가 — 08·12·15시 KST **+2분**(= UTC 23:02·03:02·06:02). 카페24와 동시에 안 돌게 띄운다
5. `simpol-ship` 배포 → **`모드:"조회"`로만** 부른다. 판정이 맞는지 본다
6. JS 5파일 + `?v` → 커밋. **push는 우람님 컨펌 뒤**
7. 🔴 **첫 실발송은 우람님이 실제로 택배를 보내시는 날, 화면에서.** 그 전에 `모드:"발송"` 금지

🔴 **함수 슬러그에 한글을 쓰지 않는다**(`simpol-collect`·`simpol-ship`). 한글이면 수정·삭제가 막힌다.
🔴 **함수 본문을 JSON `body`로 올리면 앞 4바이트가 잘려 `BOOT_ERROR`다.** multipart
`POST /v1/projects/{ref}/functions/deploy?slug=…`로 올린다. (현재상태.md 8/8 밤 절)

## 7. 지뢰 목록 — builder가 반드시 확인할 것

1. 🔴 `www.simpol.co.kr` — `www`를 빼면 301로 튄다
2. 🔴 응답이 **EUC-KR**이다. `new TextDecoder('euc-kr').decode(await res.arrayBuffer())`.
   `res.text()`를 쓰면 한글이 통째로 깨진다. 보내는 값은 전부 ASCII라 인코딩 걱정이 없다
3. 🔴 쿠키는 **`res.headers.getSetCookie()`**로 읽는다. `get('set-cookie')`는 여러 줄을
   콤마로 이어붙여 돌려줘 파싱이 깨진다. `redirect:'manual'`로 받는다
4. 🔴 로그인 성공 판정 — 본문에 `main.php`가 있나로 본다. 실패해도 200이 온다.
   **실패했는데 그대로 진행하면 order_list가 로그인 화면 HTML을 주고, 거래번호 0개가 나와
   「보낼 것이 없다」로 조용히 끝난다.** 로그인 실패는 반드시 던진다
5. 🔴 상품코드 `="005017000000081207"` — 수식 껍데기를 벗기고 앞 0을 살린다(18자리)
6. 🔴 `일자` `20260916`을 그대로 넘기면 `08a.날짜정규화`가 ms로 읽어 **1970년**이 된다.
   `날짜글()`로 `2026-09-16`까지 펴서 넘긴다(8단계 §3)
7. 🔴 「옵션(특징포함)」은 상품 설명문이다 — **옵션 칸은 언제나 빈 문자열.** 넣으면 옵션입수가 터진다
8. 🔴 「주문ID/주문번호」(`9224036@`)는 **주문자 아이디다.** 주문번호는 **`거래번호`**다
9. 🔴 심폴 값에 꼬리 공백이 붙어 온다(`28181 `). `trim()` 안 하면 로젠 파일에 그대로 실린다
10. 🔴 `order_excel.php`의 `ordercodes`는 **끝에도 콤마.** `deliinfoup2`의 세 목록도 마찬가지
11. 🔴 손으로 올리신 심폴 건과 겹치지 않는지 — 중복키 세 조각(`주문번호|원본코드|수령인`)이
    08j 변환 결과와 **글자까지 같아야** 한다. 한쪽만 `trim`하면 한 주문이 두 줄이 된다
12. 🔴 `v3_주문`을 읽을 때 **1,000줄에서 잘린다.** `edge-주문수집`의 `전부읽기()`를 그대로 쓴다.
    잘린 것을 「처음 보는 주문」으로 착각하면 누를 때마다 한 벌씩 쌓인다(8/11 사고)

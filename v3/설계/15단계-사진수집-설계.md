# 15단계 — 상품 사진 수집 · 원고 편집

> **2026-09-12 우람님과 정한 것.** 조사·시안까지 끝났다. **새 창은 이 문서만 읽고 A부터 시작하면 된다.**
> 지시 원문은 `지시로그/우람님.md` 9/12 줄.

## 왜 만드나

상세페이지 제작은 **사진 7장이 모이기 전에는 시작조차 못 한다.** `상품/_도구/사진확인.sh` 가 문지기고, 지금 `상품/제작대기.md` 에 걸린 **11건이 전부 「사진 대기」**다.

지금 우람님이 하시는 일:
```
폰 촬영 → 에어드롭으로 맥에 옮김 → esmplus 에 손으로 올림
        → 재고 탭에서 「상세페이지」 → 맥에서 제작요청.py → 「제작대기 처리해줘」
```

## 🔴 조사로 알아낸 것 둘 — 이게 설계의 근거다

**① esmplus 원료 업로드가 원래 필요 없다.** 템플릿 기본값은 esmplus URL 이지만 **실제 산출물은 로컬 `file://` 을 쓴다** — `상품/품목/구절초-노랑/발행이미지/제작.html:233` 이 `file:///Users/zerogardening/이미지/구절초-노랑/2.png` 다. `상품/_도구/검수.py:86-95` 가 이를 정식으로 인정한다.
→ **사진이 `~/이미지/{식물}/` 에만 있으면 지금 제작이 그대로 돈다.**

**② 폰 사진 업로드가 이미 돌아간다.** `v3/js/17a-메모자료.js:187-255` — EXIF 회전 교정(`imageOrientation:'from-image'`) · 1600px·q85 축소 · Supabase Storage 직업로드. **버킷 이름만 바꾸면 된다.**

## 세 단계 — 각각 완결되고 각각 push 한다

| | 무엇 | 끝나면 | 시간 |
|---|---|---|---|
| **A** | 📷 사진 탭 + 맥 스크립트(사진 받기) | **esmplus 업로드가 사라진다** | 2~3시간 |
| **B** | [원고]·[결과] 탭 + 원고 반영 | **폰에서 글을 고친다** | 2~3시간 |
| **C** | 원고를 git 에 올리고 서버에서 재렌더 | **맥이 꺼져 있어도 반영된다** | 반나절 |

🔴 **단계마다 새 창에서 한다.** A 끝나면 `/clear` → B. 한 창에서 다 하면 호출마다 앞 대화가 통째로 다시 실린다.
🔴 **한 단계가 끝나면 우람님이 며칠 써 보신 뒤** 다음을 정한다. A 를 써 보면 B 가 어떻게 생겨야 할지가 분명해진다.

## 실서비스 주의 (개발지침 §2~4)

- 저장소는 `제로가드닝/통합관리/` 다. 프로젝트 창은 저장소가 아니다

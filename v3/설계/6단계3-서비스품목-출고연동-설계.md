# v3 6단계-3 설계 — 서비스 품목이 **진짜로 재고를 깎게** 한다

우람님 재지시(8/6) — 「서비스로 나간 것도 재고가 실제로 줄어야 한다」.
**공통 규약(CSS 변수·애니메이션·접근성·저장소 규약·품목코드 규칙)은 1단계 설계 §10 · §3 · §6 그대로.**
**서비스 품목줄의 모양은 6단계 설계 §2-1 그대로.** 여기서는 **출고 연동만** 적는다.

`6단계-주문수정+서비스품목-설계.md`는 이미 구현·검수가 끝나 검수서와 짝이 맞는 문서다. 고치지 않고 **이 파일을 잇는다.**

---

## 0. 지금 왜 안 줄어드나 — 사실 확인 넷

1. `03-계산.js 현재고()`는 **`zg.v3.출고`만** 읽는다. 주문줄은 쳐다보지 않는다(6단계 설계 §4에 그대로 적혀 있다).
2. `08e-서비스품목.js 넣어주기()`(23~32행)는 `zg.v3.주문`에만 `덧붙이기` 한다. **`zg.v3.출고`에는 한 줄도 안 쓴다.** ← 이것이 원인 전부다.
3. **`출처` 칸은 이미 있다.** 출고줄 = `{ id, 출고일, 품목코드, 수량, 출처, 등록일시 }` — `00-시드.js` 119~127행이 `출처:'시드'`, `99-이사.js` 224~231행이 `출처:'주문'`을 쓴다. **새 필드 이름을 만들 필요가 없다. `출처:'서비스'` 하나를 더할 뿐이다.**
4. **연결키 이름도 이미 정해져 있다.** 2단계 설계 §2-3이 배송완료 변환용 출고줄을 `{ …, 출처:"주문", 주문id }`로 확정해 놨다. **`주문id`를 그대로 쓴다.** 새 이름을 짓지 않는다.

`현재고()`가 보는 것은 `등록일시`(조정 기준선 비교)와 `수량`뿐이고, `월출고량()`만 `출고일`을 본다.

## 1. 서비스 출고줄 — 필드

| 필드 | 값 | 비고 |
|---|---|---|
| `id` | `'sh_' + Date.now().toString(36) + '_' + 랜덤5` | 08a `새id()`와 같은 꼴, 앞자만 `sh` |
| `출고일` | **그 주문줄의 `주문일`**. 비었으면 오늘 | 서비스는 그 주문과 같은 날 함께 나간다 |
| `품목코드` | 서비스 줄의 `품목코드` | |
| `수량` | **`주문수량 × 옵션입수`** (08a `수량(줄)` 그대로 부른다) | 서비스 줄은 `옵션입수:1`이라 사실상 주문수량 |
| `출처` | **`'서비스'`** | 기존 값은 `'시드'`·`'주문'` — 안 부딪힌다 |
| `주문id` | **그 서비스 주문줄의 `id`** | 🔴 되돌리기·중복방지가 전부 이 칸에 걸려 있다 |
| `등록일시` | `Date.now()` | 재고조정 기준선보다 뒤라야 차감된다(`현재고()` 41~42행) |

**출고일에 오늘이 아니라 주문일을 쓰는 이유** — 재고 차감(=`현재고()`)은 `등록일시`로 판정하므로 영향이 없고, `월출고량()`만 이 값을 본다. 지난 주문에 뒤늦게 서비스를 넣어도 그 달 출고로 잡히는 편이 장부와 맞는다.

### 1-1. 🔴 출고줄은 주문줄 하나당 **최대 한 개**다

`주문id`가 사실상의 유일키다. 만들기 전에 언제나 「이 `주문id`로 이미 있나」를 본다.
서비스 줄 하나 = 출고줄 하나. 건 단위로 묶어 한 줄로 만들지 **않는다** — 되돌릴 때 어느 품목이었는지 못 찾는다.

## 2. 언제 만들고 언제 지우나 — 함수 하나로 모은다

`08e-서비스품목.js` 안에 둔다. `03-계산.js`는 **읽기 전용 계산 모듈이라 쓰기를 넣지 않는다.**
`08a-주문자료.js`·`02-품목코드.js`·`04-공통UI.js`는 8/5 확정대로 **이번에도 안 건드린다.**

```
ZG.서비스품목.출고맞추기(주문줄)   // 만들기 · 수량 고치기 · 0이면 지우기를 한 함수가 다 한다
ZG.서비스품목.출고지우기(주문id)
```

**`출고맞추기(줄)` 규칙**

1. `줄.서비스 !== true` → 아무것도 안 한다(즉시 return). 보통 주문줄은 배송완료 변환 몫이다.
2. `zg.v3.출고`에서 `r.주문id === 줄.id` 인 줄을 찾는다.
3. 목표수량 `= 주문수량 × 옵션입수`.
4. 목표수량 ≤ 0 이거나 `줄.품목코드`가 비었으면 → 있으면 `저장소.지우기(키.출고, 그id)`, 없으면 아무것도 안 함.
5. 있으면 → `저장소.바꾸기(키.출고, 그id, { 품목코드, 수량, 출고일 })`. **`id`·`주문id`·`등록일시`는 안 덮는다**(`바꾸기`가 `Object.assign`이라 표에 없는 칸은 남는다).
6. 없으면 → `저장소.덧붙이기(키.출고, §1 모양의 새 줄)`.

`출고지우기(주문id)` — 그 `주문id`를 가진 출고줄을 **전부** 찾아 `저장소.지우기`. (1-1 규칙상 0개 아니면 1개다.)

### 2-1. 지울까 「취소됨」으로 표시할까 — **지운다**

| 따져 본 것 | 결론 |
|---|---|
| `현재고()`·`월출고량()`은 출고줄을 **거르개 없이 전부 합산**한다 | 「취소됨」을 쓰면 `03-계산.js` 두 함수에 필터를 넣어야 한다. **모든 재고 화면이 걸린 공용 파일**이라 손대는 값이 크다 |
| 1단계 설계 §16-1 / `01-저장소.js` 66~67행 | 「원본 레코드를 실제로 지운다. 상쇄 레코드를 따로 만들지 않는다」 — v3가 이미 정한 방식이다 |
| 업무규칙 §8 「매입·주문 기록은 지우지 않는다」 | **출고는 매입도 주문도 아니다.** 세금계산 근거가 되는 원본은 `입고`(매입)와 `주문`(판매)이고, `출고`는 재고를 세려고 v3가 파생시킨 이동기록이다. 그래서 지워도 근거가 사라지지 않는다 — **없어지는 원본 기록은 없다**(서비스 주문줄은 §3대로 남거나 사용자가 명시적으로 뺀 것뿐) |

→ **출고줄은 실제로 지운다.** `03-계산.js`는 **한 글자도 안 고친다.**

## 3. 되돌리기(취소) — 어디에 붙나

8/5 구현에 **서비스 줄만 따로 빼는 경로는 없다.** 지금은 업로드 건의 모든 줄이 `옵션.뺄수없음`으로 ✕가 막혀 있다(`08c` 183행). 그래서 두 가지를 연다.

### 3-1. 서비스 줄은 ✕로 뺄 수 있게 한다

`08c 카드하나()` 183행 조건을 `if (옵션.뺄수없음 && st.id && !st.서비스)`로 한 글자 늘린다.
**업무규칙 §8과 안 부딪힌다** — 고객이 주문한 줄이 아니라 우리가 방금 얹은 사은품 줄이다. 손님 주문 원본줄은 지금대로 계속 막힌다.

### 3-2. 취소되는 세 가지 길 — 전부 §2의 두 함수를 부른다

| 어디 (`08c-주문입력.js`) | 무슨 일 | 붙이는 것 |
|---|---|---|
| `고쳐넣기()` 374~391행 · `st.id` 갈래 | 서비스 줄의 **수량을 고쳤다**(0 포함) | `저.바꾸기(…)` 반환값에 대해 `if (대상 && 대상.서비스) ZG.서비스품목.출고맞추기(대상)` |
| `고쳐넣기()` 399~409행 · 업로드 갈래 | 서비스 줄을 **✕로 뺐다** | `묶음.모두()`에도 없는 id가 `옛줄[id].서비스`면 → `저.지우기(주문,id)` + `출고지우기(id)` 하고 `return`. **`읽기()` 거르개에서만 빠진 줄(품목명을 지운 경우)은 지우지 않는다** — `모두()`에 있는지로 가른다 |
| `고쳐넣기()` 393~394행 · 수동 갈래 / `수동삭제()` 422행 | 줄을 진짜 지운다 | 각 `저.지우기` 뒤에 `출고지우기(id)`. 서비스가 아닌 줄엔 아무 일도 안 일어난다(찾는 게 없다) |
| 🔴 `고쳐넣기()` 업로드 갈래 **끝줄**(`사람것` 저장) | 서비스 줄의 **품목명을 지운 채 수량만 고쳤다** — 카드가 `읽기()` 거르개에서 빠져 `st.id` 갈래로 못 가고 여기로 온다 | `저.바꾸기(…)` 반환값에 대해 **위 첫 줄과 똑같이** `if (바뀐 && 바뀐.서비스 && ZG.서비스품목) ZG.서비스품목.출고맞추기(바뀐)`. 빠뜨리면 주문수량만 바뀌고 **출고줄이 옛 수량으로 남아 재고가 어긋난다** (8/6 검수 🟡) |

**정리 — 서비스 줄이 저장되는 길은 셋이고, 셋 다 `출고맞추기`/`출고지우기`가 붙어 있어야 한다.**
`고쳐넣기()` 안에 `저.바꾸기(저.키.주문, …)` 또는 `저.지우기(저.키.주문, …)`를 새로 쓰는 사람은 **그 자리마다** 서비스 처리를 함께 넣는다.

호출은 언제나 `ZG.서비스품목 && ZG.서비스품목.출고맞추기(...)`로 감싼다 — `08e`를 안 싣는 페이지가 생겨도 안 터지게.

## 4. 🔴 미래 약속 — 「주문 → 출고 넘기기(배송완료 변환)」를 만들 사람이 반드시 지킨다

2단계 설계 §2-3의 자리가 아직 비어 있다(`08d 배송완료()`는 토스트뿐). **그 기능을 만드는 날 이 절을 먼저 읽는다.**

> ### 출고를 만들기 **전에** 주문줄마다 두 가지를 확인한다. 하나라도 걸리면 **그 줄은 건너뛴다.**
>
> **① `줄.서비스 === true` 이면 건너뛴다.**
> 그 줄의 출고는 서비스 품목을 넣은 그 순간 이미 만들어져 있다 —
> `zg.v3.출고` 에 `출처 === '서비스'` 이고 `주문id === 줄.id` 인 줄이다.
> 또 만들면 **재고가 두 번 깎인다.**
>
> **② `zg.v3.출고`에 `r.주문id === 줄.id` 인 줄이 이미 있으면 건너뛴다 (`출처` 값과 무관하게).**
> 변환을 두 번 돌리는 사고까지 이 한 줄이 막는다.
>
> ### 새로 만드는 출고줄에는 **반드시 `주문id: 줄.id` 를 넣는다.**
> 안 넣으면 다음 사람이 ②로 중복을 못 막는다. 2단계 설계 §2-3의 모양 그대로다.

**이사 데이터에도 같은 방패를 미리 박는다** — `99-이사.js` 224~231행이 만드는 출고줄(구 주문 1,287건분)에는 지금 `주문id`가 없다. 나중에 배송완료 변환이 이 주문들 위를 지나가면 ②가 안 먹혀 **전량 이중차감**된다.
→ 그 객체에 한 줄을 더한다. `주문id: o.id || 아이디('od', i)` — 265행이 주문줄 `id`를 만드는 식과 **똑같고**, `아이디(앞,i)`가 `앞+'_이사_'+i.toString(36)`로 결정적이라 값이 정확히 일치한다(같은 `주문원` 배열의 같은 `i`).

## 5. 품목코드가 없는 서비스 줄 — 조용히 넘어가지 않는다

지금 `08e` 44~46행은 `묶음.읽기()`가 비었을 때만 막는다. 카드 세 장 중 한 장만 품목이 안 잡히면 **말없이 두 장만 들어간다.** 그 한 장은 출고도 못 만든다.

`창()`의 「넣기」 누름에서 `넣어주기()`를 부르기 **전에** 검사한다. **하나라도 걸리면 아무것도 넣지 않는다**(부분 저장 금지).

| 검사 | 안내 (`u.흔들기(묶음.요소)` + `u.토스트`) |
|---|---|
| `묶음.모두().length !== 묶음.읽기().length` | 아래 사유별 문구 중 첫 번째 것 하나를 띄운다 |
| `!st.접두` | `품목이 안 정해진 카드가 있습니다. 목록에서 골라 주세요 — 직접 쓴 이름에는 품목코드가 안 붙습니다.` |
| `st.cm <= 0` | `화분 사이즈를 정해 주세요.` |
| `st.수량 <= 0` | `수량을 1 이상으로 넣어 주세요.` |
| `접두+'-'+cm` 이 `zg.v3.품목`에 **없다** | `품목마스터에 없는 규격입니다 (SAC01-27). 재고에서 뺄 수 없으니 상품관리에 먼저 등록해 주세요.` |

빈 카드를 한 장 띄워 둔 채 넣으려 해도 걸린다 — **그게 맞다.** ✕로 빼거나 채우게 안내한다.
마지막 검사가 제일 중요하다. 마스터에 없는 코드로 출고를 만들면 **재고 화면은 그 품목을 아예 안 그리므로 「깎였는지 아닌지」가 눈에 안 보인다.**
「타이핑 말고 목록선택」(CLAUDE.md 판단기준) 원칙이 여기서 그대로 걸린다.

**넣은 뒤 토스트를 바꾼다** — `3건에 서비스 2품목을 넣고 재고 6주를 뺐습니다.` (뺀 총수량을 `넣어주기()`가 세어 돌려준다.)

## 8. 우람님께 확인할 것

1. **서비스도 재고에서 바로 빠진다** — 이제 넣는 즉시 깎인다. 반대로 **일반 주문은 아직 안 깎인다**(배송완료 변환이 없어서). 한동안 「서비스만 먼저 빠지는」 상태가 되는데 괜찮으신지.
2. **취소는 서비스 줄에만 열었다** — 손님 주문줄 ✕는 그대로 막혀 있다(업무규칙 §8).
3. **출고 기록은 지운다** — 서비스를 빼면 그 출고줄이 사라진다(§2-1). 「취소됨」 이력을 남겨야 할 이유가 있으면 알려주시면 그때 만든다.

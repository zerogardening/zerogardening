- 9(결제업체)는 **비워 둔다** — `08i`가 박스운임으로 덮어쓴다. 25(옵션추가)도 `08i`가 `'0'`으로 채운다.

  카페24 파일의 H열에도 원래 `ANP01-15` 같은 값이 실려 로젠으로 나가고 있다 — **같은 종류의 값이다.**

## 3. 일자 — 여기가 첫 번째 지뢰다

심폴 일자는 `20260808` 8자리다. `raw:true`로 읽으면 **숫자 20260808**로 온다.
`08h.날짜만들기`의 숫자 갈래는 `20000~90000`(엑셀 serial)만 걸러 내고 나머지는 `08a.날짜정규화`로 넘긴다 →
**ms로 읽혀 1970-08-23이 된다.** 그대로 두면 조회 기간에서 통째로 사라진다.

```js
// 08j.날짜글(v) — 변환할 때 미리 편다. 08a·08h 는 안 고친다
function 날짜글(v) {
  if (v instanceof Date) return v;                                  // 08h.날짜만들기가 받는다
  var s = String(v == null ? '' : v).trim();
  var m = s.match(/^(\d{4})(\d{2})(\d{2})$/);            if (m) return m[1]+'-'+m[2]+'-'+m[3];
  m = s.match(/^(\d{4})[-.\/](\d{1,2})[-.\/](\d{1,2})/); if (m) return m[1]+'-'+두자(m[2])+'-'+두자(m[3]);
  return s;   // 못 알아보면 그대로 넘긴다 — 08h 가 「날짜오류」 갈래로 걸러 화면에 보여준다
}
```
못 읽은 줄은 지금 카페24와 똑같이 **저장 안 함 · 로젠 파일에는 들어감**이다(기존 `날짜상자()`).

## 4. 감지 — 어떻게 심폴 파일인 줄 아나

🔴 **카페24 머리읽기보다 먼저 판정한다.** 심폴 머리글에도 `전화번호`·`우편번호`·`주소`·`옵션`이
있어서 카페24 검사에 반쯤 걸린다 — 순서를 바꾸면 「카페24 파일이 아닌 것 같습니다」로 끝난다.

```js
// 08j.감지(머리행) → {자리:{심폴칸이름:index}} 또는 null.  머리키 = 공백 제거(08h와 같은 규칙)
var 심폴필수 = ['일자','받는사람','거래번호','상품코드','갯수','상품가격'];
// 여섯 개가 전부 있어야 심폴이다. 카페24 27칸에는 이 중 하나도 없다 — 오판이 불가능하다
```

```js
// 08h.읽기결과() 맨 앞 — 바뀌는 곳은 여기 8줄뿐이다
var 심 = ZG.심폴 && ZG.심폴.감지(행들[0]);
var 머리;
if (심) {
  var 바꾼 = ZG.심폴.바꾸기(행들, 심);          // {행들:[<빈 머리행>, ...27칸행], 자리:표준자리}
  행들 = 바꾼.행들;
  머리 = { 자리: 바꾼.자리, 없는칸: [], 모르는: [], 우편없음: false, 심폴: true };
} else {
  머리 = 머리읽기(행들[0]);
  if (머리.없는칸.length) return { ok:false, 오류:'카페24 · 심폴 주문 파일이 아닌 것 같습니다 — 못 찾은 칸: ' + … };
}
```
`바꾸기`가 돌려주는 배열의 **0번은 빈 행**이다 — `for (var i = 1; …)` 반복문을 안 고치려고 자리를 맞춰 둔다.
`자리`는 27칸 이름 → 0~26 항등표라 `원본27()`·`칸글()`이 지금 그대로 돈다.

그리고 `return { ok:true, … }` **바로 앞에 한 줄**:
```js
ZG.심폴.되붙이기(항목들);   // 심폴 줄만 골라 짝표대로 품목을 붙인다. 카페24 줄은 지나간다
```

## 5. 짝표 — 심폴 상품코드 ↔ v3 품목코드

심폴 상품코드(`005001000000267430`)는 상품마다 고유하고 안 바뀐다. **이것 하나만 열쇠로 쓴다.**

### 5-1. 어디에 두나 — **Supabase 새 표 하나 + localStorage** (표를 나눈다)

「짝 하나 = 행 하나」다. **객체 한 덩어리로 `v3_공유설정`에 넣지 않는다** —
우람님과 두용씨가 각자 짝을 지으면 나중에 저장한 쪽이 앞사람 짝을 통째로 덮는다.
행으로 나누면 서로 다른 상품코드는 **서로를 안 건드린다.** 7단계 설계 §1의 표 모양을 그대로 쓴다.

### 5-2. 레코드 한 줄

```jsonc
{ "id": "005001000000267430",      // 🔴 심폴 상품코드가 곧 PK 다
  "붙인품목코드": "ANP01-15",       // v3 품목코드
  "심폴상품명": "추명국 핑크터치 15cm 화분",
  "만든때": 1754640000000, "고친때": 1754640000000 }
```

🔴 **v3 품목코드 칸의 이름을 `품목코드`로 지으면 안 된다.**
`01-저장소.js`의 `아이디(r)` 가 `r.id || r.품목코드` 라서, 뒷날 누가 `id` 를 빠뜨리면
`바꾸기`·`지우기`가 **v3 품목코드를 열쇠로 잡아 엉뚱한 줄을 고친다.** 그래서 `붙인품목코드` 다.
이 이름 덕에 `표키` 표(01-저장소 50행)도 **안 건드린다** — 기본 `id` 로 맞아떨어진다.

저장키 `ZG.저장소.키.심폴짝 = 'zg.v3.심폴짝'` **한 줄만** 더한다.
**스키마버전은 올리지 않는다** — 올리면 목데이터를 다시 심어 검수 브라우저의 데이터가 날아간다.

### 5-3. Supabase — 🔴 **이 SQL을 우람님이 먼저 돌리신 뒤에 push 한다**

```sql
-- v3_심폴짝 (7단계 설계 §1·§2와 같은 모양. 대시보드 SQL Editor에 그대로)
create table if not exists public.v3_심폴짝 (
  id text primary key,
  내용 jsonb not null,
  삭제됨 boolean not null default false,
  수정시각 timestamptz not null default now(),
  수정자 uuid default auth.uid());
drop trigger if exists 손댐 on public.v3_심폴짝;
create trigger 손댐 before update on public.v3_심폴짝
  for each row execute function public.v3_손댐();
create index if not exists v3_심폴짝_시각 on public.v3_심폴짝 (수정시각);
alter publication supabase_realtime add table public.v3_심폴짝;

alter table public.v3_심폴짝 enable row level security;
revoke all on public.v3_심폴짝 from anon;
drop policy if exists "로그인한사람만" on public.v3_심폴짝;
create policy "로그인한사람만" on public.v3_심폴짝
  for all to authenticated using (true) with check (true);
```

`01b-서버.js` 의 `표들` 배열에 `'심폴짝'` 을 더하면 **첫 내려받기·Realtime 구독·관문②·
`99b` 서버올리기가 전부 자동으로 따라온다**(99b는 `ZG.서버.표들`을 돌린다). 그 밖에 고칠 곳이 없다.

🔴 **표가 없는 상태로 push 하면 sync 전체가 죽는다.** `표받기('심폴짝')` 가 404(`PGRST205`)로 던지면
`Promise.all` 이 통째로 거부되어 **다른 12개 표도 안 내려오고 보내기 큐도 안 깨어난다.**
그래서 배포 순서를 못 박고, 그와 별개로 **표별 방패 4줄**을 `01b.내려받기()` 에 넣는다 —
지금은 표 하나가 넘어지면 나머지 열둘까지 같이 넘어지므로 이건 원래 있던 결함을 닫는 것이다.

```js
// 01b-서버.js 내려받기() — 표받기(표).then(…) 뒤에 붙인다
.catch(function (e) {
  서버.경고.push(표 + ' 를 못 받았습니다 (' + (e.message || e) + ')');
})
```
로컬은 그대로 남고 노란 띠로 알려 준다. **덮어쓰기는 지금과 똑같이 표 단위로만 일어난다.**

## 6. 자동으로 붙이기 — 우람님은 아무것도 안 하신다

```js
// 08j.되붙이기(항목들) — 붙이기·떼기를 한 함수로. 짝을 지을 때도 풀 때도 이것만 부른다
(항목들 || []).forEach(function (것) {
  var r = 것.줄;
  if (r.판매처 !== '심폴') return;          // 🔴 카페24 줄은 손대지 않는다
  var p = 마스터[짝표()[r.원본코드]] || null;
  r.품목코드 = p ? p.품목코드 : '';
  r.유통명   = p ? p.유통명   : 것.상품명;   // 못 찾으면 심폴 상품명 그대로 (로젠 E열이 이걸 쓴다)
  r.학명 = p ? p.학명 : '';  r.규격 = p ? p.규격 : '';
});
```

- 🔴 **`묶음키`·`중복키`는 다시 계산하지 않는다.** 중복키는 `주문번호 | 원본코드 | 수령인` 이고
  원본코드는 짝을 짓든 말든 **언제나 심폴 상품코드**다. 같은 파일을 짝짓기 전후로 두 번 올려도
  「이미 있는 줄」로 똑같이 걸린다. (유통명으로 갈랐다면 짝을 지은 순간 같은 주문이 두 번 저장됐을 것이다.)
- 🔴 **이미 저장된 옛 심폴 주문에는 소급 적용하지 않는다.** 미리보기 메모리 안에서만 붙는다.
  옛 줄은 지금 카페24와 똑같이 **주문 화면에서 나중에 지정**하신다 — 이미 있는 길이다.
- 다 붙으면 미리보기에 「짝 못 지은 상품 0종」이라 **우람님은 그대로 저장만 누르신다.**

## 7. 못 찾은 것 — 기존 품목 고르기를 그대로 쓴다 (`08k-심폴짝창.js`)

`미리보기창()` 한 줄만 갈라진다.

```js
if (코드없음.length) 몸.push(코드없음상자(코드없음));
        ↓
if (상태.심폴) 몸.push(ZG.심폴짝창.상자(상태.항목들, { 바뀌면: 짝바뀜 }));
else if (코드없음.length) 몸.push(코드없음상자(코드없음));

function 짝바뀜() { ZG.심폴.되붙이기(상태.항목들); 그리기(); }
```

### 7-1. 상자 하나 · 두 칸

**줄이 아니라 「심폴 상품코드」로 묶는다.** 같은 상품이 다섯 줄이면 짝은 한 번만 지으신다.

| 칸 | 내용 |
|---|---|
| ⚠️ **짝 못 지은 상품 N종** (노랑) | 상품마다 한 블록 — `심폴 상품명` · `상품코드 005001…430` · `이 파일에 N줄` + **품목 고르기 카드** + 「짝 지어 저장」 |
| **이미 짝 지어 둔 것 N종** (있을 때만) | 표 4칸 — 심폴 상품명 · 상품코드 · 붙는 v3 품목 · 「짝 풀기」 |
| 맨 아래 `.allrow` | 「짝을 안 지어도 **저장은 됩니다** — 품목코드 없이 들어가고 주문 화면에서 나중에 지정하시면 됩니다」 |

「짝 풀기」가 있어야 **잘못 지은 짝을 되돌릴 수 있다.** 이게 없으면 틀린 짝이 영원히 다시 붙는다.

### 7-2. 품목 고르기 — `08c` 재사용 (새로 만들지 않는다)

```js
var 묶음 = ZG.주문입력.품목카드묶음(null, { 수량숨김: true, 한장만: true });
// … 요소를 블록에 붙인다. 이름 자동완성(ZG.ui.자동완성)·화분크기 드롭다운·품목코드+재고 표시가 전부 딸려 온다
var st = 묶음.읽기()[0];                     // 접두·cm 가 다 찬 카드만 넘어온다
var 코드 = st ? st.접두 + '-' + st.cm : '';
```
- `08c` 에 더하는 것은 **한 줄**뿐 — `if (옵션.한장만) 추가.style.display = 'none';` (＋품목 추가 감추기)
- `수량숨김:true` 는 이미 있는 옵션이다(09b 수동 카드가 쓴다). 수량·단가를 안 묻는다
- 🔴 **`마스터[코드]` 에 진짜 품목이 있을 때만 저장한다.** 없으면
  「v3에 `ANP01-27` 품목이 없습니다 — 규격을 확인해 주세요」 토스트만 띄우고 짝을 안 만든다.
  없는 코드로 짝을 지으면 유통명·규격이 빈 채로 주문이 들어간다
- 자동완성 상자 `.ac` 는 흐름 안에 놓이는 요소라(`position:absolute` 아님) `.pcsheet{overflow:auto}`
  안에서도 안 잘린다. **새 CSS 규칙을 만들지 않는다** — `.itemcard` 는 `.pcsheet` 안 규칙이 이미 있다

### 7-3. 저장 · 다시 그리기

```js
ZG.심폴.짝쓰기(상품코드, 코드, 상품명);   // 있으면 저장소.바꾸기, 없으면 덧붙이기 → 큐가 서버로 보낸다
u.토스트(상품명 + ' → ' + 코드 + ' 짝을 저장했습니다.');
옵션.바뀌면();                              // 되붙이기 + 그리기 — 숫자칸·표가 한꺼번에 맞는다
```
🔴 **짝을 저장하면 미리보기창을 통째로 다시 그린다.** 그때 다른 블록에 **치다 만 글자는 사라진다.**
그 대신 화면 숫자가 언제나 진실과 맞는다 — 보통 못 찾은 상품은 1~3종이고 한 종 고르는 데 몇 초다.
(한 줄씩만 갱신하는 길은 코드가 세 배가 된다. 값어치가 없다.)

🔴 짝 저장·풀기는 **`zg.v3.심폴짝` 만 건드린다. `zg.v3.주문` 은 [저장] 전까지 한 글자도 안 바뀐다** — 08h의 기존 약속 그대로.

## 9. 지뢰 목록 — builder 가 반드시 확인할 것

1. **거래번호 ≠ 주문ID/주문번호.** 후자는 주문자 아이디다. 실물에서 `줄.주문번호` 를 눈으로 확인한다
2. **일자가 1970년이 되지 않는지** 실물로 확인한다 (§3). 숫자·문자열 두 갈래 다
3. **옵션 칸이 빈 문자열인지.** 「옵션(특징포함)」이 새면 `옵션입수` 가 상품 설명문을 파싱한다
4. **거래번호·상품코드가 숫자로 읽혀 앞 0이 날아가지 않는지.** `08d` 는 `raw:true` 라 문자열이면
   그대로 온다. 만약 숫자로 오면 `String()` 이 앞 0을 잃는다 — **실물로 확인하고, 잃으면 08j에서 `padStart` 로 되살린다**
5. **우편번호 앞 0** — `08h.우편정규화` 가 이미 5자리로 채운다. 실물로 한 번 본다
6. **같은 파일 두 번 올리기 → 전부 「이미 있는 줄」** 이어야 한다. 짝을 지은 뒤에도 그래야 한다(§6)
7. **카페24 파일 회귀** — 심폴 코드가 들어간 뒤에도 카페24 파일이 지금과 **완전히 같은 로젠 파일**을 낸다
   (`백업/카페24주문원본_20260806.csv` → `백업/로젠대량등록_20260806-01.xlsx` 27칸×2줄 대조, 8/8과 같은 방식)
8. **로젠 파일 H열**에 심폴 상품코드가 실린다 — 우람님께 보고만 한다(로젠이 H를 안 읽는다는 것은 실물 대조로 확인)
9. 🔴 **실물 `~/Downloads/order_20260808.xls` 는 손님 개인정보다.** 저장소에 복사·커밋하지 않는다.
   시험은 그 자리에서 열어 보고, 검수 문서에는 **칸 이름과 건수만** 적는다

# v3 6단계 설계 — ② 주문 품목 수정 잠금 풀기 · ③ 서비스 품목 일괄 넣기

시안 없이 설계로 간다(기존 화면에 붙는 작은 기능 둘, 우람님 「시안은 가볍게」).
**공통 규약(CSS 변수·애니메이션·접근성·저장소 규약·품목코드 규칙)은 1단계 설계 §10 · §3-7 · §6 그대로.** 여기 다시 쓰지 않는다.
**주문 줄 필드는 2단계 설계 §2-1 그대로.** 아래 표는 **거기에 더하는 칸만** 적는다.
화면 패턴 원본 — 수정 화면 `js/08c-주문입력.js`(`수정뷰`·`PC수정창`), 창 하나짜리 부품 `js/09b-카드설정.js`(`수동창`).

## 0. 먼저 확인한 것 — 이 설계가 서 있는 사실 넷

1. **잠금은 세 곳이다.** `08b` 320행(폰 상세), `08b` 50행(폰 `수동수정` 뷰 진입), `08b` 502행(PC 표 `✎` 버튼). 셋 다 `출처 === '수동'` 을 본다.
2. **`고쳐넣기`(`08c` 289행)는 이미 부분 병합이다.** `저장소.바꾸기()`가 `Object.assign` 이라 표에 없는 칸은 그대로 남는다 — 기존 줄을 고칠 때 원본 식별값은 **자동으로 보존된다.** 위험한 곳은 `줄만들기`(272행)로 만드는 **새 줄** 하나뿐이다(§2-2).
3. **재고는 주문줄을 안 본다.** `03-계산.js 현재고()`는 `zg.v3.출고`의 `품목코드`·`수량`만 읽고, 주문줄을 출고로 옮기는 코드는 아직 없다(`08d 배송완료()`가 토스트뿐 — 2단계 설계 §2-3이 「배송완료 변환 때 쓴다」로 미뤄 둔 자리).
4. **자동완성은 `02-품목코드.js`에 없다.** `04-공통UI.js`의 `후보찾기()`·`자동완성()`이다. **이번에 `02`는 한 글자도 안 건드린다.**

실데이터(`백업/제로가드닝_백업_2026-08-02.json` orders 1,287건) — 전부 `batchId`·`orderNo`가 차 있는 카페24 건이고 `itemCode` 빈 것 15건. **즉 오늘 화면에 뜨는 주문은 사실상 전부 지금 잠겨 있다.**

## 1. 기능 ② — 잠금 풀기

### 1-1. 주문 줄에 더하는 칸 (`zg.v3.주문`)

| 필드 | 타입 | 언제 채우나 | 비고 |
|---|---|---|---|
| `수정됨` | boolean | `고쳐넣기`가 그 줄을 실제로 바꿀 때 `true` | 없으면 안 고친 줄(falsy). **기본값을 박아 넣지 않는다** |
| `수정시각` | number | 고칠 때마다 `Date.now()`로 덮어씀 | 마지막에 고친 때 |
| `원본품목코드` | string | **처음 고칠 때 한 번만** | 이미 있으면 덮지 않는다 |
| `원본수량` | number | 처음 고칠 때 한 번만 | `주문수량 × 옵션입수` 계산값이 아니라 `주문수량` 원값 |
| `원본단가` | number | 처음 고칠 때 한 번만 | |

`원본*` 셋은 **값이 실제로 달라졌을 때만** 그 칸을 남긴다(수령인 주소만 고친 줄에 `원본수량`을 만들지 않는다).
`출처`·`판매처`·`묶음id`·`주문번호`·`원본코드`·`옵션원문`은 **어떤 경우에도 안 건드린다** — §1-2.

### 1-2. 보존해야 할 필드 (고쳐도 절대 안 덮는 것)

`묶음id` · `주문번호` · `판매처` · `출처` · `원본코드` · `옵션원문` · `옵션입수` · `등록일시` · `id`

- `고쳐넣기`의 `바뀔것` 표(300~305행)에 이 칸들이 **없어야** 한다. 지금 표에 `원본코드: 정보.품목코드`가 들어 있는데 **이것이 유일한 파괴 지점이다** — 엑셀에 적혀 온 원문(`ERB01-10(2)`, 소문자 `ech01-10`)이 지워져 매칭 실패 추적이 끊긴다.
  → **`원본코드`를 `바뀔것`에서 뺀다.** 대신 새 줄을 만들 때만 `원본코드 = 품목코드`로 둔다(지금 `줄만들기`가 하는 그대로).
- `옵션입수: 1`도 `바뀔것`에서 뺀다. 지금은 업로드 건의 `4개입`을 조용히 1로 눌러 수량이 ¼이 된다.
  화면에는 「4개입 × N」이 그대로 보이고, 수정 카드가 다루는 것은 `주문수량`뿐이다.
- `묶음키`는 재계산한다(수령인·전화·주소가 바뀌면 건이 갈라져야 하므로). 단 **한 건의 모든 줄을 같은 값으로** 갱신하는 지금 흐름을 유지한다.

### 1-3. 「고쳐졌다」를 화면에 보이는 법

| 어디 | 무엇 |
|---|---|
| PC 표 `누구칸`(`08b` 492행) | 회차칩 **옆에** `<span class="rnd edited">✎ 수정됨</span>`. `title`에 `수정시각`을 `MM-DD HH:mm`으로 |
| PC 표 수량 칸(`08b` 481행) | 값이 바뀐 줄이면 `.mul` 자리에 `<div class="was">원래 3</div>` |
| PC 표 단가 칸 | 같은 방식 `원래 7,900` |
| PC 표 품목 칸 | `원본품목코드`가 다르면 코드 칸에 `<div class="was">원래 ECH01-10</div>` |
| 폰 상세(`08b` 308행 `dline`) | 규격·단가 줄 뒤에 ` · ✎ 수정됨` |
| 폰 목록 카드 | **안 붙인다.** 카드가 좁다 |

`.was`·`.rnd.edited` 스타일은 `css/주문.css`에 두 줄로 넣는다(색은 `--color-text-muted`, 크기 `--font-xs`).

### 1-4. 입구를 여는 곳 (`08b`)

- **320행** — `if (g.출처 !== '수동')` 갈래 통째로 삭제. 🔒 안내줄도 없앤다. 아래 수정·삭제 버튼을 모두에게 보인다.
- **50행** — `if (g && g.출처 === '수동')` → `if (g)`.
- **502~508행** — 지금은 `묶음id`가 있으면 회차칩만, 없고 수동이면 `✎` 버튼이다. → **회차칩은 그대로 두고, 그 옆에 언제나 `✎ 수정` 버튼을 하나 더 놓는다.** 회차 정보는 지우지 않는다.
- 수정 화면 제목 — 업로드 건이면 「주문 수정」, 수동이면 지금대로 「수동주문 수정」(`08c` `수정뷰`·`PC수정창` 한 줄 분기).

### 1-5. 삭제는 어떻게 하나

`수동삭제`(`08c` 317행)는 그 건의 줄을 **실제로 지운다.** 업무규칙 §8 「매입·주문 기록은 지우지 않는다」와 부딪친다.
→ **이번 단계에서는 업로드 건의 「삭제」 버튼을 만들지 않는다.** 수정 화면에도 안 띄운다(수동 건만 지금대로).
품목줄 하나를 빼는 것(`고쳐넣기` 312행의 `처음id들` 정리)은 **업로드 건이면 막는다** — 카드의 `✕`를 흐리게 하고, 대신 수량 0을 넣도록 안내한다. 취소·반품 처리는 별도 기능이다(§5-2에 올린다).

## 2. 기능 ③ — 서비스 품목 일괄 넣기

### 2-1. 서비스 품목줄 = 보통 품목줄 + 칸 하나

**표를 새로 만들지 않는다.** `zg.v3.주문`에 똑같은 모양의 줄을 넣는다.

| 필드 | 보통 줄 | 서비스 줄 |
|---|---|---|
| `서비스` | (칸 없음) | `true` ← **이번에 더하는 유일한 칸** |
| `단가` | 주문서 금액 | `0` 기본, 창에서 고칠 수 있음 |
| `주문수량` `옵션입수` | 엑셀 값 | 창에서 넣은 값 / `1` |
| `품목코드` `유통명` `학명` `규격` | 주문 시점 값 | 품목마스터에서 고른 값 |
| `묶음id` `주문번호` `판매처` `출처` | 원본 | **붙는 건의 값을 그대로 상속** |
| `원본코드` | 엑셀 원문 | 새로 만든 `품목코드`와 같게 |
| `묶음키` `수령인` `수령인전화` `수령인주소` `우편번호` `배송메모` `주문일` | | **붙는 건의 값을 그대로 상속** |
| `등록일시` | | `Date.now()` |

이렇게 두면 `08a 수량()`·`금액()`·`건으로묶기()`·`출고리스트()`가 **아무 수정 없이** 서비스 줄을 함께 센다 — 「진짜로 나가고 재고에서도 빠짐」이 이 상속 하나로 성립한다.

### 2-2. 🔴 `줄만들기`를 고친다 — 두 기능이 함께 걸린 곳

지금 `줄만들기(st, 것, 날짜, 경로)`는 `묶음id:''` · `주문번호:''` · `출처:'수동'`을 박는다.
업로드 건에 품목을 **추가**하면 그 줄만 회차 필터에서 빠지고 출처가 갈라진다.

→ 인자를 하나 늘린다. `줄만들기(st, 것, 날짜, 경로, 바탕)` — `바탕`은 그 건의 원본 줄(보통 `g.줄들[0]`).
`바탕`이 있으면 `묶음id`·`주문번호`·`판매처`·`출처`·`우편번호`·`배송메모`를 거기서 베끼고, 없으면 지금 그대로 수동 값.
`고쳐넣기`(309행)와 서비스 넣기가 이 한 함수를 같이 쓴다.

### 2-3. 단가 0원이 지워지지 않게

`코드정보`(`08c` 260행)는 `st.원코드 !== 코드`이면 단가를 **소매가(매입가×1.7)로 덮는다.** 서비스는 이걸 맞으면 0원이 사라진다.
→ `코드정보(st)`에 `st.서비스 === true`면 자동 소매가 계산을 건너뛰고 `Number(st.단가) || 0`을 그대로 쓰게 한다.

### 2-4. 품목 고르는 부품 — `품목카드묶음`을 **그대로 재사용한다**

새 컴포넌트로 뽑지 않는다. `09b-카드설정.js 수동창`이 이미 `ZG.주문입력.품목카드묶음(null, {수량숨김:true})`로 창 하나를 만들어 쓰고 있다 — 같은 방식이다.
옵션만 둘 늘린다.

- `옵션.단가보임` — 카드 아래 `pair`에 단가 입력칸(`inp num`, 기본 `0`)을 붙이고 `st.단가`에 넣는다. 서비스 창에서만 켠다.
- `옵션.서비스` — `카드값()`이 만드는 `st`에 `서비스:true`를 달아 §2-3이 동작하게 한다.

`읽기()`의 거르개(`접두 && cm>0 && 수량>0`)는 그대로 쓴다 — **단가 0은 통과한다.**

### 2-5. UI — 어디에 어떻게 놓나

- **PC.** `08b PC아래줄()`(540행)의 `.tbar`. 지금 왼쪽에 「고른 것 N건」, 오른쪽에 「엑셀로 내려받기」다.
  → `spacer` **앞**, 「엑셀로 내려받기」 **왼쪽**에 `🎁 서비스 품목 넣기` 버튼(`btn sm`)을 하나 놓는다. 표 머리줄 버튼(`PC머리버튼`)은 **늘리지 않는다**(`08b` 122행 주석의 원칙).
  - 고른 건이 0이면 버튼을 흐리게(`aria-disabled`)하고 눌러도 토스트만. **`고른건들()`의 「없으면 전체」 규칙을 여기에는 쓰지 않는다** — 실수로 그 날 주문 전부에 서비스가 들어간다.
- **폰.** 이번 단계에서는 **일괄 넣기를 만들지 않는다.** 폰 목록에 체크박스가 없다(`상태.고른`은 PC 표 전용). 폰에서는 상세 → 수정 화면에서 품목을 하나 더하는 길이 이미 §1로 열린다.
- **창.** `pcsheet` 한 장 — 제목 「서비스 품목 넣기」, 힌트 `고른 N건 · 수령인 3명 외`, 오른쪽에 `[넣기][✕]`. 본문은 `품목카드묶음`(단가 칸 포함) 하나뿐.
  넣기 → 고른 묶음키마다 §2-1대로 줄을 만들어 `저장소.덧붙이기` → 토스트 `N건에 서비스 M품목을 넣었습니다.` → `ZG.주문.다시그리기()`.
  `같은주문인가()` 중복 확인은 **하지 않는다**(서비스는 일부러 같은 품목을 또 넣을 수 있다).

### 2-6. 「서비스」 딱지

동봉카드 시안(`시안/09-동봉카드-기존느낌.html` 66·327행)의 모양을 그대로 쓴다 — `<span class="svc">서비스</span>`, 노란 배지.

| 어디 | 무엇 |
|---|---|
| 동봉카드(`09-동봉카드.js` 131행 `.nm`) | 유통명 뒤에 `.svc` 배지. `식물들()`(91행)이 `서비스: r.서비스`를 함께 넘긴다 |
| PC 표 품목 칸 | 유통명 뒤에 `.svc` |
| 폰 상세 `dline` | 유통명 뒤에 `.svc` |
| 폰 목록 카드 `oline` | 유통명 뒤에 `.svc` |

`09-동봉카드.js 식물들()`의 중복 제거(같은 품목코드는 한 칸)에 주의 — **산 것과 서비스가 같은 품목이면 서비스 쪽이 먹히지 않게** 키를 `품목코드 + (서비스?'@s':'')`로 나눈다.
`.svc` CSS는 시안 값 그대로 `css/주문.css`에 옮긴다(카드 인쇄면과 화면 양쪽에서 쓴다).

## 4. 재고 계산이 이 필드를 읽는 곳 — 확인 결과 한 줄

`03-계산.js 현재고()`는 **`zg.v3.출고`의 `품목코드`·`수량`만** 읽고 주문줄은 쳐다보지 않는다(주문→출고 전환은 `08d 배송완료()`가 아직 토스트뿐이라 v3에 없다). 그래서 이번에 고친 `품목코드`·`주문수량`과 서비스 줄은 ①`08a 건으로묶기()`의 재고부족 경고 ②`08a 출고리스트()`의 「필요」 수량에 **즉시** 반영되고, 진짜 재고 차감은 배송완료 변환이 붙는 날 같은 `수량(줄) = 주문수량 × 옵션입수`를 읽어 **자동으로 따라온다** — 서비스 줄에 별도 처리가 필요 없다.

## 5. 우람님께 확인할 것

1. **서비스 단가 0원** — 기본 0원, 창에서 고칠 수 있게 했다. 매출 집계에서 서비스를 빼서 봐야 하는지(`서비스:true`로 언제든 나눌 수 있게 해 뒀다).
2. **업로드 주문의 「삭제」·품목줄 빼기를 막았다**(§1-5, 업무규칙 §8). 취소·반품이 실제로 생기면 어떻게 처리하시는지 알려주시면 그때 별도로 만든다. 지금은 수량 0으로 넣으시면 된다.
3. **서비스 일괄 넣기는 PC에만** 만든다(폰 목록에 체크박스가 없다). 폰에서도 필요하신지.
4. **고친 이력을 몇 개까지 남기나** — 지금 설계는 「원래 값」 한 번(처음 원본)만 남긴다. 두 번 세 번 고쳐도 맨 처음 값이 보인다. 전체 이력 표는 만들지 않았다.
5. **회차칩과 「✎ 수정」이 나란히 붙는다**(§1-4). 표가 좁아 보이면 `✎`만 아이콘으로 줄인다.
6. 서비스 줄도 **엑셀 내려받기·출고리스트·동봉카드에 그대로 나간다**. 로젠 송장에서 빼야 할 이유가 있으면 알려주시면 된다.

## §1 「카페24 주문」을 어떻게 가려내나 — 판별 근거

`edge-주문수집/index.ts:193~206`이 자동수집 줄에 넣는 것 —
`출처:"자동수집"` · `판매처:"카페24"` · `원본:[27칸]` · `카페24상태` · `상태확인`.
손업로드(`08h:145`)는 `출처:'업로드'`, 수동주문(`08c:328`)은 `출처:'수동'`, 심폴은 `판매처:'심폴'`.

**보낼 대상 = 아래 넷을 다 만족하는 줄** (`08l.대상뽑기`)

1. 그 로젠 줄의 판정이 `정상`·`이미`·`처리`·`미차감` 중 하나 — **`08f.송장표`와 똑같은 잣대다**(실제로 나간 송장)
2. 주문번호가 있다 (`것.주문번호 || 것.연결주문번호`) — 전화주문은 빠진다
3. `판매처 !== '심폴'`
4. `출처 !== '수동'` — 우리가 손으로 넣은 건은 카페24에 없다

🔴 **`출처==='자동수집'`으로만 좁히지 않는다.** 손업로드 건도 원천은 카페24 주문서라 카페24에 그대로 있다.
없는 주문번호면 `shipment-push`가 「카페24에 없는 주문번호입니다」로 돌려주고 **아무 것도 만들지 않는다**(`index.ts:80~87`).

**기본 체크 해제 두 갈래** (목록엔 보이되 처음부터 꺼둔다)
- `카페24상태`가 있고 `'배송준비중'`이 아니다 → 사유 「카페24에서 이미 발송된 것으로 보입니다」
- 같은 주문번호가 두 줄 이상(합포장 분할) → **첫 줄만 켠다.** 카페24는 주문번호 하나에 송장 하나를 N20 품목 전부에 건다(`index.ts:90~110`). 둘째 줄 사유 「같은 주문번호 — 첫 송장으로 함께 나갑니다」

## §3 `08f` 고치는 곳 — 딱 두 군데

**(1) `출고넣기` (95행) — 넷째 인자 `덧` 추가.** 기존 두 호출부(`08g:159`·`08g:333`)는 안 고친다(undefined면 그대로).

```
function 출고넣기(주문줄들, 출고일, 색인, 덧) { … 저.덧붙이기(저.키.출고, Object.assign({ …지금 그대로… }, 덧 || {})) … }
```
- 로젠 길 → `{운송장번호: 것.운송장번호}` (§4에서 넘긴다). CS·재출력 때 「어느 송장으로 나갔나」가 남는다
- 손처리 길(③) → `{수동: true}`

🔴 **`출고` 레코드는 줄 하나가 행 하나다.** 칸을 더해도 남의 줄을 덮어쓰지 않는다(한 덩어리 JSON 금지 규칙과 어긋나지 않는다).

**(2) `주문출고찾기(주문줄들)` 새로 — `출고되돌리기` 바로 아래.**
```
그 건의 줄 id 들 중 출고 표에서 `출처==='주문'` 인 것의 출고id 배열을 돌려준다.
🔴 `출처==='서비스'` 는 절대 담지 않는다 — 08e 가 넣던 순간 만든 것이라 되돌리면 사은품 재고가 늘어난다(08c:436 관례 그대로).
```
`ZG.배송완료`에 `주문출고찾기`를 내보낸다.

## §4 ① 카페24 발송처리 — 붙는 자리와 흐름

### 4-1 `08g` 결과창에 상자 하나 (207~222행 `몸` 배열, `확인표` 바로 다음)

`.needbox.c24` — 확인 필요 상자와 같은 생김새, 테두리만 파랑(`--color-info-border`가 없으면 `--color-border`).

```
☁ 카페24 발송처리                       심폴은 직접 발송처리하셔야 합니다
─────────────────────────────────────────────────────
이 파일에서 카페24 주문 12건을 카페24에도 발송처리할 수 있습니다.
심폴 3건 · 전화주문 1건은 대상이 아닙니다.
                                   [ ☁ 카페24 발송처리 하기 ]
```

- **대상 0건이면 상자를 통째로 안 그린다** — 단, **심폴이 1건이라도 있으면** 안내 한 줄짜리로 그린다(②)
- 서버 미연결(`!ZG.서버 || !ZG.서버.클라이언트`)이면 버튼 `disabled` + 「서버에 연결돼 있지 않습니다」
- 이 상자는 `요약새로()`(238행)에서도 다시 센다 — 「이름으로 찾기」로 판정이 바뀌면 대상 수도 따라 바뀐다. `참조.c24`에 상자를 물고 `08l.대상뽑기(상태.줄들, 상태.색인)`로 다시 그린다
- 버튼 → `ZG.카페24발송창.열기({짝들, 심폴수, 그다음: 요약새로})`

🔴 **자동 호출은 어디에도 없다.** `처리()`(119행)는 지금 그대로 끝난다.

### 4-2 `08m` 모달 — 세 단추, 순서를 건너뛸 수 없다

`u.탈출풀기()` 하고 자기 `pcscrim`+`pcsheet dlv`를 띄운다. 닫을 때 `u.탈출걸기(ZG.배송완료창.닫기)`로 돌려준다
— `08g:362~375`(이름 고르기)가 이미 쓰는 관례 그대로다.

**머리** `☁ 카페24 발송처리` · 힌트 `12건 · 로젠 송장번호를 카페24에 올립니다`

**몸 — 빨간 경고 한 줄(늘 맨 위)**
> 🔴 진짜로 올리면 **되돌릴 수 없습니다.** 카페24 관리자에서 손으로 지워야 하고, **손님에게 발송 알림이 나갈 수 있습니다.**

**표** — 체크 · 주문번호 · 받는 분 · 운송장번호 · 결과
심폴이 있으면 표 아래 회색 한 줄: `심폴 3건은 대상이 아닙니다 — 심폴은 직접 발송처리하셔야 합니다`

**발 (단계별로 이 순서로만 바뀐다)**

| 단계 | 단추 | 하는 일 |
|---|---|---|
| A 처음 | `[닫기] [🔍 미리보기 — 안 올라갑니다]`(main) | `진짜:false`. 카페24에서 주문을 읽어 **올라갈 것/안 올라갈 것**을 줄마다 채운다 |
| B 미리보기 끝 | `[닫기] [① 첫 1건만 올려보기] [☁ 진짜 올리기 N건]`(warn) | 켜져 있고 미리보기가 ✅인 줄만 센다 |
| C 올린 뒤 | `[닫기] [↻ 실패한 것만 다시 올리기]` | 실패가 0이면 다시올리기 없음 |

- 🔴 **B를 거치지 않으면 진짜 버튼이 화면에 없다.** 오발사 방지의 핵심이다
- `① 첫 1건만` — 인계문서 「실제로 보내시는 날 첫 1건만 올려보고 눈으로 확인」 그대로. 켜진 줄 중 첫 하나만 `진짜:true`
- 진짜 버튼 → `u.확인({제목:'카페24에 발송처리 할까요', 본문:'<b>N건</b>을 올립니다. 되돌리려면 카페24 관리자에서 손으로 지워야 합니다.<br>손님에게 발송 알림이 나갈 수 있습니다.', 확인글:'올리기', 위험:true})`
- 올리는 동안 버튼 `disabled` + 글자 `올리는 중… 25/48`

### 4-3 `08l` — 보내는 방법

```
supa.functions.invoke('shipment-push', { body: { 짝들: [{주문번호, 운송장번호}], 진짜: !!진짜 } })
```
`08b:240`의 `order-collect` 호출과 **같은 모양**으로 쓴다 — `r.error` 먼저 보고, `d.ok`가 아니면 `d.오류`를 던진다.

- **25건씩 끊어 순차로** 부른다. 함수가 주문 하나마다 카페24를 두 번 부르므로 한 번에 다 넣으면 시간제한에 걸린다
- 한 묶음이 통째로 실패해도 **다음 묶음은 계속 간다.** 그 묶음 줄들은 결과 `됨:false, 사유:'서버 오류 — …'`로 채운다
- 되돌아오는 것은 `{ok, 진짜, 보낸수, 실패수, 결과:[{주문번호, 운송장, 됨, 사유?}]}` (`index.ts:125~128`)

### 4-4 성공한 줄만 되쓴다 — `08l.상태되쓰기`

`진짜:true`로 `됨:true`가 된 주문번호에 대해, v3 주문줄마다
`ZG.저장소.바꾸기(키.주문, 줄.id, { 카페24상태:'배송완료', 상태확인: new Date().toISOString() })`.

- 줄 하나 = 행 하나로 올라간다(`01c-보내기`가 알아서 큐에 싣는다). **묶음 통째 쓰기 금지**
- 왜 되쓰나 — `08b:63~66 나갔나()`가 이 값을 본다. 안 쓰면 방금 카페24로 보낸 건이 화면에선 계속 「배송준비중」이라 **또 보내신다**
- 🔴 다음 `order-collect`가 실제 상태로 덮어쓴다. **그게 맞다 — 카페24가 진실이다**(`08b:16~20`)
- **`진짜:false`(미리보기)에서는 아무 것도 안 쓴다**

### 4-5 실패 처리 — 무엇이 실패해도 v3는 그대로다

- 🔴 **출고·재고·송장파일은 손대지 않는다.** 카페24가 안 받아도 우리 기록은 맞아야 한다
- 줄마다 끝칸에 `❌ 사유`를 그대로 적는다(함수가 준 글자를 자르지 않고 160자까지)
- 결과 아래 요약: `✅ 카페24 발송처리 N건 · ❌ 실패 M건 — 통합관리의 출고·재고 기록은 그대로 둡니다`
- `[↻ 실패한 것만 다시 올리기]` — 실패 줄만 다시 켜서 A단계(미리보기)부터 다시 태운다
- **실패가 남은 채로 닫으면** `u.확인({제목:'실패 M건이 남아 있습니다', 본문:'닫으면 이 목록은 사라집니다. 성공한 것은 이미 기록됐고, 같은 로젠 파일을 다시 올리면 남은 것만 다시 뜹니다.', 확인글:'그래도 닫기', 위험:true})`
  — 성공분은 §4-4로 `카페24상태`가 박혀 §1의 「기본 체크 해제」에 걸리므로 **두 번 안 나간다**

## §5 ③ 손으로 배송완료 — 자리·안전장치·되돌리기

### 5-1 PC — 🚚 배송완료 모달 ①고르기창(102~112행) 맨 아래 「또는」 줄

파일 고르기 상자 · 설명글 밑에 한 줄 더:

```
─── 또는, 로젠 파일 없이 ───────────────────────────
표에서 고른 3건          [ ✋ 배송완료로 넘기기 ]  [ ↩ 배송완료 되돌리기 ]
```

- **고른 건은 `ZG.주문.상태.고른`으로 직접 센다.** 🔴 `ZG.주문.고른줄들()`을 쓰면 **안 된다** — 아무것도 안 골랐을 때 화면 전체(최대 1,300건)로 폴백한다(`08b:518~522`). 그 폴백으로 배송완료를 만들면 재고가 통째로 어긋난다
- 고른 게 0건이면 두 단추 `disabled` + 회색 안내 `먼저 주문표에서 건을 고르세요`
- 새 화면·새 버튼을 목록 머리에 만들지 않는다 — PC 머리버튼은 이미 5개다

### 5-2 폰 — 주문 상세 하단(`08b:508~515`, 수정·삭제 줄)

그 건의 상태에 따라 **한 개만** 보인다.
- 주문출고가 없다 → `✋ 배송완료로 넘기기`
- 있다 → `↩ 배송완료 되돌리기` (`class:'btn warn'`)

### 5-3 `08n` 하는 일

**`넘기기(건들, 그다음)`**
1. 건마다 `08f.넘길줄만`을 통과시킨다 — **유일한 관문을 우회하지 않는다.** 서비스·이미나감·품목미확인·수량0은 저절로 빠진다
2. 넘길 줄이 하나도 없으면 `u.토스트('이미 나갔거나 품목코드가 없어 넘길 줄이 없습니다.')`로 끝
3. `u.확인` — **위험:true(빨강)**, 본문에 **무엇을 깎는지 그대로 적는다**
   ```
   제목: 3건을 배송완료로 넘길까요
   본문: 김미정 · SAC01-15 6주 차감
         이서연 · ECP01-15 외 1품목 8주 차감
         박정우 · MON02-20 2주 차감
         ─ 재고가 그만큼 줄어듭니다. 잘못 눌렀으면 「↩ 배송완료 되돌리기」로 되돌릴 수 있습니다.
   ```
   - 줄글은 `08f.차감글`을 그대로 쓴다. **6건이 넘으면 5줄 + `외 N건`**
   - 🔴 **로젠 송장이 없으므로 카페24에는 아무 것도 안 보낸다.** 본문 끝에 한 줄:
     `카페24·심폴에는 발송처리되지 않습니다 — 그쪽은 직접 처리하세요`
4. `08f.출고넣기(넘길, u.오늘문자(), 색인, { 수동:true })`
5. `u.토스트('출고 N건을 기록했습니다 — 재고 N품목 차감.')` → `그다음()`(화면 다시그리기)

**`되돌리기(건들, 그다음)`**
1. `08f.주문출고찾기(줄들)` → 출고id들. 0이면 토스트로 끝
2. `u.확인` **위험:true** — `제목: 배송완료를 되돌릴까요` / `본문: 출고 <b>N건</b>을 지우고 재고를 원래대로 돌립니다.` + 🔴 그 건에 `카페24상태`가 배송완료면 한 줄 더: `이 건은 카페24에서 이미 발송처리됐습니다 — 카페24 쪽은 되돌아가지 않습니다`
3. `08f.출고되돌리기(출고id들)` → 토스트 → `그다음()`
4. **`카페24상태`는 손대지 않는다** — 카페24가 진실이다

**`상태보기(g)`** → `{나감: 출고id들.length, 넘길수있는: 넘길줄수}`. 5-1·5-2가 단추를 고를 때 쓴다.

## §6 ② 심폴 — 안내 문구 세 자리

| 어디 | 문구 |
|---|---|
| `08g` 결과창 카페24 상자 머리 오른쪽(`.why` 자리) | `심폴은 직접 발송처리하셔야 합니다` |
| `08g` 카페24 상자 본문 | `심폴 3건 · 전화주문 1건은 대상이 아닙니다` (수가 0이면 그 조각을 뺀다) |
| `08m` 표 아래 회색 줄 | `심폴 3건은 대상이 아닙니다 — 심폴은 직접 발송처리하셔야 합니다` |

심폴은 v3 안에서 이미 **출고가 곧 배송완료**다(`08b:21~26`). 로젠 파일로 처리되는 순간 배지가 「배송완료」로 바뀐다. **코드는 한 줄도 안 바꾼다.**

## §7 시험 — builder가 여기까지 확인하고 넘긴다

| # | 무엇 | 통과 기준 |
|---|---|---|
| 1 | 로젠 파일 처리 회귀 | 카페24 상자를 아예 안 누르면 결과·송장파일·되돌리기가 **지금과 완전히 같다** |
| 2 | 대상뽑기 | 심폴·전화주문(빈번호)·수동주문이 짝들에 **없다** |
| 3 | 합포장 2줄 | 같은 주문번호 둘째 줄이 **꺼진 채로** 뜬다 |
| 4 | 미리보기 | `진짜:false`로만 부른다(Network 탭으로 body 확인) · `zg.v3.주문`이 **안 바뀐다** |
| 5 | 진짜 버튼 | 미리보기 전에는 **화면에 없다** |
| 6 | 실패 | 없는 주문번호를 섞어 미리보기 → 그 줄만 ❌, 나머지는 ✅, v3 출고 수 불변 |
| 7 | 서버 끊김 | 버튼 비활성 + 안내. 콘솔 오류 없음 |
| 8 | ③ 폴백 방지 | 아무 건도 안 고르고 「배송완료로 넘기기」 → **비활성**. `zg.v3.출고` 불변 |
| 9 | ③ 넘기기→되돌리기 | 넣기 전후 `zg.v3.출고` 길이가 **정확히 같다.** 서비스 출고는 **안 지워진다** |
| 10 | ③ 두 번 누르기 | 이미 넘긴 건을 또 넘겨도 `08f.넘길줄만`이 막아 출고가 안 늘어난다 |

🔴 **7·8·9·10은 실데이터 없이 시드로 한다. 카페24 `진짜:true` 호출은 우람님 컨펌 전까지 하지 않는다.**

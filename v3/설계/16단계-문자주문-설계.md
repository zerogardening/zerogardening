**1-3. 🔴 표 없이 push했을 때의 방어**
- 내려받기: 표마다 `.catch`가 이미 있다(01b:205~209) — 다른 표는 내려온다. 띠 경고만 뜬다. 그대로 둔다.

- **그래도 순서는 SQL 먼저 → push.** 확인은 `select count(*) from public.v3_문자주문;` = 0.

## 4. 주문올리기 → 주문탭 주문

**새 판 없이 기존 수동주문 줄 공장을 쓴다** — `ZG.주문입력.줄만들기(st, 것, 날짜, 경로, 바탕)`(08c:341, 08e도 쓴다). 줄 모양이 한 곳에만 산다. 품목 하나마다:
```
st   = { 접두, cm:Number, 유통명, 학명, 수량, 단가, 원코드: 품목코드 }   // 품목코드를 마지막 '-'에서 쪼갠다. 'MUW01-0' → cm 0
것   = { 이름: 받는분, 전화: 전화모양(전화), 주소, 우편: '' }
바탕 = { 주문번호: 새번호, 판매처: '문자', 출처: '수동', 묶음id: '', 우편번호: '', 배송메모: '' }
줄 = 줄만들기(st, 것, 오늘, '문자', 바탕);  줄.문자주문id = r.id;  저장소.덧붙이기(키.주문, 줄)
```
- 🔴 `원코드: 품목코드`를 꼭 준다 — 빠지면 `코드정보()`가 단가를 매입×1.7로 **덮어쓴다**(08c:331).
- **판매처 `'문자'`**(08c 경로 「문자」와 같은 값) · **출처 `'수동'`** — 08l이 카페24·심폴로 안 보낸다(08l:46). **주문일 = 올리는 날**(주문 조회에 오늘 건으로 뜬다).
- **주문번호는 새로 짓는다** — 08c 수동주문은 `''`이지만 시안이 `261007-01`을 보이고, 번호가 있으면 로젠 출력완료 파일 S열로 **08f 배송완료가 저절로 짝을 짓는다**(빈 번호는 08f:65가 일부러 안 맞춘다). 꼴 `YYMMDD-NN`(올리는 날) · NN = `v3_주문`의 같은 날 `^\d{6}-\d+$` 번호 최댓값+1, 두 자리. 카페24(`YYYYMMDD-…`)·심폴과 모양이 달라 안 겹친다.
- **배송비는 주문 줄로 안 만든다** — 품목코드 없는 줄은 재고·로젠을 깬다. 문자주문 줄에만 남는다(주문탭 금액엔 안 들어간다 — 가정).
- 올린 뒤 문자주문 줄: `상태:'올림'`·`받는분`·`전화`·`주소`(판에서 고친 값)·`올린주문번호`·`올린일시`·`수정일시`. **재고·송장·배송완료는 손대지 않는다** — 08i·08f·08n 기존 흐름.
- 🔴 **두 번 올리기 막기** — 시작할 때 `v3_주문`에 `문자주문id===r.id` 줄이 있으면 새 줄을 안 만들고 상태만 `올림`으로 맞춘다(중간에 끊긴 경우). 누르는 동안 단추 잠금.

## 5. 문자 내용 · 보내기

```
{첫머리}\n\n· {유통명} {규격}\n{수량}개X{단가}원 = {금액}원\n\n· …\n\n배송비 {n}원\n\n합계: {합}원\n\n💰입금계좌\n{계좌}
```
- 첫머리: 받는분 있음 `🌱 [제로가드닝]\n{받는분} 님 주문 안내` / 없음 `안녕하세요, 제로가드닝입니다.\n주문하신 내역 안내드립니다.`(🌱줄 없이 통째로).
- 배송비 0·빈칸 → 그 줄과 앞 빈 줄을 뺀다. 합계 = Σ수량×단가 + 배송비.
- 계좌 = `ZG.업체자료.자사()?.입금계좌` 다듬은 값. 실값은 한 줄(`농협 351-1390-…(제로가드닝)` — 백업 확인). **자사가 없거나 빈칸이면 💰 두 줄을 통째로 뺀다**(널서리 그대로).
- 미리보기 말풍선 = `문자내용()` 결과를 `white-space:pre-wrap`으로 **그대로** 찍는다. 따로 그리지 않는다.
- `문자열기(전화, 글)`: `'sms:' + 숫자만(전화) + '?body=' + encodeURIComponent(글)` — 널서리에서 아이폰 실사용 중인 꼴. **맥(PC)도 같은 링크**로 문자앱을 연다. 🔴 맥 문자앱이 본문을 안 받는 경우가 있어 PC는 열기 **전에** `navigator.clipboard.writeText(글)`로 복사해 둔다. 빌더는 맥에서 `?body=`/`&body=` 중 본문이 차는 쪽을 실측해 고른다.
- 순서: **먼저 저장(상태 `보냄`·`보낸일시`) → 링크**. 보냈는지는 알 길이 없다 — 누른 것을 보낸 것으로 본다.

| 묶음 = 거래id | 묶음 = 문자주문 한 줄(이미 한 덩어리) |
| 출고이력 검색: 유통명·받는 곳 | 받는 분·전화(숫자)·품목·메모, 모든 날짜 |
| 인쇄 제목 「출고 명세서」 | 「문자주문 내역」 · 자사 이름 없으면 `제로가드닝` |

## 8. 빌더가 놓치기 쉬운 것

1. **이름 필수는 주문올리기에서만.** 판의 받는 분 칸이 비면 `.inp.need`(빨간 테두리)+단추 `disabled` — 칠 때마다 다시 판정. 새 문자·목록 「저장」「문자」는 이름 없어도 된다.
2. **전화 없음** — 「저장」만 된다. 「문자」 단추는 `숫자만(전화).length < 9` 이면 `disabled`(새 문자·목록 줄 둘 다). 목록 둘째 줄 「전화 없음」.
3. **제목 짓기 순서** 받는분 → 전화모양(전화) → `📝 메모` → `{첫 품목 유통명} 외 n종`(1종이면 「외」 없이).
4. **배송비 0·빈칸** → 문자 줄 빠짐·합계에 안 더함·PC 표 품목칸 아래 「배송비 없음」. 빈칸을 저장하면 **0**(4500으로 되살리지 않는다). 기본 4,500은 **새 문자를 열 때만**.
5. **올림 잠금은 자료층(20a)에서 막는다** — 화면이 단추를 숨겨도 고치기·지우기 함수가 `상태==='올림'`이면 거부. 폰 쓸기 안 붙임, PC 속판 「삭제」 없음, 펼침 없음. 문자 다시 보내기도 없다(시안 F).
6. **두 번 올리기**(§4) · 주문번호는 **올리는 순간** 짓는다(미리 안 짓는다 — 두 기기가 같은 번호를 잡는 틈을 줄인다).
7. **다시그리기에 펼침·고치던 값이 날아간다** — 남이 저장해 Realtime이 다시 그리면 펼친 카드가 접힌다. 펼친 줄 id와 고치던 사본을 모듈 `상태`에 들고 다시 그릴 때 되살린다(01b는 글칸에 커서가 있을 때만 미뤄 준다).
8. **sms 링크** — 전화는 숫자만, 본문은 `encodeURIComponent`(🌱·💰·줄바꿈 포함). `location.href` 한 번. 저장이 먼저.
9. **품목은 목록선택만** — 검색칸 글로 품목을 만들지 않는다. 후보는 **품목코드 단위**(널서리 `후보목록` 8개)로 `.ac .it` 꼴. `u.자동완성`은 접두 단위라 안 맞는다. 같은 코드를 또 고르면 수량+1.
10. **한글 칸** — 받는 분·메모·검색은 `u.조합안전입력`. 칠 때 화면 통째 다시 그리기 금지(미리보기·합계만 갈아낀다).
11. **10a 싣는 순서** — `01-저장소` 뒤면 된다(`04b` 다음). 15e 주석 「주문.html은 10a를 안 싣는다」는 15e와 함께 사라진다.
12. **표 없이 push 금지** — 우람님 SQL → 확인 쿼리 0 → push.

## 9. 가정 (우람님 확인 전)

- 주문올리기 판은 시안대로 **받는 분·전화·주소** 셋. 우편번호 칸 없음 · 주소 비어도 올라간다(로젠 파일 만들 때 거른다).
- 주문탭 주문에 배송비는 안 실린다. 주문을 주문탭에서 지워도 문자주문은 「주문올림」으로 남는다(되돌림 연동 없음).
- 「저장」은 상태를 바꾸지 않는다(문자 보냄 줄을 고쳐 저장해도 「문자 보냄」). 「문자」를 다시 누르면 `보낸일시`만 새로.

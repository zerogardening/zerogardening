## 1. 왜 파생인가

`v3_주문` 한 줄마다 `수령인`·`수령인전화`·`수령인주소`·`우편번호`가 이미 들어 있다(`08c-주문입력.js:316`).
고객 표를 따로 두면 주문과 고객이 어긋나는 것을 평생 맞춰야 한다. **뽑아 쓰면 어긋날 것이 없다.**

공짜로 따라오는 것 — 온라인 고객 관리 · 신규 고객 자동 등록 · 주문횟수 · 주문내역 · 최근주문일. **코드 0줄.**

## 2. 사람 키 — 이름 + 우편번호

이미 이 프로그램이 쓰고 있는 방식이다. 새로 정하지 않는다.

- `08i-로젠파일.js:66` — `★재구매 — 이름+우편번호 기준. 전화로는 사람을 못 가린다(안심번호)`
- 구 프로그램 `customerHistory` **539명**도 같은 키

```js
function 사람키(이름, 우편번호, 전화) {
  var 이 = 이름키(이름);                    // 공백 제거 + 소문자
  if (!이) return '';
  var 우 = 숫자만(우편번호);
  return 이 + '|' + (우 || 'T' + 전화숫자(전화));   // 우편번호 없으면 전화로
}
```

🔴 **050 안심번호는 키에 쓰지 않는다.** 쿠팡 주문은 우편번호가 늘 있어 위 규칙에서 저절로 전화를 안 탄다.
`08a-주문자료.js:40`의 `묶음키`(이름|전화|주소)는 **화면 합포장용이라 그대로 둔다** — 목적이 다르다.

**구멍** — 수동주문 입력칸에 우편번호가 없다(`08c-주문입력.js:93`). 손으로 넣은 주문은 전화 키로 묶여, 같은 사람이 온라인에도 있으면 두 줄로 갈린다.
→ **`08c` 사람칸에 우편번호(선택) 한 칸을 넣는다.** 3줄이고, 앞으로 갈릴 일이 없어진다.
→ 이미 쌓인 것은 §3 손등록 병합 규칙이 대부분 흡수한다. **병합/분리 UI는 만들지 않는다** — 같은 이름이 두 줄 뜨면 우람님 눈에 바로 보인다.

## 3. 데이터 — 새 표 둘

### 3-1. `v3_고객` — 주문이 아직 없는 손등록 명단 + 메모

```js
{ id: 사람키, 이름, 전화, 주소, 우편번호, 메모들: [], 등록일시, 수정일시 }
```

주문에서 뽑은 것과 겹치면 **주문이 이긴다.** 이 표에서는 `메모들`만 얹는다.

**손등록 붙이기 순서** (주문 그룹을 다 만든 뒤 한 번):
1. 사람키가 같은 그룹이 있으면 → 그 그룹에 메모를 얹는다
2. 없으면 `이름+전화숫자`가 같은 그룹을 찾아 얹는다 (우편번호 유무로 갈린 것 흡수)
3. 그래도 없으면 → **주문 0건 고객**으로 목록에 따로 넣는다

### 3-2. 메모 — 날짜별 카드로 쌓인다 (우람님 8/13 확정)

`메모들`은 **배열**이다. 표를 더 만들지 않는다 — `내용` jsonb 안에 그대로 들어간다.

```js
메모들: [
  { 날: '2026-05-02', 글: '여름 오전 배송 원하심 · 아파트 경비실 맡기기 OK' },
  { 날: '2026-07-21', 글: '에키네시아 잘 받으셨다고 하심' },
  { 날: '2026-08-13', 글: '가을에 그라스류 문의' }        // ← 새 것이 맨 아래
]
```

- 🔴 **오래된 것이 위, 새 것이 아래.** 카드 한 장이 메모 한 건이다
- 적는 칸은 **하나**다. 쓰고 `💾 메모 저장`을 누르면 **오늘 날짜가 붙은 카드가 맨 아래에 생기고 칸은 비워진다**
- 날짜는 저절로 붙는다. 손으로 적지 않으신다
- 카드마다 `🗑` 하나 — 잘못 적은 것만 지운다. 고치기는 없다(지우고 다시 적으신다)

### 3-3. `v3_문자` — 문자 발송 기록 (우람님 8/13 추가)

🔴 **이 프로그램은 문자를 보내지 않는다. 보내신 것을 적어두는 곳이다.**
발송은 쓰시던 문자 서비스에서 하시고, 여기엔 「언제 · 누구에게 · 무슨 내용」만 남는다.

```js
{ id, 보낸날: '2026-08-13', 내용: '...', 받은이: [사람키, ...], 등록일시 }
```

🔴 **발송 한 번이 한 줄이다. 사람마다 한 줄로 만들지 않는다** — 100명에게 보내면 100줄이 서버로 올라간다. 발송 단위면 한 달에 몇 줄이다.

### 붙일 곳
- `01-저장소.js:13` 키에 `고객: 'zg.v3.고객'`, `문자: 'zg.v3.문자'` — PK는 `id`라 `표키` 맵은 손대지 않는다
- `01b-서버.js:11` `표들`에 `'고객'`, `'문자'` 추가 → 서버 표는 `v3_고객`·`v3_문자`로 자동
- Supabase에 두 표 생성 (`7단계-서버연동-설계.md:42` 규격 · RLS는 기존 표와 동일)

## 4. 화면 — 주문 화면 안 탭

`15d-견적탭.js`를 **3칸으로 고친다**(`주문 조회 / 견적 요청 / 고객`). 지금 `켜짐`이 boolean이니 문자열로 바꾼다.
`08b-주문목록.js:952,956`의 가로채기 호출 두 줄은 **그대로 둔다.**

🔴 **이름은 가리지 않는다.** 시안의 `김OO`는 그림용 표기였다 — 실제로는 주문에 있는 **전체 이름 그대로** 보이고 저장된다.

### PC — 표 한 장
| ☑ | 이름 | 연락처 | 주소 | 주문 | **문자** | 최근주문 | 합계 | 판매처 |

- **`문자` 열을 `주문` 열 바로 옆에** 둔다 — `문자 3 · 주문 1`이 나란히 보이는 게 이 기능의 핵심이다
- 머리줄 요약: `N명 · 주문 M건 · 합계 ○원 · 손등록 N · ⚠안심번호 N`
- 필터: 검색어 · 기간 `부터~까지` · 최소 주문횟수 · **문자 N회 이상** · 판매처 · 손등록만
- 버튼: `⬇ 엑셀` · `✉ 문자 기록` · `＋ 고객 등록`
- **체크박스 열** + 머리 전체선택 — 필터 걸어놓고 한꺼번에 고른다
- 연락처가 `050`이면 `⚠ 안심번호` 배지 — **문자가 안 가는 번호다.** 모르고 명단에 넣으면 반응률을 잘못 읽는다
- 주문 0건 손등록 고객도 섞여 나온다(주문 `0`, 최근주문 `—`)

### 폰 — 목록 / 상세 / 등록
`15c-견적폰.js` 세 뷰 구조를 그대로 따른다. 폰에서도 체크·문자 기록이 된다.

### 상세 (폰·PC 공통)
- 그 사람 주문 전부: 날짜 · 품목 · 수량 · 금액
- **메모 카드 목록** (§3-2)
- **받은 문자** 목록: 날짜 + 내용
- 버튼 `[견적요청 만들기]` `[수동주문 넣기]`

## 5. 문자 기록 창 (`✉ 문자 기록`)

1. 고객 목록에서 체크박스로 고른다
2. `✉ 문자 기록` → 창이 뜬다. **고른 N명**과 그중 **⚠안심번호 M명(도달 안 됨)**이 먼저 보인다
3. 보낸 날짜(오늘 기본) + 보낸 내용을 붙여넣고 저장
4. 창 아래에 **지난 발송 목록** — `날짜 · 인원 · 내용 첫 줄 · 보낸 뒤 주문 M명`

🔴 **`보낸 뒤 주문 M명`이 곧 반응률이다.** 캠페인 표도 어트리뷰션도 만들지 않는다 — 발송 날짜 이후 주문을 세면 나온다.

```js
// ponytail: 반응 집계 창은 14일 고정. 기간을 고르고 싶어지면 그때 칸을 단다
var 반응기간 = 14;
```

## 6. 견적요청 연동 (지시 4번)

`ZG.견적자료.추가({ 요청일: 오늘, 고객명, 연락처, 내용 })` 한 번이면 견적요청 탭에 리스트업된다. **새 코드 5줄.**
견적요청 레코드에 `고객키`는 **넣지 않는다** — 이름·연락처로 충분하고, `내용`이 jsonb라 나중에 붙이는 값이 0이다.

## 7. 수동주문 연동 (지시 1·5번)

고객관리 안에 주문 입력 화면을 **또 만들지 않는다.** `ZG.주문.열기('수동')`으로 보내되 이름·전화·주소를 채워서 연다.
`08c-주문입력.js:93` `사람칸(g)`이 이미 초기값 인자를 받으므로, 상태에 채울값 하나만 얹으면 된다.

## 8. 엑셀 (지시 6번)

`08d-주문파일.js:124` 패턴을 그대로 쓴다(`aoa_to_sheet` → `writeFile`). `주문.html`에 `xlsx.min.js`가 이미 실려 있다.
**공용 엑셀 헬퍼는 만들지 않는다** — 흩어진 세 곳(`08d`·`08f`·`08i`) 정리는 이번 범위가 아니다.
파일명 `고객_YYYY-MM-DD.xlsx`. **화면에 걸린 필터 그대로** 내려받고, `문자` 열도 함께 나간다.

## 11. 검증

🔴 **구 프로그램 `customerHistory` 539명이 대조군이다.** 같은 이름+우편번호 키로 쌓인 값이니, 새로 뽑은 고객 수가 크게 벗어나면 사람키가 틀린 것이다.

1. 이사한 실데이터로 열어 **고객 수 ≒ 539명** 확인
2. 주문 많은 고객 한 명을 골라 주문 화면 검색 결과와 **건수·합계 대조**
3. 이름이 **가려지지 않고 전체로** 나오는가
4. 쿠팡 고객(050)에 `⚠` 배지가 붙는가
5. 기간·최소횟수·문자횟수 필터 → 엑셀 내려받아 **줄 수가 화면과 같은가**
6. 메모 저장 → **오늘 날짜 카드가 맨 아래에 생기고 입력칸이 비워지는가** · 새로고침해도 남는가 · 🗑로 그 카드만 지워지는가
7. 3명 체크 → 문자 기록 저장 → **세 사람 표에 `문자 1`이 붙는가** · 상세에 내용이 보이는가
8. 문자 저장 뒤 그중 한 명 주문 넣기 → 지난 발송 목록의 **`보낸 뒤 주문` 이 1로 오르는가**
9. 고객 상세 → 견적요청 만들기 → **견적 요청 탭에 뜨는가**
10. 손등록 고객이 나중에 같은 이름+전화로 주문했을 때 **두 줄로 안 갈리는가**
11. 주문 조회·견적 요청 탭이 **여전히 멀쩡한가**(탭줄을 3칸으로 고쳤으므로)

## 0. 🔴 조사로 뒤집힌 것 셋 — 설계의 근거다

### ① 폰은 맥의 편집기에 닿지 못한다. 그래서 로컬 API 갈래는 둘 다 없는 길이다

「편집기(`편집.py`, 8765)에 새 API를 얹는다」와 「새 로컬 서버를 세운다」를 견줄 필요가 없다.
**폰에서 `127.0.0.1` 은 폰 자신이다.** 맥의 랜 IP를 써도 https 페이지 → http 사설망은 혼합콘텐츠로 막히고,
같은 와이파이일 때만 된다. 이미 `06d-상품이미지.js:25-31` 이 **바로 이 까닭으로 폰을 막아 두었다.**
그런데 시안은 **폰 3장이 원고를 고치는 그림**이다.

→ **길은 하나다. A단계가 사진에 쓴 길을 글자에 그대로 쓴다.**

```
폰·PC 화면  ──(Supabase v3_원고 표)──  맥 `원고받기.py`  ──  제작.html · 작성내용.md
                                                  └─ render.py → 1~6.jpg → Storage → [결과] 탭
```

편집기(`편집.py`)는 **한 줄도 안 고친다.** 다만 그 안의 `작업본()`·렌더 블록은 파이썬 쪽에서 본보기로 베낀다.

### ② 🔴 이미지에 찍히는 글은 `작성내용.md` 가 아니라 `발행이미지/제작.html` 이다

구절초 노랑 1구역 실측 — `작성내용.md` 는 「9~10월 화단은 흰색과 보라 쪽으로 기웁니다…」,
`제작.html:252` 의 `.lead` 는 「9~10월 **가을** 화단은 흰색과 **보라색의 꽃이 많은데요**…」. **다르다.**
`.md` 로 초안을 쓴 뒤 편집기에서 손본 것이 `제작.html` 에만 남았기 때문이다.
`.md` → `.html` 로 옮기는 스크립트는 **없다**(사람·에이전트가 조립한다).

→ **[원고] 탭이 읽고 쓰는 원본은 `제작.html` 이다.** `작성내용.md` 는 같은 값으로 **같이 갱신**해 기록이 안 썩게 한다.
→ 제작.html 이 아직 없는 품목(첫 제작 전)은 `작성내용.md` 를 읽는다. 둘 다 없으면 빈 상태다.
→ 🔴 **손대지 않은 구역은 바이트 그대로 둔다.** `제작.html` 의 `&nbsp;`(줄바꿈 막이)가 살아 있어야 조판이 안 흐트러진다.
   고친 구역은 그 손질이 사라진다 — 어차피 문장이 바뀌는 자리라 받아들인다.

### ③ 🔴 「34품목 전부 같은 구조」가 아니다 — 파서가 실패를 견뎌야 한다

품목 폴더 **35**개 실측 — `작성내용.md` **34** · `## 1구역` 꼴 **32** · `소제목 :` 줄 **28** ·
`발행이미지/제작.html` **27** · 4구역에 **④가 있는 것 4개**(3항목 고정이 아니다).

→ `원고파일.py` 는 **못 읽은 칸을 지어내지 않는다.** 없는 칸은 화면에 **흐린 빈 칸**으로 두고,
  🔴 **그 칸은 저장 대상에서 뺀다.** 있는 칸만 고치게 한다.
→ ④가 있는 4품목은 **①②③만 보여주고 ④는 건드리지 않는다**(파일에 그대로 남는다). 4구역 3항목 고정 규칙과 어긋나지 않는다.
→ `python3 통합관리/도구/원고받기.py 점검` 으로 **어느 품목의 어느 칸을 못 읽었는지**를 먼저 찍는다. 만들기 전 한 번 돌린다.

## 2. 저장 자리 — 표 하나, 🔴 글칸 하나가 한 줄

`v3_원고`. 칸·트리거·RLS는 **`13단계-제작요청.sql` 과 글자 하나 안 다르다** — 표 이름만 바꿔 새 파일
`v3/설계/15단계B-원고.sql` 로 낸다. 우람님이 Supabase SQL Editor 에서 **한 번만** 돌리신다.

**줄 두 종류**

| id | 무엇 | 내용(jsonb) |
|---|---|---|
| `{품목코드}#{칸}` | **글칸 한 개** (`QUC02-10#4-2`) | `{품목코드, 칸, 소제목, 본문, 고친때, 맥시각}` |
| `{품목코드}` | 품목 머리 (`QUC02-10`) | `{품목코드, 만들기요청, 만든때, 장수, 만들기상태, 말}` |

🔴 **한 품목의 글을 한 줄에 담지 않는다.** 우람님이 2구역을, 두용씨가 5구역을 같은 때에 고쳐도 서로 안 지운다.
🔴 **덮어쓸 때도 한 칸만 쓴다** — 화면은 **바뀐 칸만** 보낸다. 안 고친 칸은 아예 안 건드린다.

**늦게 온 것이 이긴다를 막는 두 시각**
- `고친때` — 화면이 저장할 때 찍는 ms
- `맥시각` — 맥이 그 값을 파일에 반영한 뒤 찍는 ms
- 맥은 `고친때 > 맥시각` 인 줄만 파일에 쓴다 → 쓰고 나서 `맥시각 = 고친때`
- 맥은 파일 mtime > `맥시각` 이면 **파일 쪽을 올린다** → `고친때 = 맥시각 = mtime`
- 이 두 규칙이 맞물려 **맥↔서버 핑퐁이 안 난다.**

**🔴 `01-저장소.js`·`01b-서버.js` 는 안 고친다.**
`06h` 가 `ZG.서버.클라이언트.from('v3_원고')` 로 **직접** 읽고 쓴다 — `06g` 가 Storage 를 직접 쓰는 것과 같은 결이다.
공통 파일을 고치면 `주문.html`(v=69)·`업체.html`(73)·`소싱.html`(63)·`메모.html`(63) 이 **묵은 사본을 계속 물고 있어** 갈라진다.
대가는 **오프라인 저장이 안 되는 것** — A단계 사진과 같다. 안 닿으면 토스트로 분명히 알린다(조용히 실패 금지).

**만들어진 이미지** — Storage 공개 버킷 `product` 의 `{품목코드}/발행/1.jpg … 6.jpg`.
A단계가 쓰는 `{품목코드}/1.jpg`(원료)와 **칸이 갈린다.** `06g` 의 `사진훑기()`·`주소()` 를 그대로 쓴다.

## 3. 흐름 — 저장 · 글자수 · 다시 만들기

**저장** (시안 ② → ②′)
1. 바뀐 칸을 모은다 → **글자수 검사**(브라우저, `본문.replace(/\n/g,'').length`)
2. 넘친 칸이 있으면 **아무것도 안 보낸다.** 맨 위 경고 카드 + 그 칸 머리에 `91 / 83 · 8자 넘침` + `.ta.over`
3. 다 안쪽이면 바뀐 칸만 `upsert` → 토스트 「N칸 저장했습니다 · 맥이 1분 안에 받아 갑니다」
4. 🔴 **저장은 글자만이다. 이미지는 안 만든다.** (우람님 확정)

**글자수는 두 겹이다**
- 1겹 화면 — 글자수 상한(위 표). **저장 때 한 번**, 즉시. 서버도 맥도 안 부른다
- 2겹 맥 — `render.py:16-85` 의 조판 자체검수(튀어나감·잘림). **다시 만들기 때** 돈다.
  걸리면 머리줄 `만들기상태='실패'` + `말` 에 지적을 담고, [결과] 탭이 그 말을 그대로 보여준다

**다시 만들기**
1. 화면 → 머리줄 `만들기요청 = Date.now()`, `만들기상태='요청'`
2. 화면은 **5초마다** 머리줄과 Storage `{품목코드}/발행` 을 다시 본다 (최대 5분, 단추는 「만드는 중…」으로 잠근다)
3. 맥 `원고받기.py` 가 요청을 보고 → 글칸 반영 → `render.py` → `sips` → `1~6.jpg` → `~/상세페이지/{품목}/` 로도 복사
   → Storage 업로드 → 머리줄 `만든때`·`장수`·`만들기상태='됨'`
4. 5분이 지나도 안 바뀌면 「맥이 안 받아 갔습니다 — 맥이 켜져 있는지 보십시오」. **맥이 꺼진 경우는 C단계 몫이다.**

## 5. `?v=` 갱신 — 🔴 안 올리면 눌러도 조용히 아무 일도 안 난다

`v3/index.html` 에서 **이 네 줄만** 손댄다.

```
js/06g-사진수집.js?v=75   →  ?v=76      (고쳤다)
js/06h-원고자료.js?v=76              ← 새 줄. 06g 바로 아래
js/06i-원고화면.js?v=76              ← 새 줄
js/06j-결과화면.js?v=76              ← 새 줄
```

- `05d-입고내역.js` 는 **75 그대로** 둔다 — 안 고친다.
- 나머지 `?v=72` 들도 **그대로** 둔다. 파일마다 제 번호다.
- 🔴 `주문.html`(69) · `업체.html`(73) · `소싱.html`(63) · `메모.html`(63) 은 **건드리지 않는다.**
  §2에서 공통 파일(01·01b)을 안 고치기로 한 것이 곧 이 네 장을 안 건드려도 되는 까닭이다.

## 7. 실서비스 주의 (개발지침 §2~4)

- 저장소 두 개다. **`통합관리/`(공개)에 원고 글자를 옮겨 담지 않는다.** 원고는 `제로가드닝/상품/`(비공개)에만 산다
- 고치기 전 `git status` — 다른 창 작업이 섞여 있으면 멈추고 여쭌다. **`git add -A` 금지**
- **Supabase 데이터를 지우거나 덮어쓰는 코드는 없다.** `v3_원고` 는 **새 표**이고, 기존 표는 읽기만 한다
- **push 는 우람님이 직접 하신다.** 커밋까지 하고 명령줄을 드린다. 명령줄에 `#` 주석을 붙이지 않는다
- C단계(git 반영 · 맥이 꺼져 있어도 반영)는 **이번 범위 밖이다.** 맥이 켜져 있다는 전제다

## 2. Supabase — `v3_현황판` 한 표 (SQL 전문)

🔴 빌더는 아래를 `v3/설계/25단계-현황판.sql`로 **글자 그대로** 옮겨 두고, 실행은 **우람님이 Supabase 대시보드 → SQL Editor에 붙여 넣고 Run** 한 번(16단계 지시함과 같은 방식). 칸·트리거·RLS는 `v3_지시`와 같다. Realtime은 안 붙인다(5분 판이라 폴링도 안 한다).

```sql
-- 25단계 — 현황판 표 하나. 🔴 우람님이 Supabase 대시보드 SQL Editor 에서 한 번만 돌리신다.
--   id '판'          아이맥 현황판올리기.py 만 쓴다. 지시로그에서 매번 새로 만든 사본이다
--   id '숨김:{항목id}' 브라우저만 쓴다. 「정리」 한 번 = 한 줄. 되살리기는 삭제됨=true
-- 🔴 칸·트리거·RLS 는 v3_지시(16단계)와 글자 하나 안 다르다. 표 이름만 다르다.

create table if not exists public.v3_현황판 (
    id text primary key,
    내용 jsonb not null,
    삭제됨 boolean not null default false,
    수정시각 timestamptz not null default clock_timestamp(),
    수정자 uuid default auth.uid());

drop trigger if exists 손댐 on public.v3_현황판;
create trigger 손댐 before update on public.v3_현황판
    for each row execute function public.v3_손댐();

alter table public.v3_현황판 enable row level security;
revoke all on public.v3_현황판 from anon;
drop policy if exists "로그인한사람만" on public.v3_현황판;
create policy "로그인한사람만" on public.v3_현황판
    for all to authenticated using (true) with check (true);

-- 올리기는 PATCH 만 한다 — 빈 판 줄을 미리 하나 심어 둔다
insert into public.v3_현황판 (id, 내용) values ('판', '{"판":1,"갱신":"","항목":[]}')
    on conflict (id) do nothing;
```

## 3. 항목 만드는 규칙 (올리기 쪽 — 화면은 계산하지 않는다)

### 3-1. 단계 — `단계(막힌, 날)` (🔴 10/18 팀장 판단으로 바꿈 — 「포함하면」이 아니라 「맨 앞」)
「막힌 것」 칸에서 **맨 처음 나오는 상태 기호**(🔴·⬜·⏸·🔄·✅ 중) 하나로 정한다. 뒤에 섞인 기호는 보지 않는다.
| 맨 앞 기호 | 단계 |
|---|---|
| 🔴 · ⬜ · ✅ | 컨펌대기 |
| ⏸ | 작업중 + `막힘:true` |
| 🔄 | 작업중 |
| 없음 | 준비 |
| 「끝난 것」 목록의 줄 | 완료 |
- **✅로 시작하는 열린 줄이 받은 지 `확인묵힘일`(7)을 넘으면 컨펌대기가 아니라 완료**로 넘긴다(끝났는데 「끝난 것」으로 안 옮겨진 옛 줄). 그 완료에도 §3-4 완료보존일(받은 날 기준)이 걸린다. 날이 빈 ✅ 줄은 컨펌대기로 둔다.
- 상수 둘(`완료보존일 = 30`·`확인묵힘일 = 7`)은 올리기 스크립트 맨 위 한 곳에 나란히 둔다.
⚠️·🟡 등 다른 기호는 보지 않는다. 진행률은 칸 맨 앞 `NN%`(`읽기()`의 `률`) — 없으면 null.
- 까닭: 「포함하면」 규칙은 실데이터에서 컨펌대기 215장이 됐다(옛 줄 대부분이 칸 어딘가에 ✅를 품고 「끝난 것」으로 안 옮겨짐).

### 3-2. 제목·설명 — 먼저 걸리는 것
1. **요약본** `지시로그/현황판-옛줄요약.json`에 키(§3-3)가 있으면 그 `제목`·`설명`.
2. 지시(완료는 머리) 맨글에 「 — 」가 있고 앞이 **20자 이하** → 앞 = 제목, 뒤 = 설명.
3. 자르기 — 제목 = 첫 구분자(「 — 」·「 · 」·`(`·`,`·`→`·`:`) 앞, 16자 넘으면 16자에서 자름 · 설명 = 나머지 앞 40자. 완료 줄인데 나머지가 비면 `결과` 첫 토막(맨 앞 ✅·🔴 등 기호 떼고 「 · 」 앞까지, 40자).
- 「…」는 붙이지 않는다(화면 CSS가 말줄임). `[팀]` 꼬리표는 `읽기()`가 이미 뗐다 — 시안 준비 카드의 「[허브] 현황판 정리」처럼 제목에 꼬리표가 남으면 안 된다.

### 3-3. 키와 id (🔴 바꾸면 숨김이 전부 풀린다)
```
키  = 구획 + "|" + 월/일 + "|" + 지시앞16      예) 열|10/17|작약 5종 상세에서 발송 관
      구획   '열'(안 끝난 것) · '끝'(끝난 것)
      월/일  읽기()의 날(ISO)에서 int 월 "/" int 일 (0 안 채움) · 날이 비면 "?"
      지시앞16 읽기()가 돌려준 `지시`(팀꼬리표·**·` 뗀 것) 앞 16글자 (파이썬 str 슬라이스)
      같은 키가 또 나오면 파일 순서대로 두 번째부터 "#2", "#3" … 를 뒤에 붙인다
id  = sha1(키 utf-8) 16진 앞 12자
```
- 받은 시각(`01:5x`)은 넣지 않는다 — 나중에 고쳐 적는 일이 잦다. 해(年)도 넣지 않는다 — `날짜()`가 오늘에 따라 해를 짐작해서 1년 뒤 바뀐다.
- 🔴 **줄 앞 16자를 고쳐 쓰면 다른 항목이 된다**(숨김 풀림·요약본 안 걸림). 열린 줄이 끝난 것으로 옮겨가면 `끝|` 키라 새 항목 — 숨겼던 일도 「완료」에는 다시 보인다(의도).

### 3-4. 완료 30일
- 올리기 스크립트 맨 위 상수 **`완료보존일 = 30`** 한 곳. 완료 항목은 `오늘 - 날 > 완료보존일`이면 판에 **싣지 않는다**(날이 빈 완료는 싣지 않는다). 화면은 일수를 모른다.
- 같은 상수로 숨김 줄 청소: 매 바퀴 판을 올린 **뒤**, `숨김:` 줄 중 **판에 없는 항목이고 숨긴때가 완료보존일보다 오래된 것**만 DELETE(아이맥 service_role만). 지금 판에 있는 항목의 숨김은 절대 안 지운다. PostgREST 한 번에 1,000줄 상한에 닿지 않게 하려는 것.

### 3-5. 옛줄 요약본 — 빌더가 **한 번만** 만든다
1. `python3 _도구/현황판올리기.py --옛줄뽑기 > {스크래치}/옛줄.tsv` — §3-2의 1·2번에 안 걸리는 항목(열린 전부 + 30일 안 완료)을 `키 ⇥ 지시 맨글 앞 120자 ⇥ (완료면) 결과 앞 80자`로 찍는다.
2. 빌더가 줄마다 **제목 10자 내외(최대 16) · 설명 40자 이내**를 써서 `제로가드닝/지시로그/현황판-옛줄요약.json`으로 저장 — `{"열|10/17|작약 5종 상세에서 발송 관": {"제목":"작약 상세 문구","설명":"발송 문장 빼고 규격은 6구역 칸에서만"}, …}` · 키는 tsv에서 **복사**한다(손으로 치지 않는다).
3. 40줄씩 끊어 쓴다 · 사실만 줄인다(지시에 없는 말을 보태지 않는다) · 다시 `--시험`을 돌려 **`옛줄없음 0`** 확인.
- 그 뒤엔 다시 만들지 않는다. 새 줄은 지시로그 머리 규칙(`[팀] 제목 — 설명`)으로 2번에서 걸린다. 앞으로 끝난 줄은 요약 없이 3번으로 간다.
- 올리기는 요약본을 **읽기만** 한다. 깨진 JSON이면 로그에 경고 한 줄 남기고 요약 없이 진행(판을 막지 않는다).

## 4. 아이맥 — `제로가드닝/_도구/현황판올리기.py` (허브 저장소)

- `현황판.py` **끝 4줄(97~101행)을 `def 쓰기():` 안으로 넣고 `if __name__ == "__main__": 쓰기()`** — 혼자 돌릴 때는 지금과 똑같다. 고치는 것은 이것뿐(읽기 규칙은 그대로).

### 5-1. `21a-현황판자료.js` — `ZG.현황판자료`
- `19-지시함.js`의 `통()`·`제때()`(10초)·`말썽()`을 같은 모양으로 둔다(표 없음 → 「서버에 v3_현황판 표가 아직 없습니다 — 25단계-현황판.sql 을 돌리십시오」). 01·01b는 안 고친다.
- `불러오기()` → `from('v3_현황판').select('id,내용,삭제됨')` 한 번 → `{갱신, 항목[], 숨김: Set}`. 숨김은 `삭제됨`이 아닌 `숨김:` 줄의 `내용.항목`. **숨긴 항목은 목록·모든 숫자에서 뺀다.** 모르는 id의 숨김은 무시.
- `숨기기(항목)` → `upsert([{id:'숨김:'+항목.id, 내용:{항목, 제목, 숨긴때}, 삭제됨:false}])`. 화면이 먼저 빼고(낙관), 실패하면 되넣고 토스트 「정리 못 했습니다 — {말썽}」.
- `거르기(항목들, 단계, 팀)`·`세기()`는 순수 함수(그리기 없음) — 검수가 콘솔에서 바로 부를 수 있게.

## 7. 시험 방법
1. **서버 없이 (빌더·검수)** — `python3 _도구/현황판올리기.py --시험` → 단계별 수가 빌더 보고와 같은지(§3-1 바뀐 규칙 기준 — §0의 215는 옛 규칙) · `옛줄없음 0`(요약본 뒤) · JSON에 `막힌`·`결과` 원문이 없는지 · 같은 입력 두 번 → id 전부 같다.
2. **덮어쓰기 막기** — 스크래치에 ① 빈 파일 ② `# ✅ 끝난 것` 줄을 지운 사본 ③ 열린 칸 표만 지운 사본을 만들어 `--시험 --로그 {사본}` → 셋 다 종료코드 2와 「덮어쓰지 않았다」. 진짜 모드도 `--로그`를 받게 두고 `HOME={스크래치} python3 _도구/현황판올리기.py --로그 {사본}`(열쇠를 못 찾는 집) → 「덮어쓰지 않았다」가 나와야 한다. 「키가 없다」가 나오면 검사가 서버보다 늦은 것이다. 🔴 `~/.zg_supabase_key`를 옮기거나 지우지 않는다(다른 도구가 쓴다).
3. **새 표에만 쓰는 시험** — SQL 뒤 `python3 _도구/현황판올리기.py` 한 번 → 대시보드 Table Editor에서 `v3_현황판` `판` 줄 `갱신` 확인. 이 단계에서 쓰는 곳은 `v3_현황판`뿐이다. 브라우저에서 카드 둘 정리 → `숨김:` 두 줄 · 다시 올리기 → 둘 다 그대로 숨어 있는지. 시험 숨김 되돌리기(SQL Editor):
   `update public.v3_현황판 set 삭제됨 = true where id like '숨김:%' and 수정시각 > now() - interval '1 hour';`
4. **화면** — 390px·1440px 둘 다: 처음 = 완료 뺀 셋 · 컨펌대기 누름/다시 누름 · 팀 칩 숫자가 단계를 따름 · 완료 날짜 무리·요일 · 률 null/0 · 막힘 · 폰 밀기/PC 마우스 정리 · ↻ · 더보기 시트에 안내 문구 없음·「현황판」 줄 · PC 옆칸 「현황판」. JS 문법은 osascript 파싱(기억 `js-syntax-check-without-node`).
5. launchd — 넣은 뒤 `launchctl print gui/501/com.zerogardening.현황판올리기 | grep -E 'state|runs'` · 5분 뒤 로그에 성공 줄 두 개.

- **지시로그 원본을 쓰지 않는다.** 올리기·요약본 만들기 모두 읽기만. `지시로그/우람님.md`는 늘 다른 창 미커밋(M) — 허브 커밋은 새 파일 셋 + `현황판.py`만 골라 `git add`(‑A 금지).

- 저장소가 둘이다 — 통합관리(`v3/…`)와 허브(`_도구/`·`지시로그/`). 커밋도 둘. 통합관리는 `08b`·검수 폴더가 다른 창 미커밋 → 주문.html은 `04` 줄만 `git add -p`.

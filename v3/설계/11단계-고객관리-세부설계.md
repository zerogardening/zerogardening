## 1. `js/16a-고객자료.js` — 파생 · 집계 · 손등록 · 메모 · 문자 (화면 없음)

### 1-1. 껍데기

`15a-견적자료.js`와 같다. `window.ZG` → IIFE → `'use strict'` → 맨 아래 `ZG.고객자료 = {…}`.

var 반응기간 = 14;   // ponytail: 반응 집계 창은 14일 고정. 기간을 고르고 싶어지면 그때 칸을 단다 (확정 설계 §5)

### 1-2. 열쇠 함수 — **확정 설계 §2 그대로**. 고쳐 쓰지 않는다

```js
function 이름키(s) { return String(s == null ? '' : s).replace(/\s+/g, '').toLowerCase(); }
function 숫자만(s) { return String(s == null ? '' : s).replace(/[^0-9]/g, ''); }
function 전화숫자(s) { return 숫자만(s); }

function 사람키(이름, 우편번호, 전화) {
  var 이 = 이름키(이름);
  if (!이) return '';
  var 우 = 숫자만(우편번호);
  return 이 + '|' + (우 || 'T' + 전화숫자(전화));
}
function 보조키(이름, 전화) {           // 우편번호 유무로 갈린 같은 사람을 잇는 열쇠 (§3-1 ②단계)
  var 이 = 이름키(이름);
  return 이 ? 이 + '|T' + 전화숫자(전화) : '';
}
function 안심번호인가(전화) { return /^050/.test(전화숫자(전화)); }
```

🔴 **구 프로그램 `customerHistory`의 키가 실제로 `"배성|27208"` 꼴이다**(백업 실측). 위 식과 같은 모양이라 539명 대조가 성립한다. 구분자 `|`를 바꾸면 대조가 깨진다.

### 1-3. 주문 → 고객 그룹 (핵심)

```js
function 그룹만들기() {
  var 순서 = [], 표 = {};
  저.읽기(저.키.주문).forEach(function (r) {
    var k = 사람키(r.수령인, r.우편번호, r.수령인전화);
    if (!k) return;                                  // 이름이 없는 줄은 버린다
    var g = 표[k];
    if (!g) { g = 표[k] = 새그룹(k, r); 순서.push(g); }
    얹기(g, r);
  });
  return { 순서: 순서, 표: 표 };
}
```

한 고객 객체의 모양 — **화면 셋(16b·16c·16d)이 전부 이 모양만 본다.**

| 칸 | 무엇 | 어떻게 |
|---|---|---|
| `키` | 사람키 | 위 함수 |
| `이름` `전화` `주소` `우편번호` | 사람 정보 | **가장 최근 주문줄의 값**으로 덮어 쓴다(이사·번호변경이 최신으로 보여야 한다) |
| `판매처들` | `['쿠팡','카페24']` | 나온 순서 그대로. 중복 없음 |
| `주문수` | 서로 다른 **주문일** 개수 | 🔴 같은 날 여러 건은 **1건**이다 — `08i-로젠파일.js:67` 재구매 규칙과 같은 셈이다 |
| `줄수` | 품목 줄 수 | 상세 표 줄 수 |
| `합계` | Σ `ZG.주문자료.금액(줄)` | 08a의 함수를 그대로 쓴다. 여기서 다시 곱하지 않는다 |
| `첫주문` `최근주문` | `min`/`max` 주문일 | 없으면 `''` |
| `손등록` | `주문수 === 0` | 🔴 **v3_고객 행이 있느냐가 아니다.** 메모만 단 온라인 고객에게 「손등록」이 붙으면 안 된다 |
| `안심` | `안심번호인가(전화)` | ⚠ 배지 |
| `메모들` | `[{날, 글}, …]` | `v3_고객`에서 얹는다 |
| `문자수` `문자들` | 받은 문자 | §1-6 |

- 정렬 — **최근주문 내림차순**, 주문 0건은 맨 뒤, 같으면 합계 내림차순
- 🔴 캐시를 두지 않는다. 1,287줄 한 바퀴는 그릴 때마다 돌아도 싼값이고, 캐시를 두면 주문·메모를 고친 뒤 옛 숫자가 남는다

### 1-4. 손등록 붙이기 — **확정 설계 §3-1 순서 그대로**

그룹을 다 만든 **뒤 한 번** 돈다.

```js
function 손등록얹기(뭉치) {
  var 보조 = {};
  뭉치.순서.forEach(function (g) { var b = 보조키(g.이름, g.전화); if (b && !보조[b]) 보조[b] = g; });

  저.읽기(저.키.고객).forEach(function (c) {
    var g = 뭉치.표[c.id]                              // ① 사람키가 같다
         || 보조[보조키(c.이름, c.전화)];              // ② 이름+전화가 같다 (우편번호 유무로 갈린 것 흡수)
    if (g) { g.메모들 = (c.메모들 || []).slice(); return; }
    var 새 = 새그룹(c.id, { 수령인: c.이름, 수령인전화: c.전화, 수령인주소: c.주소, 우편번호: c.우편번호 });
    새.메모들 = (c.메모들 || []).slice();               // ③ 주문 0건 고객으로 목록에 넣는다
    뭉치.순서.push(새); 뭉치.표[c.id] = 새;
  });
}
```

🔴 **주문이 이긴다** — ①②로 붙을 때 이름·전화·주소·우편번호는 **손대지 않는다.** `메모들`만 얹는다.

### 1-5. 읽기 · 필터

```js
function 목록(조건)   // 거른 고객 배열
function 하나(키)     // 목록 전체에서 한 명. 없으면 null
function 주문줄들(키) // 그 사람 주문 줄, 주문일 내림차순 (상세 표 · 엑셀용)
function 요약(것들)   // { 인원, 주문, 합계, 손등록, 안심 }
```

`조건` — 없는 칸은 안 거른다.

| 칸 | 값 | 뜻 |
|---|---|---|
| `글` | 문자열 | 이름·전화(숫자만도)·주소·우편번호 부분일치. `15a.읽기`와 같은 방식 |
| `부터` `까지` | `YYYY-MM-DD` | **그 기간에 주문이 하나라도 있는 사람만** 남긴다 |
| `최소주문` | 숫자 | `주문수 >= 값` |
| `최소문자` | 숫자 | `문자수 >= 값` |
| `판매처` | 문자열 | `판매처들`에 들어 있으면 통과 |
| `손등록만` | true | `손등록 === true`만 |

🔴 **기간은 거르개일 뿐 집계를 좁히지 않는다.** 표에 보이는 주문수·합계·최근주문은 **언제나 전체 이력**이다.
(필터마다 합계가 달라지면 같은 사람이 두 값으로 보인다. `15b` §4-② 「통계는 필터와 무관」과 같은 결이다)
🔴 **기간 기본값은 빈칸(전체)이다.** 시안의 `2026-01-01 ~ 2026-08-13`은 그림용이다 — 날짜를 미리 넣으면 주문 0건 손등록 고객이 첫 화면에서 사라지고 검증 ①(≒539명)이 안 맞는다.
🔴 **판매처 드롭다운 값은 데이터에서 뽑는다.** 실데이터의 `판매처`는 카페24 「쇼핑몰」 칸에서 그대로 온다(`08h:107`) — 시안의 여섯 값을 코드에 박으면 심폴·새 판매처가 안 나온다.

### 1-6. 문자 (`v3_문자`)

```js
{ id: 'ms_' + Date.now() + '_' + 난수, 보낸날: 'YYYY-MM-DD', 내용: '…', 받은이: [사람키, …], 등록일시 }
```

```js
function 문자전부()                       // 보낸날 내림차순 (같으면 등록일시 내림차순)
function 문자추가({ 보낸날, 내용, 받은이 })  // 저.덧붙이기(저.키.문자, …)
function 문자삭제(id)                     // 저.지우기
function 반응수(발송)                     // 「보낸 뒤 주문 M명」
```

사람별 색인 — 그룹을 만들 때 한 번만 돈다.

```js
// 🔴 발송 한 번이 한 줄이다. 사람마다 한 줄로 만들지 않는다 (확정 설계 §3-3)
// 🔴 받은이 키는 「그때의 키」다. 나중에 우편번호가 붙어 키가 갈려도 문자가 안 사라지게
//    자기 키와 보조키(이름|T전화) 둘 다로 찾아 발송 id 로 중복을 지운다.
```

`반응수(발송)` —

```js
var 끝 = 날더하기(발송.보낸날, 반응기간);   // 14일 고정
// 받은이 가운데, 보낸날 <= 주문일 <= 끝 인 주문이 하나라도 있는 사람 수
```

🔴 **보낸 당일 주문도 반응으로 센다.** 문자 보고 그날 넣는 것이 가장 흔하다.
🔴 캠페인 표·어트리뷰션을 만들지 않는다. 위 셈이 곧 반응률이다(확정 설계 §5).

### 1-7. 손등록 CRUD · 메모

```js
function 손등록추가({ 이름, 전화, 주소, 우편번호, 메모 })   // id = 사람키(이름, 우편번호, 전화)
function 손등록수정(키, { 이름, 전화, 주소, 우편번호 })
function 손등록삭제(키)
function 메모추가(고객, 글)        // 오늘 날짜 카드가 맨 아래에 붙는다
function 메모삭제(고객, 차례)
```

- `손등록추가` — 이미 같은 `id`가 있으면 **덮지 않고** `null`을 돌려준다. 화면이 「이미 있는 분입니다」 토스트를 띄운다
- `메모추가` — `v3_고객` 행이 없으면 **그 자리에서 만든다**(주문에서 파생된 고객에게도 메모를 달 수 있어야 한다). 만들 때 이름·전화·주소·우편번호를 같이 적어 둔다
- 🔴 `메모들`은 **새 배열을 만들어** `저.바꾸기`에 넘긴다. 읽은 배열을 그 자리에서 `push`하면 캐시 사본과 어긋난다
- `메모삭제(고객, 차례)` — `차례`는 화면이 방금 그린 배열의 자리다. **지운 뒤 반드시 다시 그린다.** 지우기 전 `u.확인`(위험:true)을 띄운다
- 메모 고치기는 **만들지 않는다**(확정 설계 §9)

### 2-2. 상세 뷰 (`상태.뷰 = '상세'`, 시안 PC ②)

## 7. Supabase — 🔴 **우람님이 대시보드 SQL Editor에서 먼저 돌리셔야 push한다**

여기서 실행하지 않는다. 7단계 설계 §1·§2와 같은 규격이다.

```sql
-- v3_고객 · v3_문자 (11단계 고객관리) — 7단계 설계 §1·§2와 같은 규격
do $$
declare t text; n text;
begin
  foreach t in array array['고객','문자']
  loop
    n := 'v3_' || t;
    execute format('create table if not exists public.%I (
        id text primary key,
        내용 jsonb not null,
        삭제됨 boolean not null default false,
        수정시각 timestamptz not null default clock_timestamp(),
        수정자 uuid default auth.uid())', n);
    execute format('drop trigger if exists 손댐 on public.%I', n);
    execute format('create trigger 손댐 before update on public.%I
        for each row execute function public.v3_손댐()', n);
    execute format('create index if not exists %I on public.%I (수정시각)', n||'_시각', n);
    begin
      execute format('alter publication supabase_realtime add table public.%I', n);
    exception when duplicate_object then null;
    end;

    execute format('alter table public.%I enable row level security', n);
    execute format('revoke all on public.%I from anon', n);
    execute format('drop policy if exists "로그인한사람만" on public.%I', n);
    execute format('create policy "로그인한사람만" on public.%I
        for all to authenticated using (true) with check (true)', n);
  end loop;
end $$;
```

- `수정시각` 기본값은 **`clock_timestamp()`**다(`7단계-남은것-SQL.sql`에서 고친 그것). `now()`로 만들면 두 기기가 부딪힐 때 값이 밀린다
- 표를 안 만든 채 `01b`만 push하면 **다른 표까지 안 내려온다**(표별 catch 방패가 있어도 노란 띠가 뜬다)

## 8. builder에게 — 지뢰 여덟

1. 🔴 **`08a`·`08b`·`08d`·`08h`·`08i`는 한 바이트도 안 건드린다.** 고칠 곳은 §5의 다섯 파일뿐이다
2. 🔴 **`묶음키`(`08a:40`)와 `사람키`(§1-2)는 다른 것이다.** 묶음키는 화면 합포장용이다 — 목적이 달라 그대로 둔다
3. 🔴 **050 안심번호는 사람키에 안 쓴다.** 우편번호가 있으면 저절로 전화를 안 탄다
4. 🔴 **빈 우편번호로 주문줄을 덮지 않는다**(§5-3 가드). 로젠 송장이 걸려 있다
5. 🔴 **이름을 가리지 않는다.** 시안의 `김OO`는 그림용이다 — 주문에 있는 **전체 이름 그대로** 보이고 저장된다
6. 🔴 **한 덩어리 저장 금지.** 메모는 `v3_고객` 한 줄 안 배열이고, 문자는 **발송 하나가 한 줄**이다. `저.전체쓰기`를 쓰지 않는다 — `덧붙이기`·`바꾸기`·`지우기`만 쓴다
7. 🔴 **탭을 3칸으로 고친 뒤 주문 조회·견적 요청이 멀쩡한지 먼저 본다**(확정 설계 §11-11). 여기가 깨지면 그날 업무가 멈춘다
8. 🔴 **다 만들면 확정 설계 §11 검증 11가지를 순서대로 돌린다.** 특히 ①(고객 수 ≒ **539명**)이 크게 벗어나면 사람키가 틀린 것이다 — 화면을 손보지 말고 §1-2로 돌아간다

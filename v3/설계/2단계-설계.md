## 2. 저장 구조 — 표를 나눈다

| 키 | 담는 것 | 자료형 | 나중에 갈 Supabase 테이블 |
|---|---|---|---|
| `zg.v3.주문` | 주문 한 줄 = **품목 하나** | 배열 | `order_lines` |
| `zg.v3.주문묶음` | 업로드 회차 | 배열 | `order_batches` |

**금지** — 한 주문건(수령인+여러 품목)을 객체 하나에 중첩해 넣는 것. 묶음은 **저장이 아니라 화면에서** 한다(§4).

### 2-1. 주문 한 줄 (`zg.v3.주문`)

| 필드 | 타입 | 예 | 비고 |
|---|---|---|---|
| `id` | string | `"od_ms8fi_ab3k9"` | `"od_"+Date.now().toString(36)+"_"+랜덤5` |
| `묶음id` | string | `"260804-01"` | 수동주문은 `""` |
| `주문번호` | string | `"20260731-0000050"` | 수동주문은 `""` |
| `주문일` | string | `"2026-07-31"` | **`YYYY-MM-DD` 외 금지** (§3) |
| `판매처` | string | `"카페24"` | 카페24·쿠팡·스마트스토어·전화주문·문자·직접방문·기타 |
| `품목코드` | string | `"ANW02-21"` | FK. 못 찾으면 `""` |
| `원본코드` | string | `"ech01-10"` | 엑셀에 적혀 온 그대로. 매칭 실패 추적용 |
| `유통명` `학명` `규격` | string | | 주문 시점 값을 **박아둔다** |
| `주문수량` | number | `2` | 엑셀 수량 그대로 |
| `옵션입수` | number | `4` | 없으면 `1` |
| `옵션원문` | string | `"수량=4개"` | |
| `단가` | number | `7900` | **주문서에 적힌 금액 그대로.** 매입×1.7 자동계산 아님 |
| `수령인` `수령인전화` `수령인주소` `우편번호` | string | | |
| `배송메모` | string | `"문 앞"` | |
| `묶음키` | string | `"김미정\|01024817735\|경기남양주시…"` | §4에서 만든 값을 저장해 둔다 |
| `출처` | `"업로드"`\|`"수동"` | | |
| `등록일시` | number | | `Date.now()` |

**저장하지 않는 계산값** — `수량 = 주문수량 × 옵션입수`, `금액 = 수량 × 단가`. 1단계에서 `현재고`·`금액`을 안 둔 것과 같은 이유다.
**주문 상태 필드는 없다.** 신규/출고준비/출고완료 같은 칸을 만들지 마라.

### 2-2. 주문묶음 (`zg.v3.주문묶음`)

`{ id:"260804-01", 올린날:"2026-08-04", 올린시각:"09:10", 회차:1, 파일명:"…xls", 줄수:14, 건너뛴수:2, 등록일시 }`
`id` = `YYMMDD-순번` (업무규칙 §5). 같은 날 다시 올리면 순번이 올라간다. `회차`는 그 날 안에서 시각 순.

### 2-3. 출고와의 연결

**주문을 넣는 것만으로 `zg.v3.출고`에 쓰지 않는다.** 상태 절차가 없으니 「나갔다」고 확정할 시점이 하나뿐이다 —
**⑤ 로젠 출력완료 → 배송완료 변환을 돌릴 때**, 그 파일에 실린 주문줄마다 `zg.v3.출고`에 한 건씩 덧붙인다.
`{ id, 출고일:"YYYY-MM-DD", 품목코드, 수량, 출처:"주문", 주문id }` — 1단계 §3-4 모양에 `주문id` 하나만 늘렸다.
그래서 **주문이 밀려도 재고는 줄지 않는다.** 출고리스트의 「재고부족」은 이 상태를 미리 보여주는 경고일 뿐 재고를 건드리지 않는다.

### 2-4. 설정 키 추가

`zg.v3.설정`에 `마지막주문경로`(수동주문 seg 기본값) 하나만 더한다. 조회 일자는 저장하지 않는다 — **늘 접속 당일로 연다.**

## 4. 묶기 · 검색 · 회차 (`08a-주문자료.js`)

**묶음키** = `이름 + "|" + 전화숫자만 + "|" + 주소(공백·하이픈 제거)`. 셋 다 같으면 화면에서 한 건이다.
🔴 **주문번호로 묶지 않는다.** 같은 사람이 두 번 주문해도 화면에서는 한 건으로 붙여 보여준다.

```
ZG.주문자료.날짜정규화(값)            → "YYYY-MM-DD" 또는 ""
ZG.주문자료.묶음키(줄)                → 위 규칙
ZG.주문자료.수량(줄)                  → 주문수량 × 옵션입수
ZG.주문자료.금액(줄)                  → 수량 × 단가
ZG.주문자료.읽기(조건)                → {부터, 까지, 묶음id, 글} 로 걸러 정렬된 줄 배열
ZG.주문자료.건으로묶기(줄들)           → [{묶음키, 수령인, 전화, 주소, 판매처, 줄들[], 총액, 부족여부}]
ZG.주문자료.회차목록(날짜)             → [{묶음id, 회차, 시각, 건수}]
ZG.주문자료.같은주문인가(새줄)          → 주문번호+품목코드+수령인 일치 (업무규칙 §5)
ZG.주문자료.출고리스트(줄들)           → [{품목코드, 유통명, 규격, 필요, 재고, 부족}] 품목코드별 합산
```

**검색** — 폰은 이름·전화·상품명, PC는 주소까지. 전화는 숫자만 남겨 비교(`010-2481-7735` ↔ `01024817735`).
**정렬** — 묶음키 등장 순(먼저 들어온 주문이 위). 한 건 안에서는 입력된 줄 순서 그대로.
**부족여부** — `ZG.계산.현재고(품목코드)` < 그 화면에서 합산한 필요수량. 이 값이 주문카드·PC행의 `.short`(빨간 표시)를 켠다.

## 5. 화면 (폰) — `08b` · `08c`

한 페이지 안에서 뷰 넷을 갈아 끼운다. `ZG.주문.열기('목록'|'수동'|'상세'|'출고')`, 뒤로가기는 `history.pushState` + `popstate`.

| 뷰 | 시안 | 내용 |
|---|---|---|
| **목록** | 폰1 | `.datebar` 화살표로 하루씩(기본 오늘) · `.topbtns` 3개 · `.search` · `.ph-card` 목록. 카드는 첫 2줄만 보이고 나머지는 `＋N개 더` |
| **수동주문** | 폰2 | 제목 **「수동주문」**. 경로 seg(전화·문자·직접방문·기타) → 받는 분·전화·주소 → 품목 자동완성 → 수량·단가 → 금액(읽기전용) → `주문등록` |
| **상세** | 폰3 | 「받는 분」 `.fold` 접기 · 품목 줄들 · **총액바 하단 고정**. 🔴 **고치기·삭제 버튼 없다** |
| **출고리스트** | 폰4 | **팝업이 아니라 페이지 전환.** 상단 `‹ 주문`으로 돌아온다. 그 날 조회된 줄 전체를 합산 |

**주문 카드** — `⭐N`은 그 수령인의 지난 주문 건수(`묶음키` 일치 건수, 1이면 안 보임 = 시안 그대로). `.mall`은 판매처. 부족이면 카드에 빨간 표시.
**＋N개 더** — 누르면 그 자리에서 펼친다(상세로 넘어가지 않는다). `.chev`나 카드 본체를 누르면 상세.
**자동완성** — `ZG.ui.후보찾기()`를 그대로 쓰되 접두 묶음을 **품목코드 단위로 펼쳐** 최대 8줄 보여준다(시안 `ANW02` / `ANW05` 처럼 규격·재고가 줄마다 붙는다). 재고는 `ZG.계산.현재고`. **새 품목코드를 만들지 않는다** — 목록에 없으면 「상품 화면에서 먼저 등록해 주세요」 토스트.
**저장** — `ZG.저장소.덧붙이기('주문', 줄)` 한 건. 같은 날·같은 수령인·같은 품목코드가 이미 있으면 `ZG.ui.확인`으로 한 번 묻는다.

## 6. 화면 (PC) — `08b` · `08c`

시안 그대로. 좌 사이드바 + `.pc-head`(주문 관리 / 주문 › 주문 조회) + 머리줄 버튼 4개 + `.fchips` + 표 + `.tbar` + `.pager`.

- **기간** — 시작·끝 날짜 + `오늘`·`이번 주`·`이번 달` 칩. 기본 오늘~오늘
- **회차 필터** — `전체` / `1회차 09:10` / `2회차 13:40`. 그 날 `주문묶음`에서 만든다. 수동주문은 회색 `직접입력` 배지
- **표** — 한 줄 = 품목 하나. 같은 묶음키는 `rowspan`으로 받는 분·주문한 곳·체크박스를 합친다. 첫 줄에 `.gstart`
- **체크박스** — 건 단위(그 건의 모든 줄이 함께 켜진다). `.tbar`에 「고른 것 N건」
- **엑셀로 내려받기** — 고른 것이 있으면 그것만, 없으면 화면에 보이는 전체 (§7)
- **출고리스트** — `.pcsheet` 창으로 뜬다(폰과 계산 함수는 같다). 인쇄 버튼 글자는 **「인쇄」**, `window.print()` + `@media print`로 창 안만 남긴다
- **동봉카드** — §9-3

## 7. 엑셀 (`08d-주문파일.js`)

🔴 **선행조건 — builder는 코드를 짜기 전에 우람님께 실제 파일 3개를 받는다.** ① 카페24 주문 내려받기 ② 로젠 대량등록 양식 ③ 로젠 출력완료. 칸 이름을 눈으로 확인하기 전에는 매핑을 지어내지 않는다.

**라이브러리** — `js/lib/xlsx.min.js` (SheetJS CE). **v3의 유일한 외부 라이브러리이고, 이번에 처음 넣는다.** 근거: 카페24·로젠 모두 `.xls`를 주고받아 CSV로는 우람님이 매번 손으로 변환하셔야 한다. **CDN을 쓰지 않고 파일을 저장소에 넣는다**(GitHub Pages에서 외부 의존 없이 열려야 한다). 다른 라이브러리는 넣지 않는다.

**① 카페24 → 로젠 파일**
읽기 → 칸 이름으로 매핑 → 정규화(§3) → `zg.v3.주문` 덧붙이기 + `zg.v3.주문묶음` 한 건 → 로젠 양식 파일 내려받기.
**칸 이름을 하나라도 못 찾으면 저장하지 않고 멈춘다** — 「이 파일에서 못 찾은 칸: …」을 띄운다.
결과창: `넣은 줄 N · 이미 있어 건너뛴 줄 N · 품목을 못 찾은 줄 N(코드 나열)`.

**② 로젠 출력완료 → 카페24 배송완료** (업무규칙 §5)

| 1칸 | 2칸 | 3칸 | 4칸 |
|---|---|---|---|
| 주문번호 | (비움) | 운송장번호 | 박스수량 |

**박스수량이 1이면 비운다.** 이때 `zg.v3.출고`를 함께 쌓는다(§2-3).

**③ 엑셀로 내려받기** — 화면 표의 칸 그대로(받는 분·전화·주소·주문한 곳·품목코드·품목·규격·수량·단가·금액). 파일명 `주문_YYYY-MM-DD.xlsx`.

## 8. 만들지 않는 것

- 주문 **수정·삭제** — 폰·PC 어디에도 없다. 업로드가 잘못되면 그 묶음을 통째로 지우는 것도 2단계에서는 만들지 않는다
- 주문 상태 칩 · 일괄 상태변경 · 재고 부족 시 저장 막기
- 고객 마스터 표 — `⭐N`은 `zg.v3.주문`을 세어 만든다. 별도 표를 만들지 마라
- 명세서·소싱과의 연결

## 9. 우람님 수정 4건 — 시안(8/4 13:40)과 다른 곳

1. `＋ 수동주문`으로 여는 화면 제목은 **「수동주문」** (시안 폰2 제목 그대로 확정)
2. **출고리스트는 팝업이 아니다.** 폰은 별도 화면(`‹ 주문`으로 복귀), PC만 시안의 `.pcsheet` 창
3. 🔴 **동봉카드는 만들지 않는다.** 버튼 3곳(폰 상단 · 폰 상세 총액바 · PC 머리줄)은 **자리만 두고 눌러도 아무 일이 없다.** `aria-disabled="true"` + 흐리게 — 1단계에서 죽은 메뉴를 처리한 방식과 같다. 기존 통합관리 형태를 나중에 개선하실 예정이라 지금 손대지 않는다
4. 인쇄 버튼 글자는 **「인쇄」** (`🖨 출력` 아님)

## 10. 다 만든 뒤 직접 눌러볼 것 (`dev-checker` 넘기기 전)

1. 폰에서 **한글을 실제로 타이핑**한다 — 수동주문의 받는 분·주소·품목 세 칸. `휴케라`가 `ㅎㅠㅋㅔㄹㅏ`로 깨지지 않는지 (8/4 사고)
2. 같은 파일을 **두 번 올린다** → 둘째 번은 전부 「건너뛴 줄」이어야 한다
3. `5/13/26` 형식이 섞인 파일 → 그 줄이 건너뛴 목록에 뜨고, 저장된 주문일은 전부 `YYYY-MM-DD`인지
4. 이름·전화·주소가 같은 주문 두 건 → 폰 카드 1장, PC 표 rowspan 1묶음인지
5. 쿠팡 `수량=4개` × 주문 2 → 수량 8, 작은 글씨 `2 × 4개입`
6. 재고 0인 품목 주문 → 카드 빨간 표시 + 출고리스트 「재고부족」. **저장은 막히지 않아야 한다**
7. 동봉카드 버튼 3곳을 눌러 **아무 일도 안 일어나는지** (에러도 안 난다)
8. 탭 두 개를 열고 한쪽에서 수동주문 저장 → 다른 쪽이 다시 그려지는지 (`storage` 이벤트)

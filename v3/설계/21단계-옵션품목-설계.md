# 21단계 — 옵션이 품목인 상품 설계 (시안 `20-옵션품목-macA.html` 컨펌)

새 표·새 칸·SQL 없음. 짝 id 글자만 `원본코드§옵션값`으로 늘어난다. 화면 결·톤은 시안 그대로, 08k 짝창·08b 목록의 패턴을 넓힌다.

## 1. 열쇠는 한 곳에서만 만든다 — `ZG.짝.옵션풀이(원본코드, 옵션원문)` (08j, 짝표 위)
돌려줌 `{ 열쇠, 품목옵션, 옵션이름, 옵션값, 표시값, 입수 }`. 08h·08k·08b·08c는 이것만 부른다(정규식을 옮겨 적지 않는다).
1. 축 나누기 `원문.split(/\s*,\s*(?=[^,=]+=)/)` — 쉼표 뒤에 `이름=`이 올 때만 자른다(값 속 쉼표는 안 자름). 빈 원문 → 축 없음
2. 축 풀기 `/^\s*([^=]*?)\s*=\s*(.*)$/` → 이름·값. `=`이 없으면 이름 `''`, 값 = 통째
3. 꼬리 개수 `/\s*[(（]\s*(\d+)\s*개\s*[)）]\s*$/` — 반각·전각 괄호 둘 다. 떼어 낸 나머지에 `/\s+/g→' '`, trim = **알맹이**
4. **개수 축** = 아래 하나라도 참. 나머지는 **품목 축**
   - 이름(공백 지움) `=== '수량'` (실값 `수량=15cm화분 (1개)`도 개수다)
   - 알맹이 `''` · `/^\d+\s*(개|주|구|포기|묶음|세트|팩)?$/` · `/^(단일상품|단품|기본)$/`
   - 규격만 `/^\d+(\.\d+)?\s*(cm|mm|센치)?\s*(화분|포트)?$/i` (실값 `옵션=10cm화분 (4개)`·`사이즈=10cm화분 (2개)`)
5. 품목 축 0개 → `열쇠 = 원본코드`, `품목옵션 false`. 1개 이상 → `옵션값 = 알맹이들.join(' / ')`, `열쇠 = 원본코드 + '§' + 옵션값`. 원본코드 빈칸 → 열쇠 `''`(지금처럼 짝 불가)
6. `입수` — ① `수량=N개` 축 ② 첫 꼬리 `(N개)` ③ 개수 축 알맹이 `N개` 순, **하나만**. 없으면 0(부르는 쪽이 코드꼬리→1)
7. `옵션이름`·`표시값` = 품목 축의 이름·원문 값(꼬리 포함, `, `로 잇기) — 화면 표시용. 번호(`2.`)는 열쇠에 남긴다(우람님 결정 1 그대로)

| 원문 | 열쇠 | 입수 |
|---|---|---|
| `수량=3개` · `사이즈=1개` · `옵션1=단일상품` · `''` | 원본코드 | 3 · 1 · 0 · 0 |
| `품종 선택=2. 튤립 티스부츠 （5개）` | `GGM01-0§2. 튤립 티스부츠` | 5 |
| `색상=3.휴케라 라임리키` | `HEU01§3.휴케라 라임리키` | 0 |
| `옵션=긴산꼬리풀 알바 10cm화분 (2개)` / `(4개)` | 둘 다 `…§긴산꼬리풀 알바 10cm화분` | 2 / 4 |
| `색상=흰꽃, 사이즈=1개` · `색상=흰꽃, 사이즈=대` | `…§흰꽃` · `…§흰꽃 / 대` | 1 · 0 |

🔴 실데이터(옛 백업 옵션 36종) 중 `사이즈=에린지움 블루캅 10cm (2개)`·`컬러 및 사이즈=노란 꽃 (4개)`·`색상=보라꽃`도 품목 옵션으로 잡힌다 — 옛 짝이 있으면 옵션당 「예전 짝 쓰기」 한 번씩 누르셔야 붙는다(의도된 값).

## 2. 짝 찾기 — `ZG.짝.짝찾기(줄, 색인)` (08j). `색인 = 짝색인()` = id→짝 레코드
- 품목옵션 아님 → `색인[원본코드]` (지금 그대로)
- 품목옵션 → `색인[원본코드]`에 `옵션무시:true`면 그것, 아니면 `색인[열쇠]`만. **옛 짝(id=원본코드, 표시 없음)은 안 쓴다 → 빈칸**
- 짝 레코드 내용에 칸 둘 추가(jsonb 안이라 SQL 없음): `옵션값`(표시용) · `옵션무시`(「옵션 구분 없이 하나로」로 지은 짝만 true)
- id 확인: PK는 `id`(01:58 `키필드`) — `아이디()`의 품목코드 폴백 안 탄다. 서버는 JSON 본문 upsert(01c:73 `onConflict:'id'`)·삭제도 upsert(01c:71), 큐 열쇠 `표|id`는 붙이기만 하고 쪼개지 않는다(01c:20·63, 01b:256) → `§`·한글·공백·`/` 문제없음

## 3. 되붙이기 규칙과 부딪치는 곳 (08j:127 주석)
- 🔴 **원본코드가 v3 마스터에 곧장 맞으면(코드정규화 결과가 마스터에 있으면) 옵션과 상관없이 그 품목을 쓴다 — 21단계 전과 똑같이**(옵션마다 자체품목코드가 따로인 카페24 `HEL01-15`+「색상=3.휴케라 라임리키」 등 ~180줄, 입수도 옛 규칙). 옵션 열쇠 `원본코드§옵션값`은 **원본코드가 마스터에 없을 때만**(`GGM01-0`·쿠팡 `HEU01`) 쓰고 그 줄만 줄만들기에서 품목=null로 짝을 기다린다. 판정은 08j `ZG.짝.줄풀이(줄, 마스터)` 한 곳 — 08h·08j·08k·08b·08c는 이것만 부른다. 「예전 짝 쓰기」는 `색인[원본코드]`를 내민다
- 심폴·당근 「짝이 전부」: 품목옵션 줄에 옛 짝만 있으면 **비운다**(결정 2). 미리보기 객체만 바뀌고, 저장된 줄은 `저장된줄되붙이기`가 빈칸만 메우므로 이미 붙은 줄은 안 지워진다
- 그 밖 판매처 「붙은 줄 안 덮음」: 유지. 그래서 잘못 붙은 HEG01-15 줄은 결정 6대로 그대로 남는다

## 4. 옵션입수 — 누가 이기나
- 짝 전: `풀이.입수 || 코드꼬리 || 1` (08h:111 `옵션입수()`는 이것으로 바꾸고 지운다)
- 짝 후 쿠팡: 옵션 쪽 그대로(지금과 같음)
- 짝 후 **개수 옵션 줄**: `판매단위`(지금과 같음 — 9/28 결정 안 건드림)
- 짝 후 **품목 옵션 줄**(쿠팡 외): **`max(판매단위||1, 풀이.입수||1)`** — 판매단위 1·`(5개)` → 5 · 판매단위 5·`(5개)` → 5(25 아님) · 판매단위 2·`(4개)` → 4. **곱하지 않는다**(08h:109 이중곱 금지). 코드꼬리는 짝 후에 안 본다
- 이 계산은 08j `입수정하기(줄, 품목, 풀이)` 하나에 두고 되붙이기·저장된줄되붙이기·08h가 같이 쓴다

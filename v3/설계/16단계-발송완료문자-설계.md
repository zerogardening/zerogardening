## 2. 파생 — 「발송완료」와 자동 송장

**대상 줄** (이 문자주문이 만든 주문 줄)
```
v3_주문 중  문자주문id === r.id
       또는 (주문번호 === r.올린주문번호 && 판매처 === '문자')   ← 주문탭에서 나중에 더한 줄도 잡는다
그중 서비스 !== true
```
- `올린주문번호`가 비면 `문자주문id`로만 찾는다. 판매처 조건은 같은 모양 번호의 남의 주문(시험 시드 `전화주문 YYMMDD-05`)을 막는다.
- 주문을 주문탭에서 지우면 로컬에서 빠진다(01-저장소 `지우기`가 splice) → 대상에서 저절로 빠진다.

**나간 줄** = 대상 줄 중 `출고`에 `출처==='주문' && 주문id===줄.id`가 있는 것. (`출처==='서비스'` 출고는 안 본다 — 08f `주문출고찾기`와 같은 기준)

| 판정 | 기준 |
|---|---|
| **발송완료** | `상태==='올림'` 이고 **나간 줄이 하나라도 있다** |
| 주문올림(지금 그대로) | 올림인데 나간 줄이 없다 |
| 저장·보냄 | 지금 그대로 — 발송완료가 될 수 없다(단추도 없다) |

- **일부만 나간 때** — 로젠 길은 한 주문번호의 줄을 한꺼번에 깎으므로(08f 넘길줄만) 일부만 나가는 일은 「수량 0·품목코드 없음·나중에 더한 줄」뿐이다. 송장이 나왔으면 택배는 떠난 것 → **하나라도 나가면 발송완료**로 본다. 대신 **문자의 품목 줄은 나간 것만** 적는다(§4). 화면에 「일부」 표시는 없다(시안에 없음).
- **배송완료 되돌리기**(08n 되돌리기·08g 되돌리기)로 출고가 지워지면 카드는 저절로 「주문올림」으로 돌아간다. `발송문자보냄일시`·`손송장`은 남지만 발송완료일 때만 보이므로 문제 없다. 다시 배송완료되면 그대로 되살아난다.

**자동 송장** = 나간 줄들의 출고 `운송장번호`, 빈 값 빼고 겹친 것 빼고, 출고 `등록일시` 순.
- **합포장** — 08f `합포장형제`가 형제 주문에 같은 `운송장번호`를 실어 판정하고(08f:204), 08g가 그 값을 출고에 넘긴다(§6) → 형제 주문 카드마다 같은 송장이 보인다. 따로 할 것 없음.
- **송장 둘(박스 나눔)** — 같은 주문번호의 둘째 로젠 줄은 08f가 「이미」로 걸러 출고를 안 만든다 → 자동은 **첫 송장만**. 둘째는 손으로 더한다(§5).
- **손처리(08n)** — 출고에 `수동:true`만 있고 송장이 없다 → 자동 송장 `[]` → 「송장 없음 + 입력칸」.

**보이는 송장** = `Array.isArray(r.손송장) ? r.손송장 : 자동송장`

**🔴 손송장 저장 규칙 (손이 자동을 덮는 법)**
1. 입력칸 값들을 `숫자만` → 빈 것 빼기 → 겹친 것 빼기(순서 유지).
2. 결과가 **지금 자동 송장과 같으면 `손송장: null`** — 손대지 않은 것으로 돌린다(자동을 계속 따른다).
3. 다르면 그 배열을 그대로 `손송장`에. **빈 배열 `[]`도 저장한다** = 「자동 송장을 지웠다」(로젠 건에서 다 지우면 문자에 송장 줄이 빠지고 카드는 「송장 없음」).
4. 손송장이 있는 뒤에 자동이 바뀌어도(되돌렸다 다시 처리) **손이 이긴다.** 손 값을 다시 자동과 같게 맞추면 2번으로 풀린다.

**갱신 신호 — 따로 만들지 않는다**
- 다른 기기에서 배송완료 → `출고` insert → 이미 걸린 `v3-전체` 채널(01b:244)이 `그리기예약` → `ZG.주문.다시그리기` → 문자주문 탭이 켜져 있으면 20c가 다시 파생한다. **01b 안 고침.**
- 같은 기기 — 배송완료 창(08g)·손처리(08n)는 「주문 조회」 탭 안에서만 열린다. 문자주문 탭으로 넘어오는 순간 `탭으로` → 다시그리기. **08n 안 고침.**
- 송장칸에 치는 동안은 01b `치는중()`이 남의 다시그리기를 미뤄 준다(치던 글 안 날아감).

## 3. `20a-문자주문자료.js` — 더할 함수

| 함수 | 하는 일 |
|---|---|
| `발송색인()` | 한 번에 만든다: `{ 문자id별: {smid:[주문줄]}, 번호별: {주문번호:[판매처 '문자' 주문줄]}, 출고별: {주문id:[출고(출처 '주문')]} }`. 🔴 카드마다 저장소를 읽지 않는다(08f 색인만들기와 같은 이유 — O(n²)) |
| `발송정보(r, 색인)` | 올림 아니면 `null`. 아니면 `{ 됨, 자동송장:[], 송장:[], 손: bool, 나간품목:[{유통명, 규격, 수량}] }`. `색인` 없으면 스스로 만든다 |
| `발송문자내용(r, 정보)` | §4 글 |
| `발송문자표시(id)` | `상태!=='올림'`이면 `null`. `{발송문자보냄일시: 이제, 수정일시: 이제}` 바꾸고 `하나(id)` |
| `손송장저장(id, 값들)` | `상태!=='올림'`이면 `null`. §2 손송장 저장 규칙(자동은 `발송정보(하나(id))`로 새로 구한다). `{손송장, 수정일시}` |
| `거르기` (고침) | 숫자 검색일 때 **송장도** 찾는다 — `숫자열쇠.length >= 3` 이고 올림 줄의 `발송정보().송장` 중 하나에 들어 있으면 참. 색인은 검색할 때만 한 번 만든다 |

`ZG.문자주문자료`에 `발송색인·발송정보·발송문자내용·발송문자표시·손송장저장`을 더 낸다. 기존 이름은 그대로.

**나간품목 짓기** — 나간 줄을 품목코드로 모아 수량 = 그 줄들 출고 `수량` 합(재고에서 실제로 빠진 수 — 주문탭에서 수량을 고쳤어도 맞다).
순서 = `r.품목` 순서, 거기 없는 코드는 뒤에. 이름·규격 = `r.품목`의 같은 코드 → 없으면 주문 줄 `유통명`·`규격`. 다 나간 보통 건이면 `r.품목`과 똑같이 나온다.

## 4. 문자 글

```
🌱 [제로가드닝]
{받는분} 님 주문하신 상품을 보냈습니다        ← 받는분 비면 「주문하신 상품을 보냈습니다」

· {유통명} {규격} {수량}개                     ← 나간품목 한 줄씩. 규격 비면 「· {유통명} {수량}개」
· …

로젠택배 {송장}                                ← 보이는 송장마다 한 줄
```
- 송장이 없으면 **로젠택배 줄들과 그 앞 빈 줄을 통째로 뺀다**(시안 「송장 비움」 — 품목 줄로 끝난다).
- 금액·합계·계좌는 **안 넣는다**(시안 4종 그대로). 수량은 `u.콤마`.
- 받는분은 `r.받는분` 다듬은 값(올릴 때 이름이 필수라 보통 있다 — 시안 「받는 분 없음」은 옛 줄·지운 경우 대비).
- 보내기: `문자열기(r.전화, 글)` **그대로**(PC는 복사 후 열기). 전화가 `문자되나` 아니면 단추 `disabled`(앞 설계 §8-2와 같은 규칙).

- 🔴 남의 저장으로 다시 그려져도 고치던 값이 `상태.송장고침`에 있어 되살아난다(앞 설계 §8-7과 같은 꾀). `목록으로`·`새문자로`·`나가기`·`날짜고르기`·`달로`·검색 바꿈에서 `상태.송장고침 = null`.

## 8. 위험 · 가정

1. 🔴 **08g를 고친다** — 실서비스 배송완료 창이다. 바꾸는 건 출고에 칸 하나 더 싣는 것뿐(덧은 08f가 이미 받는다). 다른 줄은 손대지 않는다.
2. 08g 수정 **전에** 배송완료된 문자주문은 자동 송장이 없다 → 「송장 없음」으로 뜨고 손으로 넣는다.
3. 일부만 나가도 발송완료로 본다 — 문자는 나간 품목만 적는다. 남은 줄이 따로 나가면 「다시 보내기」로 같은 문자(그때 나간 전부)가 다시 나간다.
4. 송장 사업자는 로젠 하나로 박는다(문자·화면 「로젠택배」). 다른 택배를 쓰게 되면 그때 칸을 더한다.
5. 손송장은 숫자만 남긴다 — 하이픈 붙여 붙여넣어도 숫자로 저장된다.

### 2-1 🔴 시안과 지시가 어긋나는 곳 — dev-manager 확인 필요

### 2-2 데이터 — `v3_문자주문.내용`에 두 칸 (SQL 없음)

| 칸 | 값 | 언제 씀 |
|---|---|---|
| `원문주소` | 손님이 보낸 주소 글(주소칸 값) | 찾기 단추를 누를 때. 이미 있고 주소칸을 손으로 안 고쳤으면 **덮지 않는다** |
| `주소확인` | `'일치'` · `'고름'`(다른데 이 주소로 사용) · `'미확인'`(원문 그대로 두기) · `'비교안됨'` · 없음 | 찾기 결과가 정해질 때 |

- 「미확인」 칩은 `주소확인 === '미확인'`일 때만, 다시 그려도 저장값에서 되살린다. ✓줄·노란줄은 그 자리 한 번만(저장값으로 다시 그리지 않는다).
- 기존 23건+ 줄에는 두 칸이 없다 → 칩 없음, 찾기를 누르면 그때 주소칸 값을 원문으로 잡는다.
- `v3_주문` 줄에는 칸을 늘리지 않는다. 주문올리기를 막지 않는다.

**20a `다듬기`** — `예약` 칸과 같은 방식: **`'원문주소' in 값`일 때만** 싣는다. 안 넘기면 `고치기`가 기존 원문을 빈칸으로 덮는다(20c 사본이 옛 모양일 때).

### 2-3 비교 함수 — `ZG.주문입력.주소비교(원문, d)` (`08c`, DOM 안 씀)

- **원문 쪽** — 정규식으로 첫 「도로명 + 건물번호(-부번)」를 뽑는다. 도로명은 `…로`/`…길`로 끝나고 `…로 112번길`·`…대로23길`·`…로12번안길`처럼 띄어 쓴 번길도 한 덩어리. 뒤에 숫자가 와야 한다(`서종면`·`문호리 683-2`는 안 걸린다). 비교 때 도로명 공백은 없앤다.
- **카카오 쪽** — 🔴 **`d.buildingMainNo`·`d.buildingSubNo`는 카카오 우편번호 데이터에 없다**(postcode.map.kakao.com/guide 확인, 건물 칸은 `buildingCode`·`buildingName`뿐). `d.roadAddress || d.autoRoadAddress`에 **원문과 같은 정규식**을 돌려 도로명·번호를 뽑고, 뽑은 도로명이 `d.roadname`(공백 없앰)과 같은지 맞춰 본다. 다르거나 못 뽑으면 `불가`.
- **판정** — 도로명 **전체가 같고**, 본번이 같고, 부번이 같으면(없음 = 없음, `112` vs `112-3`은 다름) `일치`. 하나라도 다르면 `다름`. 한쪽이라도 못 뽑으면 `불가`. 원문이 빈칸이면 `없음`(아무 표시 없이 지금처럼 채운다).

돌려주는 것: `{ 결과, 원문조각:{시작,끝}, 고른조각:{시작,끝}, 고른글, 꼬리, 지번 }`
- `조각` = 빨간 강조할 자리(도로명+번호 덩어리 — 시안대로 덩어리째 강조)
- `꼬리` = 원문에서 번호 뒤 나머지, 앞 `,`·공백 떼고 (`2층`)
- `지번` = `d.jibunAddress || d.autoJibunAddress`에서 `d.sido`·`d.sigungu`를 뗀 것 (`서종면 문호리 683-2`)

### 2-4 흐름 — `08c 주소찾기(주소, 우편, 설정)` · `주소줄(주소, 우편, 설정)`

`설정`은 선택. `{ 대상, 상세 }` — `대상`은 원문주소·주소확인을 읽고 쓰는 객체(20b 상태 · 20c/20d 사본), `상세`는 상세주소 칸. 없으면 08c가 닫힌 빈 객체를 쓴다(수동주문, 저장 안 됨).

1. **누름** — `주소`에 `input`이 있었으면(손댐 표시) 또는 `대상.원문주소`가 비면 `대상.원문주소 = 주소.value.trim()`. 그다음 지금처럼 embed(`q`도 지금처럼).
2. **oncomplete(d)** — embed 판을 닫고 `주소비교(대상.원문주소, d)`.
3. **일치** — 지금처럼 채운다. 꼬리는 `상세`가 있고 비었으면 거기, `상세`가 없으면(08c) 주소 끝에 `글 + ' ' + 꼬리`. 주소줄 아래 `.확인줄.맞음`(✓ 원문과 일치 / 도로명 / 지번). `주소확인='일치'`, 칩 지움.
4. **불가** — 지금처럼 채운다(막지 않음). `.확인줄.비교안됨`(! 원문 비교 안 됨 / 원문 / 지번). `주소확인='비교안됨'`.
5. **없음** — 지금 동작 그대로. 표시 없음.
6. **다름** — **아직 채우지 않고** 확인창 `주소확인창(비교, 그때)`:
   - `다시 찾기` → 1의 embed를 `q = d.query`로 다시 연다(원문은 그대로). 거기서 ✕로 닫으면 아무것도 안 바뀐다.
   - `원문 그대로 두기` · Esc · 바깥 누름 → 주소칸·우편 안 건드림. `주소확인='미확인'`, 라벨 옆 「미확인」 칩.
   - `이 주소로 사용` → 지금처럼 채운다(꼬리는 안 잇는다 — 다른 건물이라 동·호수를 사람이 다시 본다). `주소확인='고름'`, 칩 지움.
7. 채운 뒤 focus 돌려주기는 지금 그대로 → 20b `상세로넘기기`가 그 focus로 값을 맞춘다. 「원문 그대로 두기」는 값이 안 바뀌어 상세로 안 넘어간다(맞음).

**확인창은 08c 안 함수**로 만든다. `u.확인`은 단추가 둘이라 못 쓴다. 틀은 `u.확인`(04:81)을 그대로 따라 한다 — 두 겹 금지(`.askbox` 있으면 안 뜸), Tab 가두기, 닫을 때 포커스 되돌림. Esc를 `.askbox`가 먼저 먹는 규칙(04:383)도 그대로 맞는다. 본문은 `u.안전`으로 감싼 조각 사이에 `<span class="다름">`.

**칩 자리** — 칩은 라벨 안이라 08c 주소줄 밖이다. `주소줄`이 돌려주는 요소에 `줄.칩`(span, 기본 숨김)을 달고, 20b에 `주소밭(라벨, 줄, 스타일)` 하나를 만들어 `밭()` 뒤 label에 `줄.칩`을 붙인다. 20b·20c·20d의 `밭('주소…', …줄)` 6곳을 이것으로 바꾼다.

### 2-6 08c 수동주문 · 주문수정 — 판단

**비교·확인창·✓줄·노란줄은 그대로 쓴다. 원문 저장·「미확인」 칩은 없다.**
- 같은 부품이고, 전화로 받아 적은 주소도 「번지 하나 틀림」이 똑같이 송장에 찍힌다 — 막을 값어치가 같다.
- 저장은 하지 않는다 — `v3_주문`은 품목 단위 줄이라 칸을 늘리면 줄마다 복사되고, 지시 범위 밖이다. 「원문 그대로 두기」는 그냥 닫힘.
- 주문수정을 열면 주소칸이 이미 카카오 주소인 경우가 많다 → 그것이 원문이 되어 대개 `일치`. 해가 없다.

## 0. 이 기능이 여는 문 — 재고가 드디어 줄어든다

`03-계산.js 현재고()`는 `zg.v3.출고`만 읽는다. 지금 v3에서 출고가 생기는 길은 **서비스 품목뿐**(6단계-3)이다.
**일반 주문은 아직 한 번도 재고를 깎지 않았다.** 그 마지막 연결이 이것이다 — 2단계 설계 §2-3이 자리를 비워 둔 그 자리다.

**재고 차감의 근거는 로젠 파일이 아니라 v3 주문줄(`zg.v3.주문`)이다.**
로젠 파일은 「어느 주문번호가 실제로 나갔나」를 알려주는 **신호**로만 쓴다. 품목코드·수량은 언제나 주문줄에서 가져온다.
(로젠 AI열에 물품코드가 실려 오지만 쓰지 않는다 — 합포장이면 `ECC02-10/ECH02-10`처럼 슬래시로 붙어 오고 빈 줄도 있다.)

## 2. 로젠 「출력완료」 파일 읽기 (`08f`)

실물(`백업/주문등록_출력(복수건)_출력완료(5)건 …xlsx`)로 칸 위치를 확인했다. **1행 제목 · 2·3행 머리글 두 줄 · 4행부터 데이터.**

| 뽑을 것 | 열 | 실제 값 |
|---|---|---|
| 운송장번호 | **D**(4) | `44894114473` (하이픈 없음 — 화면에도 온 그대로 찍는다) |
| 수하인 이름 | **G**(7) | `이선열` — 2행이 `수하인`, 3행이 `이름`인 두 줄 머리글 |
| 박스수량 | **L**(12) | `1` |
| 주문번호 | **S**(19) | `20260804-0000025` · **전화주문이면 빈칸** |

```
ZG.배송완료.머리찾기(행들)   → 머리줄index | -1        // 0~5행 안에서 [3]='운송장번호' 이고 [18]='주문번호' 인 마지막 줄
ZG.배송완료.읽기시트(행들)   // 행들 = 시트배열()이 준 2차원 배열
  → { ok, 오류, 총: n, 무시: n, 줄들: [ {순번, 운송장번호, 수하인, 박스, 주문번호} ] }
```

- 🔴 **「4행부터」를 index로 박지 않는다.** `머리찾기()`로 머리글 줄을 찾고 **그 다음 줄부터** 돈다.
  0~5행 안에서 머리글 이름(공백·개행 제거 후)이 자리에 맞는 **마지막** 줄이 머리글이다 — 실물은 2·3행 둘 다 걸리므로 3행이 잡힌다.
  로젠이 제목 줄을 하나 늘려도 안 깨진다.
- 🔴 **못 찾으면 아무것도 하지 않고 멈춘다** — `ok:false`, `오류:'로젠 「출력완료」 파일이 아닌 것 같습니다 — S열이 주문번호가 아닙니다.'`
  2단계 설계 §7의 「칸을 하나라도 못 찾으면 저장하지 않고 멈춘다」 그대로다. **이 검사가 없으면 엉뚱한 엑셀을 골랐을 때 전 줄이 「확인 필요」로 떨어지고, 「전부 이름으로 찾기」 한 번에 남의 재고가 깎인다.**
- 값은 전부 `String(v==null?'':v).trim()`, 박스는 `Number(String(v).replace(/,/g,''))||1`.
- 🔴 **주문번호·운송장번호가 둘 다 비면 그 줄 자체를 무시**한다(`무시`에 셈). 실물 파일 **마지막 「합계」 줄이 여기서 걸러진다** — 이 줄이 안 걸러지면 결과 숫자가 늘 하나씩 많다.
- **운송장번호는 있고 주문번호만 빈 줄은 무시가 아니다.** 「확인 필요」로 화면에 띄운다(§4).
- `시트배열`은 `XLSX.read(…,{type:'array'})` → `sheet_to_json(ws,{header:1, defval:'', raw:true})`.
  🔴 **`raw:true`다. `raw:false`·`blankrows:false`를 쓰지 않는다.**
  실물 파일을 열어 확인한 것 — **D열(운송장번호)·S열(주문번호)은 이미 문자열 셀(`t="s"`)이고, 숫자인 것은 L열(박스수량)뿐인데 그 서식이 `#,##0`(천단위 쉼표)다.**
  `raw:false`는 서식을 입힌 글자를 주므로 **숫자 칸에 쉼표가 붙는다.** `blankrows:false`는 빈 줄을 지워 **행 번호를 밀어 버린다.**

## 3. 주문번호 → v3 주문줄 매칭 · 방패 (`08f`)

```
ZG.배송완료.주문찾기(주문번호, 색인)      → [주문줄]      // 빈 주문번호면 []
ZG.배송완료.색인만들기()                  → {주문번호별:{}, 이미나감:{}}   // 한 번만 만든다
ZG.배송완료.넘길줄만(주문줄들, 색인)      → { 넘길:[줄], 걸린:[{줄, 사유}] }
ZG.배송완료.출고넣기(주문줄들, 출고일)    → [만든 출고 id]
ZG.배송완료.출고되돌리기(출고id들)        → 지운 개수
```

**한 주문번호에 품목줄이 여럿일 수 있다** — 합포장 한 송장 = 주문줄 N개다. `주문찾기`는 **언제나 배열**을 돌려주고, 출고줄은 **주문줄 하나당 하나** 만든다(6단계-3 §1-1 그대로).
비교는 `String(줄.주문번호).trim()`끼리 **정확히 같을 때만**. 🔴 **빈 주문번호끼리는 절대 맞다고 하지 않는다**(목·실데이터에 빈 주문번호가 수백 건이다).

### 3-1. 🔴 방패 — 6단계-3 설계 §4를 그대로 집행한다

`넘길줄만()`이 **유일한 관문**이다. 출고를 만드는 코드는 여기를 통과한 줄만 받는다.

| 순서 | 걸리면 | 사유 |
|---|---|---|
| ① | `줄.서비스 === true` | `서비스` — 넣던 그 순간 이미 출고가 만들어졌다(`출처:'서비스'`) |
| ② | `색인.이미나감[줄.id]` (`zg.v3.출고`에 `주문id === 줄.id`인 줄이 있다, **`출처` 무관**) | `이미` — 변환을 두 번 돌린 사고까지 이 줄이 막는다 |
| ③ | `!줄.품목코드` | `품목미확인` — 재고에서 뺄 대상을 모른다 |
| ④ | `ZG.주문자료.수량(줄) <= 0` | `수량0` |

**새 출고줄에는 반드시 `주문id: 줄.id`를 넣는다.** 안 넣으면 다음 사람이 ②로 중복을 못 막는다.

```
{ id:'sh_'+Date.now().toString(36)+'_'+랜덤5, 출고일, 품목코드: 줄.품목코드,
  수량: ZG.주문자료.수량(줄), 출처:'주문', 주문id: 줄.id, 등록일시: Date.now() }
```

- **출고일 = 처리하는 날(오늘)**. 로젠 출력완료 파일은 그날 송장을 뽑은 결과라 실제 나간 날이다. (`현재고()`는 `등록일시`만 보고, `월출고량()`만 이 값을 본다. AL열 파일명에서 날짜를 캐지 않는다 — 칸 하나에 규칙을 더 얹으면 어긋난다.)
- 🔴 **`색인`은 실행마다 한 번만 만든다.** 줄마다 `저장소.읽기(키.출고)`를 부르면 이사 데이터(출고 1,272 × 주문 1,287)에서 O(n²)가 된다.
- **이사된 옛 주문 1,287건은 이미 출고줄에 `주문id`가 박혀 있다**(6단계-3 §4). 그 주문번호로 로젠 파일을 돌리면 전부 ②에 걸려 「이미 처리됨」으로 뜬다 — **그게 정상 동작이다.**

## 4. 줄마다의 판정 — 화면이 보여줄 다섯 상태

| 판정 | 언제 | 시안 어디 | 송장 파일 |
|---|---|---|---|
| `정상` | 주문번호로 찾았고 방패를 통과한 줄이 하나 이상 → 출고 만듦 | 왼쪽 초록 칸 | **넣는다** |
| `이미` | 찾았지만 방패에 전부 걸림(대개 두 번째 실행) | 초록 칸에 함께 세고 `.done` 줄에 「이미 처리된 N건은 건너뜀」 | **넣는다** (실제로 나간 송장이다. 재차감만 안 할 뿐) |
| `확인` | ⓐ 주문번호가 빈 줄(전화주문) ⓑ 주문번호는 있는데 v3에 그 주문이 없다 | 오른쪽 빨강 칸 + `.needbox` 표에 한 줄 | 아직 안 넣는다 |
| `처리` | `확인` 줄에서 **「이름으로 주문 찾아 재고 차감」**을 눌러 연결됨 | 그 줄이 초록 글로 바뀌고 `되돌리기` | **넣는다** |
| `넘어감` | **「재고 그대로 두고 넘어가기」**를 눌렀거나, 이름 후보가 하나도 없었다 | 그 줄이 회색으로 바뀜 | 🔴 **안 넣는다**(시안 문구 그대로) |

`.needbox` 머리의 사유 문구는 그 표에 ⓐ만 있으면 시안 문구(`운송장번호는 있지만 주문번호 칸이 비어 있습니다 (전화주문으로 보입니다)`),
ⓑ가 섞이면 `v3에 없는 주문번호입니다 — 그 회차를 아직 안 올리셨을 수 있습니다`를 함께 쓴다. 줄마다의 사유는 표 안에 짧게 적는다.

## 5. 이름으로 주문 찾기 (`08f` 후보 · `08g` 고르기)

```
ZG.배송완료.이름후보(수하인, 색인)
  → [ {묶음키, 수령인, 주문일, 판매처, 줄들:[주문줄], 총수량, 글} ]   // 최근 주문일부터, 최대 8건
```

**비교 필드는 2단계 §2-1의 `수령인`** 이다(로젠 G열 = 수하인 이름). `NFC 정규화 + 모든 공백 제거` 후 **완전일치**. 부분일치는 안 쓴다 — 「김미정」이 「김미정외1」을 물면 남의 재고가 깎인다.
후보는 `zg.v3.주문` 전체에서 고르되 **§3-1 방패를 통과할 줄이 하나라도 있는 건만** 남긴다(이미 나간 주문은 후보에 안 뜬다). `ZG.주문자료.묶음키()`로 **건 단위**로 묶고, 건 하나를 고르면 그 건의 통과 줄 전부에 출고를 만든다.

| 후보 수 | 하는 일 |
|---|---|
| 0 | `u.토스트('그 이름으로 아직 안 나간 주문을 못 찾았습니다 — 이 줄은 넘어갑니다.')` → 그 줄은 `넘어감` |
| 1 | 묻지 않고 바로 처리. 그 줄에 **무엇을 찾았는지** 적는다 — `정다은 · 08-04 · SAC01-15 6주 차감` |
| 2 이상 | `ZG.ui.고르기()`로 다시 고르게 한다. 항목 글 = `정다은 · 2026-08-04 · 스마트스토어 · SAC01-15 외 1품목 · 총 8주` |

🔴 **`고르기`·`확인`을 부르기 직전에 `u.탈출풀기()`, 콜백에서 다시 `u.탈출걸기(닫기)`.**
안 하면 Esc 한 번에 후보창과 결과창이 **같이** 닫혀 처리 이력이 통째로 날아간다 — 8/5 카드설정에서 실제로 났던 사고와 같은 종류다(`04-공통UI.js`는 안 고친다).

**되돌리기** — `처리`·`정상` 줄에는 방금 만든 출고 id를 들고 있는 `되돌리기` 작은 버튼을 둔다(`출고되돌리기()`). 시안은 「처리 후」 모습을 그리지 않았다 — 새 부품을 만들지 않고 기존 `.btn.sm` + 회색 글로만 채운다. 재고를 잘못 깎았을 때 창을 닫기 전에 되물릴 유일한 길이다.

## 6. 송장 업로드 파일 쓰기 (`08f`)

```
ZG.배송완료.송장표(줄들)    → [ ['주문번호','품목별 주문번호','운송장번호','수량'], … ]   // 머리글 포함
ZG.배송완료.내보내기(줄들, 파일명)   // aoa_to_sheet → writeFile
```

- **머리글을 넣는다**(②로젠 대량등록은 머리글 없음 — 반대로 하면 택배사가 한 줄을 먹는다. `엑셀변환-규칙.md` 170행).
- **품목별 주문번호** = `{주문번호}-{NN}`. NN은 **내보내는 표 안에서 같은 주문번호가 나온 순서**를 두 자리로(`-01` `-02`). 한 주문이 두 송장으로 갈렸을 때만 02가 생긴다.
- **박스수량이 1이면 4번째 칸을 공란**으로 둔다.
- **주문번호가 없으면 품목별 주문번호도 빈칸.** 단 이름으로 찾아 연결된 줄은 **그 v3 주문줄의 `주문번호`를 채워 넣는다**(있을 때만). 전화주문이면 그대로 빈칸이다.
- 파일명 `카페24_송장업로드_YYYYMMDD.xlsx`(시안 하단 문구 그대로). 시트 이름 `송장`.
- 2단계 설계 §7 표의 「2칸 = (비움)」은 옛 표기다. **`엑셀변환-규칙.md` ③→④가 최신이고 그쪽을 따른다.**

- 개발자도구 `JSON.parse(localStorage['zg.v3.출고']).filter(r=>r.출처==='주문'&&r.주문id)` — ②에서 **4줄**, ④ 뒤 **5줄**, ⑧ 뒤에도 **5줄**(안 늘어난다). 각 `주문id`가 `zg.v3.주문`의 그 줄 `id`와 글자 그대로 같다.
- 🔴 **서비스 방패** — ②를 하기 전에 정다은 건에 서비스 `SAC01-15` 3주를 넣으면 75 → **72**. 그 뒤 ②를 돌리면 **66**(서비스 줄은 §3-1 ①에 걸려 다시 안 깎인다). 66이 아니라 63이면 이중차감이다.
- `되돌리기`를 누르면 그 줄이 만든 출고줄만 사라지고 재고가 정확히 원래대로 돌아온다.
- 결과창을 닫으면 주문 표의 「재고부족」 빨간 표시가 새 재고로 바뀐다.
- 🔴 **엉뚱한 엑셀을 막는지** — `📋 출고리스트`나 `엑셀로 내려받기`로 받은 `주문_YYYY-MM-DD.xlsx`를 골라 본다. **아무것도 저장하지 않고 안내만 뜨고**, `zg.v3.출고` 줄 수가 한 줄도 안 변해야 한다(§2 머리글 검사).
- 🔴 **실물로도 한 번 열어 본다** — `백업/주문등록_출력(복수건)_출력완료(5)건 (2026-08-04 23시17분41초).xlsx`. **총 5줄 · 무시 1줄(합계) · 정상 0 / 확인 필요 5**(주문번호가 빈 줄 **2** — 실물 6·7행 · v3에 없는 번호 **3** — 4·5·8행)로 떨어지면 파싱이 맞는 것이다. 여기서 「전부 넘어가기」를 눌러 **재고가 한 주도 안 변하는지**까지 본다.
- 콘솔 에러 0건 · 확인 필요가 0건인 파일에서는 `.needbox`가 아예 안 그려진다 · Esc 한 번에 후보 고르기만 닫히고 결과창은 남는다(§5).

## 11. 우람님께 확인할 것

1. **출고일은 「파일을 돌린 날」로 넣는다** — 어제 뽑은 송장을 오늘 처리하시면 그 달 출고 집계에서 하루 밀린다.
2. **넘어간 줄은 송장 파일에도 안 들어간다**(시안 확정). 그 줄은 카페24에서 손으로 배송완료 처리하셔야 한다.
3. **전화주문 줄을 이름으로 찾아 처리하면** 송장 파일에 주문번호가 빈칸으로 들어간다(v3 주문줄에도 번호가 없어서). 카페24가 그 줄을 무시할 수 있다 — 빼는 편이 나으면 알려주시면 뺀다.
4. **이미 처리된 줄도 송장 파일에는 다시 들어간다**(재고만 안 깎는다). 같은 송장을 두 번 올려도 되는지.
5. **되돌리기는 창을 닫기 전까지만** 된다. 닫은 뒤에 되물리려면 별도 화면이 필요하다.

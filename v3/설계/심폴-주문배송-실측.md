# 심폴 주문수집·배송완료 — 실측 기록 (2026-09-16 Node)

> **다시 로그인해서 조사하지 마라.** 아래는 실제 심폴 계정으로 읽어 확인한 값이다.
> 심폴 상점관리자는 **API가 없다**. 그런데 **브라우저도 필요 없다** — 순수 HTTP 로 다 된다(실측).
> 상품등록(`상품/_도구/심폴보내기.py`)은 Playwright 를 쓰지만 **주문·배송은 그 길을 안 쓴다.**

## 0. 우람님 확정 (9/16)

| 정한 것 | 값 |
|---|---|
| 어디서 도나 | **클라우드(Edge Function)** — 맥이 꺼져 있어도 돈다 · 크론에도 같이 탄다 |
| 배송완료 절차 | **바로 보낸다** — 심폴만의 미리보기·1건 시험을 만들지 않는다 |
| 수집 범위 | **「배송요청」(`deli_gbn=X`)만** |

🔴 **비밀번호는 우람님이 Supabase 시크릿에 직접 넣으셔야 한다** (`SIMPOL_ID`·`SIMPOL_PW`).
   카페24 열쇠(`CAFE24_CLIENT_ID` 등)가 이미 같은 자리에 있다. 맥 키체인(`zg-simpol`)은 상품등록 몫으로 그대로 둔다.

## 1. 로그인

```
POST https://www.simpol.co.kr/vender/loginproc.php
      id={아이디}&passwd={비번}          (application/x-www-form-urlencoded)
→ 200 · 쿠키 2개 · 본문은 `<meta refresh url=main.php>` 뿐
```
캡차·CSRF 토큰 없다. 이후 모든 요청에 그 쿠키를 얹는다.
🔴 `www` 를 빼면 301 로 튄다. 🔴 응답은 **EUC-KR** 이다 — `TextDecoder('euc-kr')`.
🔴 보내는 값에 한글이 없다(날짜·상태·주문코드·송장번호 전부 ASCII) — 인코딩 걱정은 안 해도 된다.

## 2. 주문수집

```
① POST vender/order_list.php   sdate=2026-08-16&edate=2026-09-16&deli_gbn=X&listnum=300
   → HTML. 주문코드는 `name="chkordercode" value="2026091609240536840A"` 로 박혀 있다
② POST vender/order_excel.php  ordercodes=코드1,코드2,     ← 🔴 끝에도 콤마를 붙인다
   → CSV (application/vnd.ms-excel · EUC-KR)
```

🔴 **이 CSV 가 `js/08j-심폴.js` 가 이미 읽고 있는 31칸 그 파일이다.** 머리글 실측 —

```
,일자,주문자,주문자 전화(XX-XXXX-XXXX),이메일,주문ID/주문번호,결제상태,받는사람,전화번호(XX-XXXX-XXXX),
비상전화(XX-XXXX-XXXX),우편번호(XXX-XXX),주소,전달사항,상품명,옵션(특징포함),갯수,상품가격,상품 적립금,
입금일,주문관련메모(관리자),고객알리미,상품별 송장번호,거래번호,상품코드,옵션,특징,상품별 처리여부,
상품별 주문메세지,상품별 배송일,택배메세지,주문관련 메모,,
```

- `상품코드` 값은 `="005017000000081207"` 꼴이다 — **엑셀 수식 껍데기를 벗겨야 짝표 열쇠가 된다**
- `일자` = `20260916` (08j.날짜글 이 이미 편다) · `상품별 처리여부` = `배송요청`
- `상품별 송장번호` = 이미 등록된 송장. **비어 있지 않으면 이미 나간 건이다**

## 3. 배송완료(발송처리)

화면의 `save_deli()` 가 하는 일 그대로 —
```
POST vender/order_list.php
     mode=deliinfoup2
     ordercodes=코드1,코드2,     delicoms=9,9,     delinums=송장1,송장2,      ← 🔴 셋 다 끝에 콤마
```
택배사 **로젠택배 = `9`** (실측 · 화면 기본 선택값도 로젠이다).

🔴 **누르면 심폴이 손님에게 문자·이메일을 자동발송한다** (심폴 화면 원문: 「주문자께 발송문자와
   이메일이 자동발송됩니다」). **되돌릴 수 없다.** 두 번 보내지 않게 막는 것이 이 기능의 전부다.

## 4. 🔴 열쇠가 이미 v3 에 있다 — 새 칸도 이사도 없다

| 심폴 CSV `거래번호` | 화면 `chkordercode` | v3_주문 |
|---|---|---|
| `2026091609240536840A` | `2026091609240536840A` | `주문번호` (08j 지도 2번이 거래번호를 여기 넣는다) |

**셋이 같은 값이다**(실측). 그래서 v3 주문줄의 `주문번호` 를 그대로 `ordercodes` 에 넣으면 발송처리가 된다.
`주문ID/주문번호`(`9224036@`)는 **주문자 아이디다 — 쓰지 않는다.**

## 5. 손대는 자리

- `js/08l-카페24발송.js:32` 「② 심폴은 아무 것도 안 보낸다」(`대상뽑기` 의 `심폴수++; return;`) — **여기가 갈래다**
- 31→27칸 변환·짝표는 **`08j-심폴.js` 에 이미 있다.** Edge 로 옮겨 쓸 때 **규칙을 새로 정하지 않는다**
  (`edge-주문수집/index.ts` 머리 주석의 경고와 같은 함정 — 한쪽만 고치면 손업로드와 자동수집이 어긋난다)
- 🔴 **짝(`v3_심폴짝`)을 못 지은 상품이 자동수집에는 화면이 없다** — 설계에서 정할 일.
